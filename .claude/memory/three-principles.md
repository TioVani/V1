# 项目三大方针

1. **好管理** — 代码结构清晰，模块职责分明，状态可追踪，配置可调整
2. **好扩展** — 新功能可以低成本接入，系统间松耦合，插件化架构
3. **好维护** — 逻辑可读，错误可查，改动影响范围可控，不产生隐式依赖

**How to apply:** 每次做技术决策时，用这三点衡量：
- 这个方案会让代码更难管理还是更易管理？
- 新增功能时是否需要大量改动现有代码？
- 半年后回来看这段逻辑，能快速理解吗？
