# 大地图资源落地方案

> 与 `大世界探索系统策划案.md` 及 `WorldMapConfig.js` / `WorldMapPlayer.js` / `WorldMapRenderer.js` 对齐。
> 当前为 **Phase 3 基础框架完成后**的空白地图阶段（纯色背景 + 矩形碰撞 + 几何图形渲染），以下描述从空白到正式美术资源落地的完整路径。

---

## 一、当前架构概述

### 1.1 地图数据驱动方式

每个世界由一个纯数据配置 `WorldMapConfig` 驱动，**不含任何图片文件引用**：

```js
// src/config/WorldMapConfig.js
{
    worldId: 'world_01',
    name: '灵域初境',
    width: 2000, height: 1500,       // 地图像素尺寸
    playerStart: { x: 100, y: 800 },
    hasTutorial: true,
    entryCutscene: null,

    collisions: [
        { id: 'tutorial_wall_right', type: 'rect', x: 550, y: 0, w: 30, h: 600 },
        // ...
    ],

    entities: [
        { id: 'tutorial_spirits', type: 'tutorial', x: 400, y: 800, ... },
        { id: 'chest_01', type: 'chest', x: 600, y: 400, ... },
        { id: 'enemy_01', type: 'enemy', x: 900, y: 300, ... },
        // ...
    ]
}
```

- **碰撞层**：`collisions` 数组，每项是 `{ id, type: 'rect', x, y, w, h }` 的矩形定义
- **实体层**：`entities` 数组，每项定义一个地图实体（宝箱/敌人/塔/传送门/NPC/屏障等）
- **碰撞检测**：`WorldMapPlayer.checkCollision()` 遍历 rect 数组做 AABB 检测，无图片像素读取

### 1.2 当前渲染流程

```
每帧渲染顺序（WorldMapRenderer.js）:
  1. 纯色背景填充（#1a1a2e）
  2. 网格参考线（100px 间距，alpha=0.03）
  3. 已发现的实体（几何图形：圆形/矩形 + 中文字符标识）
  4. 交互确认按钮（触屏）
  5. 玩家角色（蓝色圆点 + 描边）
  6. HUD（探索度百分比 + 世界名称）
  7. NPC 对话框
  8. 虚拟摇杆
```

**当前没有**：地图背景图、遮挡层、collision.png、doors 传送门。

### 1.3 模块结构

```
src/config/WorldMapConfig.js        纯数据，每个世界一份配置
src/systems/WorldMapSystem.js       入口，组合子模块
src/systems/worldmap/
  WorldMapPlayer.js                 移动 + rect 碰撞检测
  WorldMapEntity.js                 实体发现/交互/优先级/刷新
  WorldMapExploration.js            探索度 + 存档
  WorldMapUnlock.js                 菜单解锁 + 屏障解除
src/renderers/WorldMapRenderer.js   渲染 + 摄像机 + 摇杆 + 对话框
```

## 二、资源落地路线

### 2.1 从空白到正式美术的三个阶段

| 阶段 | 地图背景 | 碰撞检测 | 实体渲染 | 状态 |
|---|---|---|---|---|
| **A. 当前（空白原型）** | 纯色 #1a1a2e | rect 数组 | 几何图形 + 文字 | ✅ 已完成 |
| **B. 底图接入** | 单张地图背景图 | rect 数组（手动标注） | 几何图形 + 文字 | 📋 待做 |
| **C. 完整美术** | ground + overhead 双层 | rect 或 tilemap | 实体美术素材 + 动画 | 📋 远期 |

### 2.2 阶段 B：底图接入（优先落地）

**目标**：把现有的 AI 生成地图底图作为背景显示，碰撞仍用 rect 手动标注。

#### 需要做的事

1. **选择底图**：从参考素材中为每个区域选一张底图

   | 区域 | 可用素材（`assets/images/reference/地图资源/蜀汉国/地图资源（底图）/`） |
   |---|---|
   | 市场 | `cyberhua_map_market_*.png` |
   | 寺庙 | `cyberhua_map_temple_*.png` |
   | 小巷 | `cyberhua_map_alley_*.png` |
   | 全景备选 | `cyberhua_pixel_topdown_*.png`、`nano_banana_map01_*.png`、`nano_banana_map05_*.png` |

2. **资源归位**：将选中底图复制到正式目录

   ```
   assets/images/worldmap/
     world_01.png       ← 灵域初境底图（拼接或单张）
     world_02.png       ← 冥河幽境底图
   ```

3. **WorldMapConfig 增加背景图字段**：

   ```js
   world_01: {
       // ... 现有字段
       backgroundImage: 'assets/images/worldmap/world_01.png',
       // ...
   }
   ```

4. **WorldMapRenderer 改造**：在"纯色背景"步骤替换为绘制 `backgroundImage`

   ```js
   // 改造前
   ctx.fillStyle = '#1a1a2e';
   ctx.fillRect(0, 0, sw, sh);

   // 改造后
   var bgImg = getAssets().worldMapBg;
   if (bgImg) {
       ctx.drawImage(bgImg, -_camX, -_camY, config.width * scale, config.height * scale);
   } else {
       ctx.fillStyle = '#1a1a2e';
       ctx.fillRect(0, 0, sw, sh);
   }
   ```

5. **碰撞 rect 手动标注**：对照底图，在 WorldMapConfig 中手写碰撞矩形。标注工具可用简单脚本辅助：在 Canvas 上叠加半透明矩形，拖拽调整后导出坐标。

6. **AssetConfig 注册**：在 `src/config/AssetConfig.js` 的 `worldmap` 分组中添加底图条目。

#### 工作量

| 任务 | 预估 |
|---|---|
| 底图选择 + 裁剪/拼接 | 1-2 小时/世界 |
| 碰撞 rect 手动标注 | 2-4 小时/世界（可用工具辅助） |
| Renderer + Config 改造 | 2-3 小时 |
| AssetConfig + 加载集成 | 1 小时 |

### 2.3 阶段 C：完整美术（远期）

**目标**：ground/overhead 双层渲染 + 实体美术素材替换。

#### 资源结构

```
assets/images/worldmap/
  world_01/
    ground.png          ← 地面层（道路、草地、建筑底部）
    overhead.png        ← 遮挡层（树冠、屋檐，透明背景）
  world_01_entities/
    chest.png           ← 宝箱素材
    enemy_slime.png     ← 敌人素材
    tower.png           ← 塔素材
    portal.png          ← 传送门素材
    ...
```

#### 渲染流程升级

```
每帧渲染顺序（阶段 C）:
  1. 绘制 ground.png（地面层）
  2. 绘制实体美术素材（替代几何图形）
  3. 绘制玩家角色
  4. 绘制 overhead.png（遮挡层，树冠覆盖在玩家上方）
  5. 绘制 UI 层（HUD、对话框、摇杆）
```

#### ground/overhead 拆分规范

用图片编辑器把底图拆成两部分：

- **ground.png**：道路、地面、建筑底部墙面（不需要透明通道，可压成 JPG 省体积）
- **overhead.png**：树冠、屋檐、屋顶边缘等应遮挡玩家的部分（需要 PNG 透明通道）

> 阶段 C 需要同时改造 `WorldMapRenderer` 的渲染顺序和 `AssetManager` 的加载逻辑。
> **不影响碰撞层**（仍然用 rect）和**实体系统**（实体交互逻辑不变）。

## 三、碰撞系统说明

### 3.1 当前实现（rect AABB）

`WorldMapPlayer.checkCollision(x, y)` 遍历 `_activeCollisions` 数组，对每个 `type: 'rect'` 的项做 AABB 检测：

```js
// WorldMapPlayer.js
if (x + _playerRadius > c.x && x - _playerRadius < c.x + c.w &&
    y + _playerRadius > c.y && y - _playerRadius < c.y + c.h) {
    return true;  // 碰撞
}
```

- `_playerRadius = 12`（角色视为圆形，半径 12px）
- X 和 Y 分开检测（允许沿墙滑动）
- 边界碰撞默认生效（角色不可超出地图 width/height）

### 3.2 碰撞的动态管理

| 操作 | 方法 | 场景 |
|---|---|---|
| 初始化碰撞 | `init(config)` 从 WorldMapConfig 加载 | 加载世界 |
| 屏障解除移除碰撞 | `removeCollisionsById(ids)` | barrier 解除时移除关联碰撞（如冥河） |
| 完全替换碰撞 | `setCollisions(collisions)` | 需要整体替换碰撞配置时 |

### 3.3 远期可选：tilemap 碰撞

如果 rect 碰撞精度不够（复杂地形），可扩展为 tilemap 模式：

- 在 `WorldMapConfig` 中增加 `collisionTilemap` 字段（二维数组，1=阻挡，0=可走）
- `WorldMapPlayer.checkCollision()` 增加 `type: 'tile'` 分支
- 不影响 rect 碰撞的现有逻辑，两种模式可共存

**不建议用 collision.png 像素检测**，原因：
- 需要额外的图片加载和 Canvas 像素读取
- 碰撞数据不可在配置中直观查看和编辑
- 与当前架构（纯数据配置）不兼容
