# 技能流星击杀怪物不清理问题分析

## 问题现象

蓄力技、拖拽技、节奏技、联连技触发的流星可以对怪物造成伤害并使其 HP 归零，但怪物不会从战场上被移除（清理）。只有再次用普通攻击（点击灵光触发流星）攻击该空血怪物，怪物才会被清理掉。

---

## 一、两条伤害路径的完整对比

### 1.1 普通攻击路径（能正常清理怪物）

```
玩家点击灵光
  → NormalBattleAdapter.handleStarClick()
  → BattleEngine.handleStarClick()
      ├── 计算伤害 → targetMonster.hp -= damage
      ├── 创建流星动画
      └── if (targetMonster.hp <= 0) {
              if (immediateDeath) {
                  直接调用 callbacks.onMonsterDeath()
              } else {
                  addPendingDeath(targetMonster)  // 延迟1150ms后触发
              }
          }
  → BattleEngine.update() 每帧检查 pendingDeaths
      └── 消散时间到 → callbacks.onMonsterDeath()
          → NormalBattleAdapter.onMonsterDeathCallback()  (行 822)
              → handleMonsterDeath()                       (行 1090)
                  ├── 怪物分裂检查
                  ├── onMonsterDefeat(m)  // 通知外层系统
                  ├── monsters[].splice(mi, 1)  // 从数组移除
                  ├── 位置重排
                  ├── 统计更新（totalMonstersKilled, bossKillCount）
                  ├── 掉落奖励、加分
                  └── 任务进度更新
```

**关键点**：`BattleEngine.handleStarClick()` 在扣完 HP 后，**显式检查 `hp <= 0`** 并加入 `pendingDeaths` 队列，最终链式触发到 `handleMonsterDeath()` 完成怪物清理。

### 1.2 技能路径（不能清理怪物）

四个技能系统存在两种伤害方式，但都**没有死亡检查**：

| 技能系统 | 文件 | 伤害方式 | 死亡处理 |
|---------|------|---------|---------|
| **蓄力技** | `ChargeSystem.js` (行 204, 266) | 通过 `attackMonster(dmg, false, 'charge', target)`，即 `attackMonsterInternal()` | 无 |
| **拖拽技** | `DragSystem.js` (行 188, 278, 293) | 通过 `attackMonster(baseDamage, false, 'drag', target)`，即 `attackMonsterInternal()` | 无 |
| **联连技** | `LinkChainSystem.js` (行 460-472) | 直接操作 `mon.hp = Math.max(0, mon.hp - dmg)` | 无 |
| **节奏技** | `RhythmSkillSystem.js` (行 302-310, 391-398) | 直接操作 `targetCopy.hp` / `mon.hp` | 无 |

**伤害入口函数 `attackMonsterInternal()` 的流程**（`NormalBattleAdapter.js` 行 1752-1930）：

```
attackMonsterInternal(damage, isCritical, starType, targetMonster)
  ├── 吸收检查（absorb）：有概率被怪物吸收入，heal 怪物
  ├── 闪避检查（dodge）：有概率闪避
  ├── 元素汽伤检查（ice + fire 组合 → ×2）
  ├── 护甲/护盾/反弹处理
  ├── if (finalDamage > 0) {
  │       m.hp -= finalDamage;
  │       onMonsterHit(m);  // ← 仅触发命中事件，不做死亡检查！
  │   }
  ├── 狂暴/毒液分裂/吞噬者逃跑后处理
  └── return { success, ... }
      // ← 没有任何 if (m.hp <= 0) 或 handleMonsterDeath 调用！
```

**对比**：`useGreedySkill()`（行 1934-1959）中在 `m.hp <= 0` 时显式调用了 `onMonsterKilled(m)`，从而触发 `killMonster() → handleMonsterDeath()`。这是正确的做法。但四个技能系统都没有这样做。

### 1.3 关键差异表

| 维度 | 普通攻击（灵光点击） | 技能伤害（蓄力/拖拽/节奏/联连） |
|------|-------------------|-------------------------------|
| 伤害入口 | `BattleEngine.handleStarClick` | `attackMonsterInternal` 或直接 `mon.hp -= dmg` |
| HP 归零后 | 加入 `pendingDeaths` → 延迟 1150ms → `handleMonsterDeath()` | **无任何后续处理** |
| 怪物清理 | 正常 | **不清理，怪物残留在 `monsters[]` 中** |
| 为何能补刀 | 普通攻击走的是 `BattleEngine` 路径，有死亡判断 | 技能走的是 `attackMonsterInternal`，没有死亡判断 |

---

## 二、根因分析

**一句话**：四个技能系统的伤害结算链路中，缺少 **"扣血后检查 `m.hp <= 0` 并触发 `onMonsterKilled()` / `handleMonsterDeath()`"** 这一环节。

具体来说：

1. **蓄力技 / 拖拽技**：调用 `attackMonsterInternal()`，该函数只扣血并返回结果，不对 HP 归零做任何反应。
2. **联连技 / 节奏技**：直接操作 `mon.hp`，完全绕过了任何可做死亡检查的入口函数。
3. 唯一有死亡检查的 `useGreedySkill()` 是正确示范：扣血后 `if (m.hp <= 0) { onMonsterKilled(m); }`。

## 三、最终方案：三段式伤害管线

### 3.1 核心思路

将 `attackMonsterInternal` 拆成三段独立函数，让单目标和 AOE 共享同一套防御计算管道，死亡检查统一收口。

**问题定位**：这是实现层面的遗漏，不是架构问题。技能系统在实现时漏掉了"扣血后检查死亡"这一步，联连技和节奏技绕过了统一伤害入口直接操作 `mon.hp`。

**统一了什么**：

| 维度 | 改前 | 改后 |
|------|------|------|
| 伤害入口 | 4 个不同入口（`attackMonsterInternal`、直接 `mon.hp -=`、直接 `targetCopy.hp =`、`BattleEngine.handleStarClick`） | 2 个公共 API（`attackMonster` 单目标、`attackMonstersAOE` 批量），都走同一条管线 |
| 防御结算 | 联连技和节奏技各自手写护盾逻辑，与 `attackMonsterInternal` 中的护盾逻辑可能不一致 | 所有技能共用 `calculateFinalDamage`，规则完全一致 |
| 死亡处理 | `BattleEngine` 走一条路径，`useGreedySkill` 走另一条，四个技能系统不处理 | 所有路径最终都走 `onMonsterKilled → killMonster → handleMonsterDeath` |

### 3.2 三阶段结构

| 阶段 | 函数 | 职责 | 有无副作用 |
|------|------|------|-----------|
| 1 | `resolveDamage(rawDamage, starType)` | 解析伤害元数据（伤害值、灵光类型），返回 `DamageMeta` | 无 |
| 2 | `calculateFinalDamage(meta, monster)` | 对单个目标计算：吸收→闪避→元素汽伤→护甲→护盾→反弹，返回 `{ finalDamage, reflected, comboMultiplier, isAbsorbed, isDodged }` | 无（纯计算） |
| 3 | `executeMonsterDamage(monster, finalDamage, reflected, comboMultiplier)` | 执行扣血、受击反馈、狂暴、毒液分裂、吞噬者逃跑后处理，返回 `isDead`（boolean） | 有（改 monster 状态） |

### 3.3 对外 API

```javascript
// ── 类型定义 ──
// DamageMeta = { rawDamage: number, starType: string }
// DamageResult = { finalDamage: number, reflected: number, comboMultiplier: number, isAbsorbed: boolean, isDodged: boolean }

// ── 内部阶段函数 ──
function resolveDamage(rawDamage, starType) {
    return { rawDamage: rawDamage, starType: starType };
}

function calculateFinalDamage(meta, monster) {
    var dmg = meta.rawDamage;
    var result = { finalDamage: 0, isAbsorbed: false, isDodged: false, reflected: 0, comboMultiplier: 1 };

    if (checkAbsorb(monster, meta.starType)) { result.isAbsorbed = true; return result; }
    if (checkDodge(monster))                     { result.isDodged = true;  return result; }

    result.comboMultiplier = checkElementalCombo(monster, meta.starType);
    dmg *= result.comboMultiplier;
    dmg = applyArmorReduction(dmg, monster);
    var shieldResult = applyShieldAbsorption(dmg, monster);
    dmg = shieldResult.remainingDamage;
    result.reflected = applyReflectDamage(meta.rawDamage, monster);

    result.finalDamage = Math.max(0, dmg);
    return result;
}

function executeMonsterDamage(monster, finalDamage, reflected, comboMultiplier) {
    if (finalDamage > 0) {
        monster.hp -= finalDamage;
        onMonsterHit(monster);
    }
    monster.scale = 0.9;
    monster.animationFrame = 5;
    triggerRage(monster);
    triggerPoisonSplit(monster);
    triggerStarDevourerEscape(monster);

    return monster.hp <= 0;
}

// ── 公共 API ──

// 单目标攻击（蓄力技、拖拽技、节奏技流星等）
function attackMonster(damage, isCritical, starType, target) {
    var meta = resolveDamage(damage, starType);
    var calc = calculateFinalDamage(meta, target);
    if (calc.isAbsorbed || calc.isDodged) return calc;
    if (calc.finalDamage <= 0) return calc;

    var isDead = executeMonsterDamage(target, calc.finalDamage, calc.reflected, calc.comboMultiplier);
    if (isDead) onMonsterKilled(target);
    return calc;
}

// AOE 批量攻击（联连技、节奏技 settle 等）
// damagePlan = { raw: number, starType: string, targets: Monster[] }
function attackMonstersAOE(damagePlan) {
    var meta = resolveDamage(damagePlan.raw, damagePlan.starType || 'normal');

    var deadList = [];

    for (var i = 0; i < damagePlan.targets.length; i++) {
        var t = damagePlan.targets[i];
        if (!t || !t.active) continue;
        var calc = calculateFinalDamage(meta, t);
        if (calc.isAbsorbed || calc.isDodged) continue;
        if (calc.finalDamage <= 0) continue;

        var isDead = executeMonsterDamage(t, calc.finalDamage, calc.reflected, calc.comboMultiplier);
        if (isDead) deadList.push(t);
    }

    // 先收集所有阵亡，再统一触发死亡处理（避免循环中 splice 扰乱数组）
    for (var j = 0; j < deadList.length; j++) {
        onMonsterKilled(deadList[j]);
    }
}
```

### 3.4 各系统改动

| 系统 | 改动 |
|------|------|
| **蓄力技** | 无需改动。继续调用 `attackMonster(dmg, false, 'charge', target)`，死亡检查已内置 |
| **拖拽技** | 无需改动。继续调用 `attackMonster(baseDamage, false, 'drag', target)`，死亡检查已内置 |
| **联连技 `applyJudgeResult`** | 移除手写护盾逻辑和 `mon.hp = Math.max(0, mon.hp - dmg)`，改为调用 `attackMonstersAOE({raw: baseAtk * multiplier, starType: 'normal', targets: monsters})` |
| **节奏技 `detonateStars` 流星回调** | 移除手写护盾逻辑和 `targetCopy.hp = Math.max(...)`，改为调用 `attackMonster(dmg, false, s.type, targetCopy)` |
| **节奏技 `settle`** | 移除手写批量扣血逻辑，改为调用 `attackMonstersAOE({raw: baseAtk * skill.mult, starType: 'normal', targets: monsters})` |

### 3.5 收益

1. **好管理**：所有伤害行为收敛到一个管线，出问题只查一处
2. **好维护**：防御规则、死亡逻辑只在一处修改，不会出现不同技能计算结果不一致
3. **好扩展**：新增技能系统只需构造伤害描述丢给 `attackMonster` 或 `attackMonstersAOE`，零心智负担
4. **耐用**：如果未来做"AOE 统一计算防御再分摊"，只需在阶段 2 和阶段 3 之间插一层分摊逻辑，不动其他代码

### 3.6 实施步骤

1. 在 `NormalBattleAdapter.js` 中重构 `attackMonsterInternal` 为三段式管线，暴露 `attackMonster` 和 `attackMonstersAOE`
2. 修改 `LinkChainSystem.js` 的 `applyJudgeResult`，改用 `attackMonstersAOE`
3. 修改 `RhythmSkillSystem.js` 的 `detonateStars` 流星回调和 `settle`，改用 `attackMonster` / `attackMonstersAOE`
4. 验证四种技能击杀怪物后均能正常清理、掉落正常、分裂正常

## 四、注意事项

1. **动画时序**：普通攻击走 `pendingDeaths` 有 1150ms 延迟，目的是给死亡动画留时间。`onMonsterKilled` 是同步调用的，但技能系统的流星动画在调用 `attackMonster` 之前已确定终点坐标，不影响动画播放。
2. **教学战斗**：`handleMonsterDeath` 中已处理教学战斗的跳过逻辑，走 `onMonsterKilled → killMonster → handleMonsterDeath` 路径可复用该逻辑。
3. **怪物分裂**：`handleMonsterDeath` 中的分裂检查也走同一路径，技能击杀的怪物同样触发分裂。
4. **Stage / 赛季模式**：`handleMonsterDeath` 内部已处理不同模式的差异，走标准路径即可。
5. **AOE 中 splash 数组安全**：`attackMonstersAOE` 先收集所有阵亡怪物到 `deadList`，全部结算完成后再统一调用 `onMonsterKilled`，避免在遍历 `monsters[]` 时 splice 导致索引错乱。

## 五、FAQ

**Q: 这是架构问题吗？**

不是。这是实现层面的遗漏——`attackMonsterInternal` 扣血 + 调用方负责死亡检查的职责划分是合理的，只是技能系统在实现时漏了这一步。联连技和节奏技绕过统一接口直接操作 HP 是风格问题，不是设计缺陷。

**Q: 改完后统一了吗？**

统一了三件事：伤害入口（2 个公共 API 覆盖所有场景）、防御结算（所有技能共用 `calculateFinalDamage`）、死亡处理（所有路径最终走 `onMonsterKilled`）。

**Q: 好管理好维护好扩展吗？**

好管理：攻击行为收敛到一处，出问题只查管线。好维护：防御规则和死亡逻辑只在一处修改。好扩展：新增技能系统只需调用 `attackMonster` 或 `attackMonstersAOE`，不需要关心防御结算和死亡检查。
