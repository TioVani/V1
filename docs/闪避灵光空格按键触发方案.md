# 闪避灵光空格按键触发方案

## 一、需求概述

玩家装备闪避灵光后，当闪避灵光在舞台上生成（可见），玩家按下空格键即可触发闪避效果，无需手动点击屏幕上的闪避星星。

## 二、现有架构分析

### 2.1 闪避灵光生命周期

```
SeasonSystem.startDodgeStarTimer() (1.2s间隔)
  → StarSystem.spawnDodgeStar()          // 在舞台上生成闪避星星
    → 赋予 type: 'dodge', visible: true, createTime, disappearTime
  → 星星自然存在 1 秒后自动消失 (DODGE_STAR_LIFETIME)
  
玩家点击闪避星星 (触摸/鼠标)
  → game.js handleTouchStart
    → NormalBattleAdapter.handleStarClick()
      → BattleEngine.handleStarClick()
        → case 'dodge': 设置 playerEffects.dodging=true + dodgeEndTime
```

### 2.2 现有输入管道

```
keydown 事件 → _keysDown[key] = true  (仅大地图 E 键交互)
触摸事件 → handleTouchStart → 战斗状态管道 （闪避通过点击星星触发）
```

键盘按键在战斗状态中完全不参与任何操作。

### 2.3 关键状态变量

| 变量 | 位置 | 含义 |
|---|---|---|
| `_keysDown` | `game.js:517` | 全局按键状态字典 |
| `playerEffects.dodging` | `GameState.js` / `game.js` | 玩家是否处于闪避状态 |
| `playerEffects.dodgeEndTime` | 同上 | 闪避结束时刻 |
| `stars[]` | `StarSystem` | 舞台上的所有星星数组，含 `type`、`visible` 等字段 |
| `pd.equippedStars` | 存档数据 | 已装备的灵光类型列表 |

## 三、方案设计

### 3.1 触发条件（全部满足）

1. 玩家已解锁闪避灵光：`pd.unlockedStarTypes` 包含 `'dodge'`
2. 玩家已装备闪避灵光：`pd.equippedStars` 包含 `'dodge'`
3. 当前处于战斗状态：`PLAYING / SEASON_PLAYING / STAGE_PLAYING / BOSS_BATTLE / TOWER_COMBAT`
4. 玩家不处于硬控状态：`!playerEffects.stunned`
5. 节奏技未激活或已结束：`!rhythmSkillSystem.isActive()`
6. 舞台上存在可见的闪避星星：`stars[]` 中存在 `type === 'dodge' && visible === true` 的条目
7. 玩家尚未处于闪避状态：`!playerEffects.dodging || Date.now() >= playerEffects.dodgeEndTime`

### 3.2 行为逻辑

```
空格按下(keydown, 非重复) → 检查触发条件
  ├─ 条件全部满足 → 消费最近生成的闪避星星 → 触发闪避
  └─ 条件不满足 → 不响应
```

**消费星星**：找到舞台上最近的 `type === 'dodge'` 且 `visible === true` 的星星，将其标记为已消费（`visible = false` 或直接从数组移除），然后执行与点击该星星完全相同的闪避逻辑。

### 3.3 闪避逻辑复用

直接调用 `BattleEngine.handleStarClick()` 传递找到的 dodge star 对象，完全复用现有逻辑：
- 闪避持续时间计算（考虑快速点击加成）
- 闪避状态标记（`dodging = true`, `dodgeEndTime`）
- 视觉反馈（紫色星爆 + 消息文字）
- 连击更新
- 扩展钩子通知

**注意**：空格触发的闪避不应有"快速/超速点击"加成，始终使用基础 1 秒持续。因为快速点击加成是触摸频率检测的产物，空格键触发场景下没有"连续点击间隔"的语义。

### 3.4 重复按键保护

在 `keydown` 事件中增加 `e.repeat` 检查：长按空格不触发重复闪避。一次 keydown 只消费一颗闪避星星。

### 3.5 事件注册位置

在 `game.js` 现有的 `keydown` 事件监听器（约第 4217 行）中扩展，增加战斗状态下的空格处理分支。建议在 E 键大地图逻辑之后、记录 `_keysDown` 之前插入。

## 四、实现步骤

### 步骤 1：添加查找舞台上闪避星星的方法

在 `StarSystem.js` 或直接使用 `getStars()` 访问星星数组。新增辅助函数：

```
findActiveDodgeStar(): 遍历 stars[] → 找到第一个 type === 'dodge' && visible === true → 返回该星星对象（优先返回消失时间最晚的），未找到返回 null
```

### 步骤 2：消费闪避星星

新增辅助函数：

```
consumeDodgeStar(star): 设置 star.visible = false → 从渲染中移除 → 不触发消失动画
```

### 步骤 3：扩展 keydown 处理

在 `game.js` 的 `keydown` 监听器中添加：

```
if (key === ' ' && !e.repeat && isCombatState(state)) {
    if (playerEffects.stunned) return;
    if (rhythmSkillSystem && rhythmSkillSystem.isActive()) return;
    if (playerEffects.dodging && Date.now() < playerEffects.dodgeEndTime) return;
    
    var dodgeStar = findActiveDodgeStar();
    if (dodgeStar) {
        consumeDodgeStar(dodgeStar);
        normalBattleAdapter.handleStarClick(dodgeStar.x, dodgeStar.y);
        // 或者直接调用 BattleEngine.handleStarClick(dodgeStar)
    }
}
```

### 步骤 4：阻止空格默认行为

在 `keydown` 监听器中，当空格被消费时调用 `e.preventDefault()` 防止页面滚动。

## 五、涉及文件

| 文件 | 修改内容 |
|---|---|
| `V1/src/systems/StarSystem.js` | 新增 `findActiveDodgeStar()` + `consumeDodgeStar()` |
| `V1/game.js` | 在 `keydown` 监听器中新增空格闪避分支，导入新方法 |
| `V1/src/config/GameConfig.js` | 可能需要新增 `DODGE_KEY_TRIGGER_ENABLED` 开关（建议默认 true） |

## 六、边界情况

| 场景 | 处理方式 |
|---|---|
| 舞台上有多颗闪避星星 | 消费消失时间最晚（最新）的那颗 |
| 长按空格不放 | `e.repeat` 拦截，只触发一次 |
| 闪避中按空格 | 条件 7 拦截，不重复触发 |
| 节奏技激活时 | 条件 5 拦截，节奏技已有全程闪避 |
| 玩家被眩晕/打断 | 条件 4 拦截 |
| 游戏暂停时 | 战斗状态检查不通过（暂停不是战斗状态），不触发 |
| 触摸操作和空格同时发生 | 各自独立消费不同的星星，或同一颗星星先到先得 |

## 七、扩展考虑

- 未来可支持自定义按键绑定（当前阶段只做空格）
- 可在设置界面添加"空格闪避"开关
- 当星星被空格消费时，可播放一个简短的"按键触发"提示动画（区分于手动点击）
