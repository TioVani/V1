# 开场剧情「猫灵追逐」落地方案

## 概述

玩家进入游戏后，在世界地图上首次触发"新手战斗"实体时，插入一段完整的剧情对话（剑魄、猫灵、主角三方对峙），对话结束后进入教学战斗。战斗结束后触发剑魄离场、玩家获得"找到猫灵"任务。

---

## 设计原则：统一、好管理、好扩展

整个对话和剧情系统围绕三个"统一入口"设计：

| 统一入口 | 说明 |
|---------|------|
| **DialogueSystem** | 唯一对话播放入口，大地图剧情、战斗内引导、战斗后演出**全部走同一个系统**，通过 `mode` 参数切换全屏/叠加模式 |
| **DialogueConfig.js** | 所有剧情对话脚本的**唯一存放文件**，配置即文档，新增剧情只加数据不写逻辑 |
| **剧情编排表** | 每个剧情场景的结构由**声明式配置**驱动（`StorySceneRegistry`），不散落在 game.js 的 if/else 中 |

规则：**加对话只加数据，加场景只加注册项，不加代码分支**。

## 一、架构设计

### 1.1 新增文件

```
V1/src/systems/
└── DialogueSystem.js        ← 新增：唯一对话系统（全屏/叠加双模式）

V1/src/config/
└── DialogueConfig.js         ← 新增：所有剧情对话脚本 + 场景注册表
```

### 1.2 数据流

```
大地图点击 tutorial 实体
  → WorldMapEntity → game.js onInteractResult({ type:'tutorial', storyScene:'prologue' })
    → 查找 StorySceneRegistry['prologue']
      → scene 配置指定了 3 个阶段:
        preBattle: PROLOGUE_DIALOGUE        ← 播对话 → 回调进入战斗
        inBattle:  TUTORIAL_BATTLE_GUIDE    ← 战斗中叠加引导
        postBattle: PROLOGUE_AFTER_BATTLE   ← 胜利后播对话 → 创建任务

  → 阶段流转完全由 StorySceneRegistry 的声明式配置驱动
  → game.js 只做一件事：sceneDispatcher.start('prologue')
```

### 1.3 状态机

```javascript
GAME_STATE 新增：
  CUTSCENE_DIALOGUE: 'cutscene_dialogue'   ← 新增：全屏对话剧情状态

GAME_STATE 现有：
  CUTSCENE: 'cutscene'        ← 现有过场动画（帧序列+淡入淡出）保留不变
  TUTORIAL: 'tutorial'        ← 教学战斗，不变
```

**区别**：`CUTSCENE` 是帧序列图片播放；`CUTSCENE_DIALOGUE` 是文字对话界面（带角色立绘、逐字打印）。


## 二、DialogueSystem 设计（唯一入口）

### 2.1 核心数据结构

```javascript
// 单段对话 — 所有对话场景的原子单元
{
  speaker: '剑魄',           // 说话人显示名称
  speakerId: 'char_004',     // 角色 ID → 查找立绘
  side: 'left' | 'right' | 'center',  // 立绘位置
  text: '别动！……',
  // expression 等扩展字段预留
}
```

### 2.2 对话脚本格式

所有对话脚本都是 `Array<对话单元>`，存放在 `DialogueConfig.js` 中。

### 2.3 场景注册表（StorySceneRegistry）

这是**统一管理+好扩展**的核心：每段剧情场景的完整生命周期用声明式配置描述。

```javascript
// V1/src/config/DialogueConfig.js

export const STORY_SCENES = {
  // 场景 key — 外部引用只用这个 key
  prologue: {
    id: 'prologue',
    name: '猫灵追逐·开场',

    // 阶段一：战前剧情（全屏对话）
    preBattle: {
      script: PROLOGUE_DIALOGUE,       // 对话数组
    },

    // 阶段二：战斗中引导（叠加模式）
    inBattle: {
      script: TUTORIAL_BATTLE_GUIDE,   // 引导对话数组
      mode: 'overlay',                  // 半透明叠加，不阻断战斗
      triggers: [
        {
          at: 'battle_start',           // 触发时机
          delayMs: 500,
          lineIndex: 0,                 // 从 script[0] 开始播
        },
        {
          at: 'first_star_click',       // 触发时机
          delayMs: 0,
          lineIndex: 1,
        },
      ],
    },

    // 阶段三：战斗后剧情（全屏对话）
    postBattle: {
      script: PROLOGUE_AFTER_BATTLE,
      onCompleteAction: {
        type: 'create_task',
        taskId: 'guide_find_cat_spirit',
      },
    },
  },
};
```

**为何这样设计**：

- 新增剧情场景只需在 `STORY_SCENES` 加一个 key，不改任何逻辑代码。
- 阶段的生命周期（preBattle → 进入战斗 → inBattle → 战斗结束 → postBattle）由 `SceneDispatcher` 统一驱动，game.js 只调用 `sceneDispatcher.start('prologue')`。
- `triggers` 数组定义战斗中何时触发哪句引导，后续加"击杀怪物后说一句"只需加一条 trigger。

### 2.4 DialogueSystem API

```javascript
function createDialogueSystem(deps) {
  return {
    // 播放对话脚本
    // opts: { script, mode:'fullscreen'|'overlay', onComplete }
    play(opts): void,

    // 更新循环
    update(dt): boolean,

    // 渲染
    render(ctx, screenWidth, screenHeight): void,

    // 点击处理
    handleClick(x, y): void,

    // 是否正在播放
    isActive(): boolean,

    // 销毁
    destroy(): void,
  };
}
```

**mode 参数**：

| mode | 行为 | 使用场景 |
|------|------|---------|
| `fullscreen` | 全屏不透明，独立背景 | 大地图剧情、战斗后剧情 |
| `overlay` | 半透明叠加在现有画面上 | 战斗中引导对话 |

**统一了之前的两个方案问题**：不再有 tipShowTipOnce 改造版和 DialogueSystem 两条管线，战斗内引导就是 DialogueSystem 的 overlay 模式。

## 三、SceneDispatcher（场景调度器）

### 3.1 职责

`SceneDispatcher` 是一个薄调度层，负责：

1. 从 `STORY_SCENES[sceneId]` 读取场景配置
2. 依次执行各阶段的对话播放
3. 在阶段之间插入战斗流程控制（startGame / endGame 回调由 game.js 注入）
4. 管理战斗中 trigger 的注册/注销

### 3.2 核心逻辑（伪代码）

```javascript
function createSceneDispatcher(deps) {
  const { dialogueSystem, startBattle, getBattleEvents } = deps;

  return {
    start(sceneId, context) {
      const scene = STORY_SCENES[sceneId];
      if (!scene) return;

      // 阶段一：preBattle
      if (scene.preBattle) {
        dialogueSystem.play({
          script: scene.preBattle.script,
          mode: 'fullscreen',
          onComplete: () => {
            // preBattle 结束 → 进入战斗
            startBattle(context);
            // 注册 inBattle 引导触发器
            registerBattleTriggers(scene.inBattle);
          },
        });
      }
    },

    onBattleEnd(result) {
      const scene = getActiveScene();
      if (!scene) return;
      unregisterBattleTriggers();

      if (result === 'win' && scene.postBattle) {
        dialogueSystem.play({
          script: scene.postBattle.script,
          mode: 'fullscreen',
          onComplete: () => {
            executeAction(scene.postBattle.onCompleteAction);
          },
        });
      }
    },
  };
}
```

### 3.3 game.js 集成点

game.js 中只改两处，代码量极小：

**触发点（onInteractResult 中）**：
```javascript
if (result.type === 'tutorial') {
  if (result.storyScene) {
    sceneDispatcher.start(result.storyScene, { entityId: result.entity.id });
    return;  // 后续由 SceneDispatcher 接管
  }
  // 无剧情场景的 tutorial 走原流程（兼容）
  _tutorial.active = true;
  // ...
}
```

**战斗结束点（endGame 中）**：
```javascript
// tutorial 胜利后
sceneDispatcher.onBattleEnd('win');
```

### 3.4 战斗事件钩子

SceneDispatcher 需要从战斗系统获取事件回调：

```javascript
// deps.getBattleEvents() 返回一个事件发射器
battleEvents = {
  onFirstStarClick(callback),     // 首次点击灵光
  onMonsterKilled(callback),      // 击杀怪物（未来扩展用）
  onStarSpawned(callback),        // 灵光出现（未来扩展用）
}
```

在 tutorial 模式下，通过 `NormalBattleAdapter` 的 `extensions.onBeforeStarClick` 钩子链注册首次点击灵光的回调。SceneDispatcher 根据 `triggers` 配置自动注册合适的回调。

### 5.2 统一事件任务机制

不单独为"找到猫灵"开一个 ad-hoc API，而是在 TaskSystem 中新增一个通用的事件驱动型任务机制：

```javascript
// TaskSystem 新增
function completeEventTask(taskId) {
  // 遍历所有 type === 'event_flag' 且 id 匹配的任务
  // 标记为完成，发放奖励
}
```

这样后续任何"和某个 NPC 对话 3 次"、"触发某个机关"等任务都可以用同一套机制，只需在任务配置中指定 `type: 'event_flag'`，然后外部调用 `completeEventTask(taskId)`。

> 如果 TaskSystem 暂时不改，也可以在 `saveData.storyFlags` 中追踪，等 TaskSystem 重构时统一迁移。优先推荐直接改 TaskSystem，因为改动量很小（一个函数 + 一条配置）。

## 九、可扩展性验证

| 需求场景 | 改动范围 |
|---------|---------|
| 新增一段主线剧情（如第二章开场） | 在 `STORY_SCENES` 加一个 key + 配 3 段脚本数组。不改任何 `.js` 逻辑 |
| 在某个战斗中插入"击杀怪物后对话" | 在 `triggers` 数组中加 `{ at:'monster_killed', lineIndex: N }` |
| 新增一种任务类型（如"收集 3 个道具"） | 在 TaskSystem 加一个 `type` + `updateProgress` 分支 |
| 在普通战斗中插入对话（非 tutorial） | SceneDispatcher 同样支持，只需在触发处传入不同的 sceneId |
| 对话增加分支选项 | DialogueSystem 扩展 `choices` 字段即可，不影响现有配置 |

## 十、风险与注意事项

| 风险 | 处理 |
|------|------|
| 立绘资源不足 | 猫灵 3 张、剑魄 6 张、玉蝉仙 6 张，默认立绘可上线。表情差分后续补 |
| 主角无立绘 | side: 'center' 时只显示文字，无立绘 |
| tutorial 失败重试 | SceneDispatcher 内部维护 `_preBattlePlayed` 标记，首次 tutorial 触发时播放 preBattle，失败重试时跳过。`onBattleEnd('lose')` 只注销触发器，不触发 postBattle |
| 存档兼容 | 新增字段均有默认值，旧存档无缝兼容 |
| DialogueSystem 性能 | 逐字打字用定时器，每帧只重绘对话框区域，无性能问题 |
| `_tutorial.ending` 保护锁与剧情流程冲突 | endGame 在第 3372 行检查 `_tutorial.ending`，在第 3375 行置锁。**postBattle 剧情必须在 victoryPopup.onClose 回调内部播放**，此时锁尚未释放。onClose 末尾再切回 WORLDMAP。详见下文"审计附录"问题 2。 |
| CUTSCENE_DIALOGUE 需注册 5 处而非 3 处 | GAME_STATE 枚举 + StateMachine 转移图 + render._dispatch + update 循环 + touchstart 事件。详见涉及文件清单。 |

### 问题 2：`_tutorial.ending` 保护锁与 postBattle 时机

**原始方案**：`sceneDispatcher.onBattleEnd('win')` 在 "endGame 中" 调用，但未明确是在 victoryPopup.onClose 内部还是外部。

**实际代码**：endGame（第 3372-3406 行）中：
1. 第 3375 行：`_tutorial.ending = true`（置锁）
2. 第 3396 行：创建 victoryPopup，其 `onClose` 在第 3401 行释放锁 `_tutorial.ending = false`
3. 第 3423 行：`state = GAME_STATE.TUTORIAL`

**正确做法**：postBattle 剧情播放必须在 `victoryPopup.onClose` 回调体内执行，在 `_tutorial.ending = false` 释放锁之后、`state = GAME_STATE.WORLDMAP` 之前。此时锁已释放，DialogueSystem 全屏模式下不会与任何 _tutorial 逻辑冲突。

**具体插入位置（game.js onClose 回调内，约第 3401-3422 行之间）**：
```javascript
_tutorial.ending = false;
_tutorial.retryCount = 0;
_tutorial.entityId = null;
_tutorial.completed = true;
runtimeData.tutorialCompleted = true;

// ← 在此处插入: sceneDispatcher.onBattleEnd('win');

// 确保初始角色...（保留原有逻辑）
dataStore.flush();
state = GAME_STATE.WORLDMAP;  // 由 postBattle 的 onComplete 回调设置
```

注意：`state = GAME_STATE.WORLDMAP` 的最终切回需要由 postBattle 对话的 `onComplete` 回调执行，而非立即执行。需将原有切回逻辑包裹为函数，传递给 postBattle 完成回调。

### 问题 3：firstStarClick 不在 StarSystem，在 NormalBattleAdapter

**原始方案**：修改 `StarSystem.js` 暴露回调。

**实际代码**：StarSystem.js 不包含任何点击处理逻辑（仅 1 处 `bottomHitZone: 40` 配置常量）。实际点击链路是：

NormalBattleAdapter 已有 `extensions` 钩子链（第 421-426 行），包括 `onBeforeStarClick`。firstStarClick 的一次性回调应插入此处。

### 问题 4：TaskSystem 无 `triggerEventTask` — 需新增导出方法

**原始方案**：`TaskSystem.triggerEventTask(taskId)`。

**实际代码**：`createTaskSystem` 当前返回 10 个方法，无一支持事件触发型完成。`updateTaskProgress` 只处理累计统计型（`click_stars`、`play_games` 等）。需要新增 `completeEventTask(taskId)` 方法，独立于 `updateTaskProgress` 的逻辑。

**方案已更新**：API 名称改为 `completeEventTask`，明确标注为 TaskSystem 新增导出方法。

### 问题 5：tutorial 实体天然支持 `storyScene` 字段透传

**确认**：`WorldMapEntity.interact` 在第 114 行将完整 `entity` 对象传给 `onInteractResult`。在 WorldMapConfig 的 tutorial 实体中新增 `storyScene: 'prologue'` 字段后，通过 `result.entity.storyScene` 即可访问。无需修改 WorldMapEntity.js。

**注意**：实际通过 `onInteractResult` 传递的 `result` 中，`result.entity` 可用，但 `result.storyScene` 不可用——因为 `onInteractResult` 生成 `result` 时只写入了 `{ type: 'tutorial', entity: entity }`，没有扁平化 entity 的字段。game.js 中应通过 `result.entity.storyScene` 访问。
