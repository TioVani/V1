# 猫灵对话系统 — 两段式交互优化方案

## 问题

当前方案中，猫灵台词和玩家选项按钮**同时显示**在同一屏幕上。需求是交互分两步：

1. **先选择环节**：只显示玩家可选的话（"你好~" / "喵喵喵？"），没有猫灵台词
2. **再回应环节**：猫灵根据选择给出回应台词，展示后**自动关闭**（无需额外点击）

即每次来访的交互是：

```
玩家接近猫灵 → 按下交互键
  → 出现两个选项: "你好~"  "喵喵喵？"
  → 玩家点击其中一个
  → 猫灵回应台词（显示约2秒后自动消失）
  → 对话结束
```

## 二、数据结构变化

### 对话脚本格式（NpcDialogueConfig.js）

原格式：
```
一行 = { text: "猫灵台词", choices: [...] }   ← 台词和选项同时出现
```

新格式：拆为两行
```
第一行 = { choices: [...], choicePrompt?: "提示文字" }    ← 纯选项行
第二行 = { text: "猫灵回应", autoDismissAfter?: 毫秒数 }   ← 纯台词行，自动关闭
```
- `choicePrompt`：选项行上方显示的提示文字，缺省时不显示
- `autoDismissAfter`：台词行展示后自动关闭的延迟（毫秒），任何对话行都可使用。猫灵回应行设为 2000ms，免去手动关闭操作。设为 0 或不设则行为不变（手动关闭）

完整脚本数组则是交错结构：

```
[
    { choices: [...], choicePrompt: "你想说什么？" },   // 玩家选择
    { text: "猫灵回应", autoDismissAfter: 2000 },       // 猫灵回应，2秒后自动关闭
    { choices: [...], choicePrompt: "你想说什么？" },   // 下一轮选择
    { text: "猫灵回应", autoDismissAfter: 2000 },       // ...
]
```

### 猫灵具体对话脚本

```javascript
getScript: function (state) {
    var v = state.visitCount;

    // 第3次已结束，后续访问 → 只有台词，无选项
    if (state.resolved) {
        if (state.gaveReward) {
            return [{ text: '喵~（猫灵冲你眨了眨眼）' }];
        }
        return [{ text: '……' }];
    }

    // 第1次：先选 → 再回应
    if (v === 0) {
        return [
            {
                choicePrompt: '你想说什么？',
                choices: [
                    { label: '你好~', key: 'hello' },
                    { label: '喵喵喵？', key: 'meow' }
                ]
            },
            { text: '喵。', autoDismissAfter: 2000 }
        ];
    }

    // 第2次：先选 → 再回应
    if (v === 1) {
        return [
            {
                choicePrompt: '你想说什么？',
                choices: [
                    { label: '你好~', key: 'hello' },
                    { label: '喵喵喵？', key: 'meow' }
                ]
            },
            { text: '喵喵喵？', autoDismissAfter: 2000 }
        ];
    }

    // 第3次：先选 → 再回应（台词根据前两次选择变化）
    var c1 = state.choice1;
    var c2 = state.choice2;
    var thirdLine;
    if (c1 === 'hello' && c2 === 'hello') {
        thirdLine = '喵喵喵。';
    } else if (c1 === 'meow' && c2 === 'meow') {
        thirdLine = '干嘛三番五次套近乎？';
    } else {
        thirdLine = '喵三喵四喵喵喵？';
    }

    return [
        {
            choicePrompt: '你想说什么？',
            choices: [
                { label: '没啥。', key: 'nothing' },
                { label: '看看你有没有受伤。', key: 'care' }
            ]
        },
        { text: thirdLine, autoDismissAfter: 2000 }
    ];
}
```

## 三、WorldMapRenderer 渲染变化

### 核心变化

现在 `_dialogue` 中每行可以是三种之一：
- 纯文本行：`string` 或 `{ text: "..." }`
- 纯选项行：`{ choices: [...] }`
- 混合行（旧格式兼容）：`{ text: "...", choices: [...] }`

渲染逻辑：

| 行类型 | 渲染内容 |
|--------|---------|
| `{ choices: [...] }` (无 text) | 只渲染选项按钮，若有 `choicePrompt` 则在上方显示配置的提示文字 |
| `{ text: "...", choices: [...] }` | 旧格式兼容：台词 + 选项同时显示（不推荐新内容使用） |
| `{ text: "..." }` (无 choices) | 纯台词行，显示台词文字 + "点击继续" |

### 对话框尺寸自适应

选项行与台词行的高矮不同：

```
选项行高度 ≈ 按钮高度(38) + 上下边距(40) + 提示文字行高(19) ≈ 100 * uiScale
台词行高度 ≈ padding(20) + 文本行高(19*N) + 底部间距(30)
```

渲染时先检测当前行类型，计算对应高度。对话框底部对齐。

### 选项行渲染伪代码

```javascript
// lineIdx 直接取 _dialogue.index，不通过 Math.min 间接取值
var curLine = _dialogue.lines[_dialogue.index];

if (curLine && typeof curLine === 'object' && curLine.choices && !curLine.text) {
    // 纯选项行 — 只渲染选项按钮
    _choiceHotspots = [];

    // 提示文字（从配置读取，缺省不显示）
    if (curLine.choicePrompt) {
        var hintFontSize = Math.floor(14 * uiScale);
        ctx.font = hintFontSize + 'px sans-serif';
        ctx.fillStyle = 'rgba(232,213,163,0.6)';
        ctx.textAlign = 'center';
        ctx.textBaseline = 'top';
        ctx.fillText(curLine.choicePrompt, dlgX + dlgW / 2, dlgY + padding);
    }

    // 选项按钮（在提示文字下方，若没有提示文字则更靠上）
    var btnW = Math.floor((dlgW - padding * 3) / 2);
    var btnH = Math.floor(38 * uiScale);
    var btnFontSize = Math.floor(14 * uiScale);
    var promptOffset = curLine.choicePrompt ? Math.floor(24 * uiScale) : Math.floor(8 * uiScale);
    var btnY = dlgY + padding + promptOffset;
    var btnGap = Math.floor(8 * uiScale);

    for (var bi = 0; bi < curLine.choices.length; bi++) {
        var btnX = dlgX + padding + bi * (btnW + btnGap);

        // 按钮背景
        ctx.fillStyle = 'rgba(232,213,163,0.15)';
        ctx.strokeStyle = '#e8d5a3';
        ctx.lineWidth = Math.floor(1.5 * uiScale);
        var bdr = Math.floor(6 * uiScale);
        ctx.beginPath();
        ctx.moveTo(btnX + bdr, btnY);
        ctx.lineTo(btnX + btnW - bdr, btnY);
        ctx.arcTo(btnX + btnW, btnY, btnX + btnW, btnY + bdr, bdr);
        ctx.lineTo(btnX + btnW, btnY + btnH - bdr);
        ctx.arcTo(btnX + btnW, btnY + btnH, btnX + btnW - bdr, btnY + btnH, bdr);
        ctx.lineTo(btnX + bdr, btnY + btnH);
        ctx.arcTo(btnX, btnY + btnH, btnX, btnY + btnH - bdr, bdr);
        ctx.lineTo(btnX, btnY + bdr);
        ctx.arcTo(btnX, btnY, btnX + bdr, btnY, bdr);
        ctx.closePath();
        ctx.fill();
        ctx.stroke();

        // 按钮文字
        ctx.fillStyle = '#e8d5a3';
        ctx.font = 'bold ' + btnFontSize + 'px sans-serif';
        ctx.textAlign = 'center';
        ctx.textBaseline = 'middle';
        ctx.fillText(curLine.choices[bi].label, btnX + btnW / 2, btnY + btnH / 2);

        // 记录热区
        _choiceHotspots.push({
            x: btnX, y: btnY, w: btnW, h: btnH,
            key: curLine.choices[bi].key
        });
    }

    // 选项模式下隐藏 "点击继续"（原有 renderHint 段需加判断 _choiceHotspots.length === 0）
}
```

## 四、推进逻辑变化

### advanceDialogue 流

原逻辑（单选行推进）：
```
advanceDialogue(key) → 通知回调 → index++ → 返回下一行
```

新逻辑（两段式）：
```
advanceDialogue(key) → 通知回调（更新状态）→ index++ → 返回"猫灵回应"行
  → 回应行有 autoDismissAfter → 启动自动关闭定时器
  → 2秒后自动 dismissDialogue
```

换言之，选项行推进后自动展示猫灵回应行，**回应行展示后自动在 2 秒内关闭，无需用户额外点击**。

`advanceDialogue` 核心推进逻辑（选项卡住检测、回调触发、index++）不变。但在 `index++` 和 `return` 之间新增 `_startAutoDismiss` 检查（见下文"autoDismissAfter 自动关闭机制"）。

### autoDismissAfter 自动关闭机制

在 `showDialogue` 中存储一个 `_autoDismissTimer`，每次 `advanceDialogue` 返回新行后检查该行是否有 `autoDismissAfter` 字段：

```javascript
// 在 advanceDialogue 末尾，index++ 之后：
var nextLine = _dialogue.lines[_dialogue.index];
if (nextLine && typeof nextLine === 'object' && nextLine.autoDismissAfter > 0) {
    _startAutoDismiss(nextLine.autoDismissAfter);
}
```

`_startAutoDismiss(ms)` 清除旧计时器，设置 `setTimeout` 调用 `dismissDialogue()`。`dismissDialogue()` 中也清除计时器。

用户在计时器期间手动点击继续或按 E 会正常推进（如果后面还有行），或直接 dismiss。自动关闭只在用户没有手动操作时生效。

### _handleNpcDialogue 回调改造

```javascript
worldMapRenderer.showDialogue(script, function (choiceKey) {
    if (choiceKey) {
        var result = drv.onChoice(pd, driverId, state, choiceKey);
        if (result && result.toast) {
            $P.showToast({ title: result.toast, icon: 'success', duration: 2500 });
        }
        worldMapSystem.saveProgress();
    }
    // 不手动 dismiss — advanceDialogue 自动推进到回应行，回应行 autoDismissAfter 自动关闭
});
```

## 五、E 键推进兼容

选项行中按 E：`advanceDialogue()` 无参 → 检测到 `cur.choices` 存在 → 返回 `cur`（不推进）。E 键无效，只能鼠标/触摸选择选项。

猫灵回应行中按 E：`advanceDialogue()` 无参 → 正常推进 → 到末尾 → dismiss。**同时自动关闭计时器也在倒计时**，两者竞速无副作用——哪个先到哪个关闭对话。

触摸事件：选项行中只响应热区点击；回应行中触摸任意位置推进。若用户在 autoDismissAfter 计时中点击，手动推进优先，计时器被清除。

## 六、game.js 改动

与 `猫灵对话系统落地方案.md` 相同，唯一的差异在 `_handleNpcDialogue` 的回调函数：

```javascript
function _handleNpcDialogue(driverId) {
    var drv = _gameModules.NPC_DIALOGUE_DRIVERS[driverId];
    var pd = saveData;

    if (!pd.npcDialogState) pd.npcDialogState = {};
    if (!pd.npcDialogState[driverId]) {
        pd.npcDialogState[driverId] = drv.initState();
    }
    var state = pd.npcDialogState[driverId];

    var script = drv.getScript(state);
    if (!script || script.length === 0) return;

    worldMapRenderer.showDialogue(script, function (choiceKey) {
        if (choiceKey) {
            var result = drv.onChoice(pd, driverId, state, choiceKey);
            if (result && result.toast) {
                $P.showToast({ title: result.toast, icon: 'success', duration: 2500 });
            }
            worldMapSystem.saveProgress();
        }
        // 不手动 dismiss — advanceDialogue 自动推进到猫灵回应行
    });
}
```

## 七、与基本方案的差异对照

| | 基本方案 | 优化方案 |
|---|---|---|
| 对话脚本格式 | `[{ text, choices }]` 一行 | `[{ choices, choicePrompt }, { text, autoDismissAfter }]` 两行交替 |
| 交互节奏 | 台词+选项同时出现 | 先选、再看回应（自动关闭） |
| 推进次数 | 1次（选完即结束） | 1次（选完自动展回应，2秒后自动关闭） |
| WorldMapRenderer 改动 | 支持 `{ text, choices }` | 额外支持 `{ choices }` 无台词行 + `autoDismissAfter` 自动关闭 + 自适应高度 |
| E 键行为 | 选项行 E 键无效 | 相同；回应行 E 键仍可手动关闭 |
| 触摸行为 | 选项行只响应热区 | 相同；回应行触摸可手动关闭 |
| onChoice 回调 | 更新状态 + 结束对话 | 更新状态，对话继续推进到回应行，自动关闭 |

## 八、向后兼容

- `{ text: "...", choices: [...] }` 格式仍渲染为台词+选项（旧格式兼容）
- 纯字符串数组 `["...", "..."]` 仍正常工作（world_04 商户NPC）
- `{ choices: [...], choicePrompt: "..." }` → 新格式，只渲染选项+提示
- `{ choices: [...] }` 无 choicePrompt → 新格式，只渲染选项（提示留空）
- `{ text: "...", autoDismissAfter: 2000 }` → 纯台词行 + 自动关闭
- `{ text: "..." }` 无 autoDismissAfter → 纯台词行，和旧行为一致（手动关闭）
