# 赛季模式：暂停→返回主界面 定时器与音乐残留问题

## 问题描述

赛季战斗中，玩家点击暂停→返回菜单→回到大地图后，战斗音乐没有停止，灵光仍在生成。本质上是因为定时器清理和音乐停止的时序有冗余操作窗口，缺少兜底保障。

## 完整链路追踪

暂停→返回菜单的执行顺序（`game.js` L4427-4433）：

```
① PauseCoordinator.instance.resume()
    └─ 遍历 subscriber → ModeTimers.onResume
       └─ handlers['season'].resume() → resumeNormalTimers()
          ├─ setGameState(GAME_STATE.PLAYING)  ← 状态被改为 PLAYING
          ├─ setTimerInterval(setInterval(...))  ← 创建倒计时（全局 timerInterval）
          ├─ setMoveInterval(setInterval(...))   ← 创建灵光生成（全局 moveInterval）
          └─ setMonsterAttackInterval(...)       ← 创建怪物攻击

② modeLifecycle.cleanupMode('season')
    └─ handlers['season'].cleanup() → endSeasonGame()
       ├─ setGameState(GAME_STATE.GAMEOVER)
       ├─ clearTimerInterval()     ← 清理①中创建的 timerInterval
       ├─ clearMoveInterval()      ← 清理①中创建的 moveInterval
       ├─ clearMonsterAttackInterval()
       └─ stopPetAttackTimer()

③ stateMachine.transitionTo(GAME_STATE.WORLDMAP)
    └─ setGameStateRaw: prevState=GAMEOVER → state=WORLDMAP
       └─ audioSystem.exitBattle()  ← 恢复BGM
```

## 根因分析

步骤①中 `resume()` 触发 `resumeNormalTimers()`，做了三件事：
1. **将状态改为 `PLAYING`**：这个状态不是赛季战斗需要的（赛季是 `SEASON_PLAYING`），只是一个中转状态
2. **创建了全局定时器**（`timerInterval`、`moveInterval`、`monsterAttackInterval`）：这些是普通模式的定时器，倒计时逻辑不同、灵光生成间隔不同
3. **倒计时到0时调用 `endGame()` 而不是 `endSeasonGame()`**：虽然 `endGame()` 内部会检测 `SEASON_PLAYING` 并转发给 `endSeasonGame`，但步骤①已经把状态改成了 `PLAYING`，转发将失效

步骤②中 `cleanupMode('season')` → `endSeasonGame()` 会清理步骤①创建的定时器。**在正常流程中，步骤①创建的定时器会被步骤②立即清理，理论不会残留。**

### 但残留发生的几种可能场景

**场景A：`endSeasonGame()` 执行中途抛异常**

如果 `endSeasonGame()` 中 `uploadSeasonScore()`、`seasonLeaderboard.sort()`、`saveData()` 等任一行抛出未捕获异常，后续的清理代码就不会执行。但 `clearTimerInterval()` 等清理代码在 `endSeasonGame()` 的**前半部分**（L404-408），所以只要执行到这行，定时器就会被清。

**场景B：用户快速连续操作，状态混乱**

如果在暂停菜单上用户快速点两次，第二次点击时状态可能已经不是 PAUSED，导致进入了非预期的处理分支。

**场景C（最可能）：`resumeNormalTimers` 中的 `setGameState(PLAYING)` 误导了后续音乐判断**

步骤①把状态改为 `PLAYING` 后，`setGameStateRaw` 中的音乐判断（`game.js` L3507-3509）检测的是 `prevState`：
- 步骤①：prevState=PAUSED → state=PLAYING，不触发 `endBattle()`（因为 prevState !== SEASON_PLAYING）
- 步骤②：prevState=PLAYING → state=GAMEOVER，不触发 `endBattle()`（因为 prevState !== SEASON_PLAYING）
- 步骤③：prevState=GAMEOVER → state=WORLDMAP，触发 `exitBattle()` ← **正常**

在步骤③，`exitBattle()` 应该是正常工作的。但如果 `audioSystem` 的状态在步骤①中被 `resumeNormalTimers` 的 `setGameState(PLAYING)` 触发了某些副作用（例如 `_battleMusicTriggered` 标志被错误触发），音乐可能在 WORLDMAP 上重新开始播放。

**场景D（最可能）：`PauseCoordinator.pause()` 提前清理了战斗音乐的 BGM 记忆**

`PauseCoordinator.pause()` → subscriber 遍历 → `ModeTimers.onPause` → `modeTimers['season'].clearAll()`。虽然这只是清理 modeTimers 的 Pool（不影响全局定时器），但 `AudioSystem` 可能在 `pause()` 中做了 BGM 淡出操作。当 `resume()` → `resumeNormalTimers()` → `setGameState(PLAYING)` 时，进入 PLAYING 状态可能触发 `enterBattle()` 音乐——这是多余的，因为用户选择的不是"继续"而是"退出"。

## 根本矛盾

核心矛盾在于 **"返回菜单"这个操作不应该走 `resume()` 路径**。`resume()` 的设计意图是"恢复战斗"，而不是"退出战斗"。当前的暂停→返回菜单流程是先恢复再退出，中间步骤①的副作用（重建定时器、修改状态为 PLAYING）是不必要的，且引入了潜在风险。

## 修复方案

### 思路：点击返回菜单 → 直接结算 → 进 GAMEOVER 界面

不绕到 resume → cleanup → WORLDMAP。在暂停状态下，玩家点"返回菜单"时直接调用 `endSeasonGame()` 进入结算界面。这样：

- 定时器被清理（`endSeasonGame` 内置）
- 战斗音乐停止（代码直接调 `audioSystem.endBattle()`，不依赖状态自动检测）
- 玩家能看到分数、排名，决定再来一局还是回大地图
- GAMEOVER 的"返回菜单"按钮已有 `cleanupMode('season')`，生命周期完整

### 代码修改

`game.js` 暂停按钮处理区（L4427-4433），只改"返回菜单"这一条分支：

```javascript
// 修改前：
if (PauseCoordinator.instance.isPaused) {
    // 返回菜单按钮
    const menuBtnY = getDesignOffsetY() + Math.floor(DESIGN_HEIGHT * 0.60 * getScreenScale());
    if (x >= screenWidth/2 - btnWidth/2 && x <= screenWidth/2 + btnWidth/2 &&
        y >= menuBtnY - btnHeight/2 && y <= menuBtnY + btnHeight/2) {
        _log('点击返回菜单');
        PauseCoordinator.instance.resume();          // ← 会重建定时器
        var exitMode = modeLifecycle.getPreviousMode() || modeLifecycle.getActiveMode();
        modeLifecycle.cleanupMode(exitMode);          // ← 清理上面刚建的定时器
        stateMachine.transitionTo(GAME_STATE.WORLDMAP);  // ← 直接回大地图，跳过结算
        return;
    }
    // ... 重新开始、继续游戏不变 ...
}

// 修改后：
if (PauseCoordinator.instance.isPaused) {
    // 返回菜单按钮
    const menuBtnY = getDesignOffsetY() + Math.floor(DESIGN_HEIGHT * 0.60 * getScreenScale());
    if (x >= screenWidth/2 - btnWidth/2 && x <= screenWidth/2 + btnWidth/2 &&
        y >= menuBtnY - btnHeight/2 && y <= menuBtnY + btnHeight/2) {
        _log('点击返回菜单');
        var exitMode = modeLifecycle.getPreviousMode() || modeLifecycle.getActiveMode();
        // 不调 resume()，原因：resume → resumeNormalTimers → setGameState(PLAYING)
        // → 覆盖 prevState → endSeasonGame 中 setGameState(GAMEOVER) 不被识别为赛季结束
        // → endBattle 不触发 → 战斗音乐残留。
        if (exitMode === 'season') {
            endSeasonGame();
        } else if (exitMode === 'stage') {
            stageModeSystem.end(false);
        } else if (exitMode === 'boss') {
            BossBattleMode.cleanup();
        } else if (exitMode === 'tower') {
            if (towerSystem && towerSystem.endCombat) towerSystem.endCombat();
            endGame();
        } else {
            endGame();
        }
        // 兜底清理（endSeasonGame 已清全局定时器，双保险）
        if (timerInterval) { clearInterval(timerInterval); timerInterval = null; }
        if (moveInterval) { clearInterval(moveInterval); moveInterval = null; }
        if (monsterAttackInterval) { clearInterval(monsterAttackInterval); monsterAttackInterval = null; }
        if (stopPetAttackTimer) stopPetAttackTimer();
        if (normalBattleAdapter) normalBattleAdapter.destroy();
        // 停止战斗音乐（直接调，绕过 prevState 依赖）
        if (audioSystem) audioSystem.endBattle();
        // 清除暂停标志（直接设内部字段，不触发 subscriber 重建定时器）
        PauseCoordinator.instance._paused = false;
        PauseCoordinator.instance._pauseStartTime = 0;
    }
    // 重新开始按钮、继续游戏按钮 — 保持不变
    // ...
}
```

### 前后对比

| | 修改前 | 修改后 |
|---|---|---|
| 点击"返回菜单" | resume→cleanupMode→WORLDMAP，resume 覆盖 prevState 导致 endBattle 不触发 | **直接 endSeasonGame 结算 + 兜底清定时器 + 直接 endBattle + 直接解 PauseCoordinator** |
| 是否看到结算界面 | 否，直接回大地图 | 是，和倒计时结束一样 |
| 定时器残留风险 | resume 建→cleanup 拆，resume 覆盖 prevState 断 endBattle | resume 不调，直接 endSeasonGame + 兜底清全局变量 |
| 音乐残留风险 | resume 覆盖 prevState，endBattle 不被触发 | 直接调 audioSystem.endBattle()，不依赖状态检测 |

GAMEOVER 界面上已有"再来一局""查看排行榜""返回菜单"三个按钮，返回菜单按钮已经有 `cleanupMode('season')`（上一轮修复），生命周期完整闭环。

## 总结对比

| 项 | 旧路径 | 新路径 |
|----|--------|--------|
| 暂停→返回菜单 | resume→cleanupMode→WORLDMAP，resume 覆盖 prevState | endSeasonGame 结算 + 量产清理 + 直接 endBattle + 解 PauseCoordinator |
| 玩家体验 | 直接回大地图，看不到分数 | 进结算界面，可看分、再来一局 |
| 定时器风险 | resume 建→cleanup 拆，中间窗口 | endSeasonGame 清 + 兜底 null 检查 |
| 音乐风险 | resume 覆盖 prevState，endBattle 不被触发 | 直接调 audioSystem.endBattle() |
