# 联连技冲击波触发灵光 — 效果增强优化方案

> 代码层面已落地：`detectShockwaveStarHits` + `triggerStarMeteor` + `createMeteor` 注入均已完成。
> 问题：实际运行时灵光密度不足，导致冲击波扫到的灵光极少（甚至为 0），效果不可见。

---

## 一、根因分析

### 1.1 灵光密度瓶颈

| 参数 | 值 | 含义 |
|------|-----|------|
| `STAR.MAX_ON_SCREEN` | 5 | 场上同时最多 5 颗灵光 |
| `MIN_LINKED_STARS` | 3 | 联连窗口最少 3 颗灵光 |
| `MAX_LINKED_STARS` | 7 | 联连窗口最多 7 颗灵光 |

联连窗口从场上随机选取 3~7 颗灵光并标记 `_linking`。在 `MAX_ON_SCREEN=5` 的限制下，联连窗口吃掉最多 5 颗灵光后，场上剩余可被冲击波触发的灵光为 **0~2 颗**。

`detectShockwaveStarHits` 的排除条件（`_linking || _charging || _dragging || _rhythm`）是正确的，但**源头数据太少**。

### 1.2 视觉沉默

即使有 1~2 颗灵光被冲击波触发，流星飞过去后冲击波已经扩散完了，玩家很难把"冲击波扩散"和"灵光变流星"两个事件关联起来。需要更强的视觉因果链。

---

## 二、优化方案

### 方案 A：冲击波触发时不依赖场上剩余灵光，改为从联连窗口灵光中产生流星雨（推荐）

**思路**：冲击波扩散时，不检测场上非联连灵光，而是在联连窗口灵光被判定成功的瞬间（`_allMatchedTime`），让它们随冲击波扩散节奏依次化为流星。

**实现**：

```js
// LinkChainSystem.js — enterJudging() 中，创建冲击波环时同时记录流星雨调度:

// 收集所有匹配成功的 linkedStars（已在 enterJudging 中）
var matchedLs = [];
for (var i = 0; i < state.linkedStars.length; i++) {
    if (state.matchedIndices.indexOf(state.linkedStars[i].index) !== -1) {
        matchedLs.push(state.linkedStars[i]);
    }
}

// 按冲击波进度分配流星发射延迟（均匀分布在整个扩散过程中）
var ringDur = state.shockwaveRings[0].duration || 600;
var firstDelay = 0.20;  // 第一颗在进展 20%
var totalCount = matchedLs.length;
var remaining = totalCount > 1 ? (0.95 - firstDelay) / (totalCount - 1) : 0;
for (var j = 0; j < totalCount; j++) {
    var fraction = j === 0 ? firstDelay : firstDelay + remaining * j;
    state.pendingMeteors.push({
        star: matchedLs[j].star,
        delayMs: fraction * ringDur,
        launched: false
    });
}
```

然后在 `update()` 中：

```js
// detectShockwaveStarHits 中，改为按延迟发射:
var ringDuration = state.shockwaveRings.length > 0 ? state.shockwaveRings[0].duration : 600;
var ringStartTime = state.shockwaveRings.length > 0 ? state.shockwaveRings[0].startTime : now;
var ringElapsed = now - ringStartTime;
var ringProgress = ringElapsed / ringDuration;
for (var mi = state.pendingMeteors.length - 1; mi >= 0; mi--) {
    var pm = state.pendingMeteors[mi];
    if (ringProgress >= pm.delayMs / ringDuration) {
        triggerStarMeteor(pm.star);
        state.pendingMeteors.splice(mi, 1);
    }
}
```

**效果**：联连技成功后，金色冲击波从触发灵光扩散出去，联连灵光随冲击波节奏依次化为流星飞向怪物。

**优点**：
- 不依赖场上剩余灵光密度
- 联连灵光本身就会被消耗（`applyJudgeResult` 中），流星化是消耗动画的高级版
- 视觉因果链清晰：冲击波扩散 → 灵光变流星 → 飞向怪物

### 方案 B：冲击波扩散到怪物头顶时产生全屏小爆炸粒子（视觉增强）

**思路**：冲击波环半径超过每个怪物到中心的距离时，在该怪物头顶产生一个金色小爆炸粒子效果。

**实现**：

```js
// 在 detectShockwaveStarHits 中（ox, oy, ringRadius, getScreenWidth, getScreenHeight 已在函数上下文中可用），
// 除了检测灵光碰撞，也检测怪物碰撞:
var monsters = getActiveMonsters();
for (var mi = 0; mi < monsters.length; mi++) {
    var mon = monsters[mi];
    if (mon.hp <= 0 || !mon.active) continue;
    var sw = getScreenWidth ? getScreenWidth() : 375;
    var sh = getScreenHeight ? getScreenHeight() : 667;
    var mdx = (mon.x || sw / 2) - ox;
    var mdy = (mon.y || sh / 3) - oy;
    var mdist = Math.sqrt(mdx * mdx + mdy * mdy);

    if (mdist <= ringRadius && !mon._shockwaveHit) {
        mon._shockwaveHit = true;
        // 创建小爆炸视觉效果——复用 createMeteorHitEffect
        if (createMeteorHitEffect) {
            createMeteorHitEffect(mon.x || sw / 2, mon.y || sh / 3,
                Math.floor(baseAtk * 0.2), false, 'normal');
        }
    }
}
```

然后在 `applyJudgeResult` 中清理所有怪物上的 `_shockwaveHit` 标记：

```js
// applyJudgeResult 末尾:
var monsters = getActiveMonsters();
for (var i = 0; i < monsters.length; i++) {
    delete monsters[i]._shockwaveHit;
}
```

同时 `reset()` 中也清理，防止怪物死亡后残留标记带到下一场战斗。

**注意**：需要在 game.js 注入 `createMeteorHitEffect`。

### 方案 C：冲击波扫过的区域产生短暂金色光晕（视觉增强）

**思路**：冲击波环内区域叠加一层淡金色径向渐变，从冲击波中心到环内半径。

**实现**：

```js
// render() 冲击波绘制后追加（在 var nowFx = Date.now() 声明之后）:
var innerAlpha = 0.10 + 0.05 * Math.sin(nowFx / 120);  // 低频微脉动，透明度峰值约0.15
ctx.fillStyle = 'rgba(255, 215, 0, ' + innerAlpha.toFixed(3) + ')';
ctx.beginPath();
ctx.arc(ringCx, ringCy, ringRadius * 0.85, 0, Math.PI * 2);
ctx.fill();
```

**效果**：冲击波扩散时内部有一层暖金色光晕，强化区域覆盖感。

## 四、方案 A 完整实现细节

### 4.1 State 新增

```js
// LinkChainSystem 内部 state:
pendingMeteors: []  // [{ star, delayMs, launched }] 联连灵光流星雨调度表
```

### 4.2 enterJudging 修改

```js
// 在现有 shockwaveRings 创建之后追加:
var matchedLs = [];
for (var i = 0; i < state.linkedStars.length; i++) {
    if (state.matchedIndices.indexOf(state.linkedStars[i].index) !== -1) {
        matchedLs.push(state.linkedStars[i]);
    }
}
// 第一颗（触发灵光）在 20% 处发射最强流星，后续均匀分布
var totalCount = matchedLs.length;
var firstDelay = 0.20;  // 第一颗在进展 20%
var remaining = totalCount > 1 ? (0.95 - firstDelay) / (totalCount - 1) : 0;
for (var j = 0; j < totalCount; j++) {
    var fraction = j === 0 ? firstDelay : firstDelay + remaining * j;
    state.pendingMeteors.push({
        star: matchedLs[j].star,
        delayMs: fraction * (state.shockwaveRings[0].duration || 600),
        launched: false
    });
}
```

### 4.3 update 修改

```js
// 在 detectShockwaveStarHits 调用之后、现有流星清理之前追加:
// ── 联连灵光流星雨（按冲击波延迟发射） ──
// 统一使用 shockwaveRings[0] 的 startTime 和 duration 计算进度，
// 与 enterJudging 中 delayMs 基于同一 duration 来源，避免时序错位。
var ringStartTime = state.shockwaveRings.length > 0 ? state.shockwaveRings[0].startTime : now;
var ringDuration = state.shockwaveRings.length > 0 ? state.shockwaveRings[0].duration : 600;
var ringElapsed = now - ringStartTime;
for (var mi = state.pendingMeteors.length - 1; mi >= 0; mi--) {
    var pm = state.pendingMeteors[mi];
    if (!pm.launched && ringElapsed >= pm.delayMs) {
        pm.launched = true;
        triggerStarMeteor(pm.star);
        // 发射后从数组中移除（倒序遍历，splice 安全）
        state.pendingMeteors.splice(mi, 1);
    }
```

### 4.4 reset 清理

```js
state.pendingMeteors = [];
```

### 4.5 与原有 detectShockwaveStarHits 的关系

方案 A 的联连灵光流星雨与补充方案（`联连技冲击波触发灵光补充方案.md`）的场上灵光扫描是**互补关系**，不是替代：

- **方案 A（pendingMeteors 调度）**：处理联连窗口内的匹配灵光，按冲击波延迟依次化为流星。这些灵光带有 `_linking` 标记，补充方案的扫描逻辑原本就会跳过它们。
- **补充方案（detectShockwaveStarHits 扫描）**：处理场上**非联连标记**的残余灵光（0~2 颗），被冲击波扫到时引爆。

两套逻辑在同一个 `detectShockwaveStarHits` 函数中共存：先执行 `pendingMeteors` 的延迟调度（方案 A），再执行场上非联连灵光的实时扫描（补充方案）。两者操作的是互不重叠的灵光集合，不会冲突。

如果同时需要方案 B（怪物爆炸），可在同一函数中追加。
