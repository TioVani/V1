## 需要排查的额外问题

`saveBestScore()` 在 `game.js:3413` 和 `game.js:3423` 的 `modeLifecycle.cleanup` 中被调用。但如果这个 cleanup 从未被触发，`bestScore` 就不会被更新。排查步骤：

1. 在 `StorageSystem.js` 的 `saveBestScore()` 中加 `console.log`，确认函数被执行
2. 确认执行时 `getScore()` 返回值 > 0

**如果 `modeLifecycle.cleanup` 根本没被调用，`bestScore` 就永远是 0，需要单独修复 cleanup 触发时机。**

## 改动清单

### 改动 1：修复"净化数"数据源（立即执行）

**文件**: `game.js`，第1914行附近（MenuRenderer deps 注入块）

改为:

`saveData.taskProgress.stats.monstersKilled` 通过 TaskSystem 的 `updateTaskStats('monstersKilled', 1)` 累积写入（`TaskSystem.js:161-167`, `NormalBattleAdapter.js:1313`），跨局持久化。

### 改动 2：确认 bestScore 链路（诊断性改动）

在 `StorageSystem.js` 的 `saveBestScore` 和 `loadBestScore` 中加日志：

```js
function saveBestScore() {
    try {
        var currentScore = getScore();
        var currentBest = getBestScore();
        console.log('[saveBestScore] currentScore:', currentScore, 'bestScore:', currentBest);
        if (currentScore > currentBest) {
            setBestScore(currentScore);
            setStorageSync('bestScore', currentScore);
            console.log('[saveBestScore] 新纪录:', currentScore);
        } else {
            console.log('[saveBestScore] 未刷新纪录');
        }
    } catch (e) {
        console.error('保存最高分失败:', e);
    }
}
```

验证步骤：
1. 打一局普通模式，看控制台是否输出 `[saveBestScore]`
2. 如果从未输出，说明 `modeLifecycle.cleanup` 未被触发 → 需要修复 cleanup 调用链路
3. 如果输出但 `currentScore: 0`，说明 cleanup 触发时 score 已被重置 → 需要把 saveBestScore 提前到 score 清零之前
