# 世界4到达彩蛋「勒就是灵域？？？」策划案

## 一、概述

玩家首次到达 world_04（蜀汉·市场）时自动触发隐藏彩蛋——弹出一条提示"勒就是灵域？？？"，同时达成隐藏成就「勒就是灵域？？？」，发放 150 灵石。

- **触发时机**：任何途径进入 world_04 时（portal_market 从世界3进入，或 portal_market_w05 从世界5回传）
- **触发次数**：仅首次（`isWorldVisited` 之前从未到过 world_04，即 `saveProgress` 尚未为 world_04 创建存档条目）

---

## 二、设计原则：配置驱动，不加代码分支

与世界10→11彩蛋系统共用同一个 `EasterEggConfig.js` 驱动器注册表，扩展 `trigger: 'onArrive'` 类型。

| 统一入口 | 说明 |
|---------|------|
| **EasterEggConfig.js** | 已有彩蛋驱动器注册表，新增 `world04Arrive` 条目（trigger='onArrive'） |
| **game.js** | 在 `loadWorld` 完成后，遍历 `EASTER_EGG_DRIVERS` 检测 `trigger === 'onArrive'` 且 `targetWorld` 匹配 |
| **TaskSystem.js** | 成就配置表新增「勒就是灵域？？？」条目（只加数据） |

**规则**：game.js 不对 `world_04` 写硬编码判断。遍历 drivers、匹配 `trigger === 'onArrive'` 是通用逻辑，未来新增其他到达彩蛋只加配置项。

---

## 三、触发条件与数据边界

| 条件 | 说明 |
|------|------|
| 触发时机 | `loadWorld('world_04')` 执行后 |
| 前置条件 | 首次到达（`isWorldVisited(pd, 'world_04') === false`），即玩家从未来过世界4 |
| 存档字段 | `pd.easterEggs.world04ArriveChecked`（Boolean） |

### 判定逻辑

```
game.js 执行 loadWorld(targetWorld) 后
  → 遍历 EASTER_EGG_DRIVERS，找 trigger === 'onArrive' 且 targetWorld 匹配的 driver
  → 匹配到 world04Arrive
  → 检查 pd.easterEggs.world04ArriveChecked
  → false（首次到达）:
      → 弹出 toast："勒就是灵域？？？"
      → 写入 pd.taskProgress.achievements.world_04_arrive 标记完成
      → 发放 150 灵石到 pd.starSource
      → 存档标记 world04ArriveChecked = true
      → saveProgress()
  → true（非首次）: 跳过
```

## 四、架构设计

### 4.1 改动文件

| 文件 | 改动类型 | 职责 |
|------|---------|------|
| `V1/src/config/EasterEggConfig.js` | 修改 | 新增 `world04Arrive` 驱动器（trigger='onArrive'） |
| `V1/src/systems/GameDataStore.js` | 修改 | `defaultSaveData.easterEggs` 新增 `world04ArriveChecked: false` |
| `V1/src/systems/TaskSystem.js` | 修改 | 新增「勒就是灵域？？？」成就定义（加数据） |
| `V1/game.js` | 修改 | `loadWorld` 后新增通用 onArrive 检测遍历（不针对 world_04） |

### 4.2 数据流

```
玩家通过任意 portal 传送进入 world_04
  → game.js if (result.type === 'portal') ... loadWorld('world_04')
    → worldMapSystem.loadWorld('world_04', fromWorld)
    → worldMapSystem.saveProgress()  // 此时 worldMapProgress.worlds.world_04 尚未创建
    → // ── 通用 onArrive 彩蛋检测 ────────
    → 遍历 EASTER_EGG_DRIVERS
      → 找到 trigger === 'onArrive' && targetWorld === 'world_04' 的 driver
        → 检查 pd.easterEggs.world04ArriveChecked === false
          → YES:
            → 弹出 toast："勒就是灵域？？？"
            → 写入成就进度
            → 发放灵石
            → 存档标记
            → saveProgress()
```

### 4.3 EasterEggConfig 扩展结构

在原 `EASTER_EGG_DRIVERS` 对象中新增：

```javascript
// ── 勒就是灵域？？？（首次到达 world_04）────────────
world04Arrive: {
    trigger: 'onArrive',
    targetWorld: 'world_04',
    stateKey: 'world04ArriveChecked',

    onTrigger: function (deps) {
        return {
            toast: { title: '勒就是灵域？？？', icon: 'success', duration: 3000 },
            reward: {
                achievementId: 'world_04_arrive',
                spiritStones: 150
            }
        };
    }

```

与 portal 彩蛋的区别：

| 维度 | portal 彩蛋（worldEdge） | onArrive 彩蛋（world04Arrive） |
|------|------------------------|-------------------------------|
| `trigger` | 无（默认 portal） | `'onArrive'` |
| `targetWorld` | 无（由 TeleportConfig easterEgg 字段指定） | `'world_04'`（目标世界） |
| 触发时机 | 点击 portal 时 game.js 拦截 | loadWorld 后 game.js 遍历 drivers |
| `onFirstTrigger` / `onPass` | 两阶段（拦截/通过） | 无（仅 `onTrigger`，一次到位） |

### 4.4 存档新增字段

在 `defaultSaveData.easterEggs` 中新增：

```javascript
easterEggs: {
    worldEdgeChecked: false,        // 已有
    world04ArriveChecked: false     // 新增
}
```

### 4.5 game.js 通用编排逻辑

onArrive 彩蛋检测需要插入到 **两处位置**——portal 彩蛋传送成功后、以及默认传送成功后。两处共享同一个提取的辅助函数 `_checkOnArriveEasterEggs()`。

**必须先提取辅助函数**（放在 `if (result.type === 'portal')` 分支之前或所在函数作用域顶部）：

```javascript
// 辅助函数：遍历所有 onArrive 彩蛋并触发匹配的
function _checkOnArriveEasterEggs(targetWorld) {
    for (var driverKey in EASTER_EGG_DRIVERS) {
        if (!EASTER_EGG_DRIVERS.hasOwnProperty(driverKey)) continue;
        var drv = EASTER_EGG_DRIVERS[driverKey];
        if (drv.trigger !== 'onArrive') continue;
        if (drv.targetWorld !== targetWorld) continue;

        var chk = pd.easterEggs && pd.easterEggs[drv.stateKey];
        if (chk) continue;  // 已触发过，跳过

        var act = drv.onTrigger({ pd: pd });
        if (act.toast) $P.showToast(act.toast);

        if (act.reward) {
            var aid = act.reward.achievementId;
            if (!pd.taskProgress) pd.taskProgress = {};
            if (!pd.taskProgress.achievements) pd.taskProgress.achievements = {};
            var entry = pd.taskProgress.achievements[aid];
            if (!entry) entry = pd.taskProgress.achievements[aid] = { progress: 0, claimed: false };
            if (!entry.claimed) {
                entry.progress = 1;
                entry.claimed = true;
                if (act.reward.spiritStones) {
                    pd.starSource = (pd.starSource || 0) + act.reward.spiritStones;
                }
            }
        }

        if (!pd.easterEggs) pd.easterEggs = {};
        pd.easterEggs[drv.stateKey] = true;
        worldMapSystem.saveProgress();
    }
}
```

**插入位置 1：portal 彩蛋检测 `checked` 分支**（`loadWorld` → `saveProgress` → `onPass` → `return` 之间）

在世界10→11方案 4.6 节的彩蛋分支代码中，`passAction` 处理完成后、`return` 之前加入一行调用：

```javascript
        // ... 前置代码：loadWorld + saveProgress + passAction 处理 ...

        _checkOnArriveEasterEggs(result.targetWorld);  // ← 插入这一行
        return;
    }
```

**插入位置 2：默认传送分支**（`// ... 原有冷却 + 传送代码 ...` 中，`loadWorld` + `saveProgress` 之后）

在世界10→11方案 4.6 节中，`world_17` BGM 切换之后、默认传送分支结束前，加入调用：

```javascript
        // ... 原有代码：loadWorld + _updateCatSpiritVisibility + saveProgress + BGM ...
        worldMapSystem.loadWorld(result.targetWorld, fromWorld);
        _updateCatSpiritVisibility(result.targetWorld);
        worldMapSystem.saveProgress();
        if (result.targetWorld === 'world_17') {
            if (audioSystem) audioSystem.enterArdeacinerea();
        }
        // ── 通用 onArrive 彩蛋检测 ──────────────────
        _checkOnArriveEasterEggs(result.targetWorld);  // ← 插入这一行
        return;                                         // 原有
    }
```

**为什么必须两处都加**：

- 彩蛋传送分支（有 `easterEgg` 字段的 portal）：内部独立了 `loadWorld` + `saveProgress` + `return`，不会 fall through 到默认传送分支，因此必须在 `return` 前加。
- 默认传送分支（无 `easterEgg` 的普通 portal）：走的是原有传送逻辑，`loadWorld` 在这里执行，因此必须在这里 `return` 前加。

**关键**：这段逻辑不出现 `world_04`、`勒就是灵域` 等特化字符串。只遍历 drivers、匹配 `trigger === 'onArrive'`、匹配 `targetWorld`。新增其他到达彩蛋只需在 `EasterEggConfig` 加一行注册项，game.js 不再改动。

## 七、与 world10→11 彩蛋的统一性

| 维度 | world10→11 彩蛋 | world04 到达彩蛋 |
|------|---------------|-----------------|
| 配置层 | `EasterEggConfig.worldEdge` | `EasterEggConfig.world04Arrive` |
| 触发类型 | portal 点击拦截 | onArrive |
| game.js 特化代码 | 无 | 无 |
| 存档键 | `easterEggs.worldEdgeChecked` | `easterEggs.world04ArriveChecked` |
| 成就 ID | `world_edge` | `world_04_arrive` |
| 灵石 | 150 | 150 |

两者在同一个 `EasterEggConfig.js` 注册表中，game.js 的通用编排逻辑各遍历一次（portal 分支 vs onArrive 分支），新增第三、第四个到达彩蛋只需各加一条注册项。

## 八、风险与边界

- **存档兼容性**：`world04ArriveChecked` 为新增字段，旧存档加载时通过 `_migrateIncomingSaveData` 字段补全自动获得 `false`，首次进入世界4时正常触发。
- **重复触发保护**：`onArrive` 循环中优先检查 `pd.easterEggs[drv.stateKey]`，已标记的跳过。成就写入也通过 `claimed` 防重复。
- **多入口兼容**：world_04 有两个入口（世界3 portal_market、世界5 portal_market_w05），onArrive 检测不依赖入口 portal 的 `easterEgg` 字段，只匹配 `targetWorld`，两个入口都能正常触发。
- **与 portal 彩蛋不冲突**：onArrive 遍历独立于 portal 拦截分支。如果未来某个世界的 portal 同时有 `easterEgg` 字段和 onArrive 彩蛋（比如拦截+到达分别触发），两者互不干扰。
