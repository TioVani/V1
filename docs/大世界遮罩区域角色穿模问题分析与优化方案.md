# 大世界遮罩区域角色穿模问题分析与优化方案

## 问题现象

角色走入遮罩区域（房屋/树木/遮挡物后方）时，从外部视角看：角色身体部分呈现预期的半透明遮挡效果，但**头部及上半身仍然是实体不透明**，形成"半边实体露出来"的视觉穿模。

## 相关文件

| 文件 | 用途 |
|------|------|
| `src/renderers/WorldMapRenderer.js` | 大世界渲染，第364-469行处理玩家遮挡渲染 |
| `src/systems/worldmap/WorldMapPlayer.js` | 遮罩加载、碰撞检测、遮挡判断 |
| `src/config/WorldMapConfig.js` | 每个世界的遮挡遮罩引用 |
| `src/config/CollisionBitmapConfig.js` | RLE 编码的遮挡位图数据 |
| `scripts/generate_collision_data.js` | PNG→RLE 遮罩数据预计算工具 |

## 数据流全貌

```
美术 PNG 遮罩图 (1408x768 px, white=遮挡)
    │
    ▼
generate_collision_data.js  → RLE 编码 → CollisionBitmapConfig.js
    │
    ▼
WorldMapPlayer._decodeRLEBitmap() → Uint8Array (1408x768)
    │
    ▼
WorldMapPlayer._createOcclusionCanvas() → 离屏 Canvas (1408x768)
    │  白色像素(RGBA 255,255,255,255) = 遮挡区域
    │  透明像素(RGBA 0,0,0,0)       = 无遮挡
    │
    ▼
WorldMapRenderer 渲染玩家立绘 (PLAYER_ALPHA.png, 1024x1536)
    │  宽高比 ~0.667 → portraitW=48*scale, portraitH≈72*scale （竖长形）
    │
    ├── source-over: 绘制完整立绘到离屏 canvas
    ├── destination-out: 从 ocCanvas 采样遮罩区域，擦除被遮挡部分
    └── source-over: 将结果绘制到主画布
```

## 根因分析

### 根因1：遮挡采样区域是固定正方形，与实际立绘矩形不匹配

当前采样代码从 ocCanvas 采样的区域：

```
采样基准点: (pwx, pwy) = 玩家地图坐标（脚底位置）
采样范围:    (pwx-14, pwy-14) 到 (pwx+14, pwy+14) → 28x28 像素正方形
```

但玩家立绘的实际渲染范围：

```
立绘宽: portraitW = 48*scale ≈ 48~96 px（取决于屏幕缩放）
立绘高: portraitH = portraitW / imgRatio ≈ 72~144 px
```

**28x28 的正方形采样区仅覆盖立绘中心约 40% 区域。立绘上部（头部）和下部（脚）都在采样范围之外，完全不会被擦除。**

### 根因2：采样锚点未能覆盖立绘全高

- `pos.x/pos.y` 是角色的**地图世界坐标**（碰撞圆圆心，半径为12）
- ocCanvas 的坐标系与地图像素坐标系相同（1408x768）
- 旧代码采样以圆心为中心向四周扩展 14px，即 28x28 正方形
- 但立绘渲染时以圆心为**垂直中心点**绘制，立绘高度（~72*scale 的地图投影）远大于 28px
- 28x28 正方形只能覆盖圆心周围一小段，上半部（头）和下半部（脚）完全在采样区外

### 根因3：遮挡判定是硬切而非渐变

- ocCanvas 只有纯白和透明两种像素，无灰度过渡
- destination-out 合成时对采样区域边界做的是硬切
- 即使采样区域范围正确，边缘也会出现锯齿状裁切

### 根因4：采样未考虑设备像素比（DPR）和屏幕缩放

- 采样区域 28x28 使用的是地图像素坐标（原始尺寸 1408x768）
- 但实际屏幕上地图可能被缩放到更大/更小
- 立绘的 `portraitW`/`portraitH` 基于 `scale = mapScale`，但遮挡采样区域大小是固定的 24+4=28 地图像素
- 在高 DPR 屏幕上，28 地图像素对应的屏幕像素远小于立绘的屏幕像素尺寸

### 视觉效果解释

```
玩家立绘 (竖长形, ~48x72 scale)
┌─────────────┐
│   头部        │  ← 完全在 28x28 采样区之外，保持实体不透明
│   肩膀        │  ← 同样在采样区之外
├─────────────┤
│   胸部        │  ← 部分进入采样区上沿，可能部分被擦除
│   腰部  ──────┤  ← 28x28 正方形中部，被正确擦除
│   腿部  ──────┤  ← 28x28 正方形下部
├─────────────┤
│   脚部        │  ← 在采样区之外，保持实体
└─────────────┘
        ◄── 遮罩区域边界 ───►
```

当角色从下方走入遮挡物后方时，身体中段被擦除变半透明，但头部和脚保持实体，造成"头冒出来"的穿模感。

## 已实施的修复方案

### 改动文件

`src/renderers/WorldMapRenderer.js`

### 根因

`destination-out` 合成时从 ocCanvas（遮挡位图）采样的源矩形是硬编码的 `28x28` 像素正方形（旧代码）：

```
pc.drawImage(occCanvas,
    pwx - 14, pwy - 14, 28, 28,        // 仅从遮罩图采 28x28
    ..., ..., ..., ...);
```

但玩家立绘的实际渲染范围是：

- `portraitW = 48 * scale`
- `portraitH = portraitW / imgRatio ≈ 72 * scale`（竖长矩形）

两者完全不匹配，立绘头部和脚部在采样区之外，不会被擦除。

### 修复逻辑

将 `destination-out` 的源采样矩形从固定 28x28 改为**动态计算，精确覆盖整张立绘在地图坐标系中的范围**：

```
portraitW_map = portraitW / scale   // 立绘宽(地图像素)
portraitH_map = portraitH / scale   // 立绘高(地图像素)
srcW = portraitW_map + margin*2     // 加 2px margin 防边缘漏像素
srcH = portraitH_map + margin*2
srcX = pos.x - srcW/2               // 以玩家圆心为锚点
srcY = pos.y - srcH/2
pc.drawImage(occCanvas,
    srcX, srcY, srcW, srcH,         // 覆盖整个立绘范围
    0, 0, portraitW, portraitH);    // 填满整个离屏 canvas
```

同时，离屏 canvas 尺寸也同步改为与立绘完全一致的 `portraitW x portraitH`（旧代码为 `portraitW+4 x portraitH+4`，带了多余的 padding）。

### 同步修复 fallback 路径

蓝色圆形回退方案（`playerImg` 未加载时）也做了相同的修复——将 `destination-out` 采样区从硬编码 28x28 改为根据 `playerR`+`strokeW` 动态计算的圆形直径，采样区精确匹配圆形大小。

### 为什么根因用 `pos.y` 而不是脚底偏移

玩家坐标 `pos` 在 `WorldMapPlayer` 中是碰撞圆的**圆心**（碰撞半径 `_playerRadius = 12`）。立绘渲染时 `psp` 是 `worldToScreen(pos)` 即圆心屏幕坐标，立绘以圆心为垂直中心绘制——向上延伸 `portraitH/2`，向下延伸 `portraitH/2`。因此采样锚点直接使用 `pos` 圆心，上下各取 `srcH/2` 即可覆盖整个角色。

### 不改什么

- ocCanvas 的生成逻辑（`_createOcclusionCanvas`）不变——仍为二元黑白位图
- `destination-out` 的 alpha 值保持 `0.7`——遮挡区域变 0.3 透明度
- 不做渐变边缘——当前修复先消除核心的漏穿问题，渐变过渡属于视觉优化范畴

### 向后兼容

- 所有世界地图通用，不依赖特定世界的遮罩配置
- 不同楼层通过 `_loadFloorData()` 切换遮罩位图，修复自动兼容
- 无新增依赖、无数据格式变更

## 额外注意事项

1. **左右镜像：** 遮挡处理需要同时兼容 `facingX < 0`（角色朝左）时的坐标翻转逻辑（当前在 `source-over` 阶段已处理镜像，`destination-out` 阶段未做镜像，但遮挡区域与角色朝向无关，无需处理）

2. **多楼层：** 不同楼层使用不同的遮罩位图（如 world_01_T01、world_01_T02），当前 `_loadFloorData()` 已正确切换，修复方案自动兼容

3. **性能：** 方案二仅改变了采样区域大小（从 28x28 像素到约 48x72 地图像素），对性能无实质影响
