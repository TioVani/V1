# 联连技 & 节奏技 — 全屏伤害视觉优化方案

> 问题：联连技和节奏技结算时只有文字消息 + 屏幕震动，没有任何全屏视觉反馈，玩家无法直观感知技能是否生效。

---

## 一、现状分析

### 1.1 当前结算流程（以联连技为例）

```
applyJudgeResult() 执行:
  1. 遍历所有活怪 → 直接扣 mon.hp（无视觉特效）
  2. addMessage("联连技! 3连 ×3.0 -150")  ← 仅文字
  3. createScreenShake(8)                   ← 仅震动
  4. vibrateShort('heavy')                  ← 仅触觉
```

**缺失环节**：全过程没有任何画面级视觉反馈——没有全屏闪光、没有冲击波扩散、没有伤害飞字、没有屏幕颜色变化。玩家看到屏幕震了一下，但无法确认"是我的技能打中了"还是"我被怪物打了"。

### 1.2 节奏技现状

节奏技有两个阶段的视觉表现：

- **每次成功点击**（Perfect/Great）：已有从缩圈灵光中心扩散的青色冲击波（`shockwaveTime` 机制，400ms圆环扩散）。视觉上可感知，但半径仅覆盖缩圈灵光附近区域，不扩散到全屏。
- **`settle()` 结算**：只有 `createScreenShake()` + 文字消息，全屏 AOE 伤害结算瞬间没有任何全屏视觉反馈。

本次优化的重点是**结算瞬间的全屏视觉**，每次点击的小冲击波保留不改。

### 1.3 已有的可复用能力

项目中 AnimationSystem 已具备：
- **怪物伤害飞字** (`createMonsterDamageAnimation`)：在怪物上方弹出伤害数字，金黄色字体+深红描边，带淡出和上飘
- **流星爆炸** (`createMeteorHitEffect`)：圆环扩散 + 粒子飞散
- **屏幕震动** (`createScreenShake`)：已在使用
- **战斗渲染器** (`GameBattleRenderer`)：控制游戏画面渲染的根节点

注意：`createMonsterDamageAnimation` 的实际签名为 `(monster, damage)`，其中 `monster` 必须是一个带有 `.x` 和 `.y` 属性的对象。game.js 第 1497 行有一个包装函数 `(x, y, dmg)` 但实现有误。联连技/节奏技需要构造 `{ x: mon.x, y: mon.y }` 临时对象来使用它。

---

## 二、需要新增的视觉特效

按优先级分为 **T0（必须）→ T1（应有）→ T2（锦上添花）** 三个层级。

---

### T0：联连技全屏冲击波（diffusion ring）

**目标**：联连技/强化联连技结算瞬间，从屏幕中心扩散一道金色冲击波，扫过所有怪物位置。

**视觉设计**：
- 1 道金色圆环从屏幕中心 (`screenW/2`, `screenH/3`) 向外扩散
- 持续时间：600ms
- 半径：0 → `max(screenW, screenH) * 1.2`
- 透明度：1.0 → 0（线性衰减）
- 环宽：3px → 12px（随扩散变粗）
- 颜色：金色 `#FFD700`，强化联连技加一道第二层橙色环 `#FF8C00`

**数据结构**：
```js
state.shockwaveRings = [
  { startTime, duration: 600, color: '#FFD700', startRadius: 0,  
    endRadius: maxDimension * 1.2, alpha: 1.0 }
]
```

**渲染**：在 `render()` 的 `judging` 阶段末尾，叠加绘制：
```
ctx.strokeStyle = rgba(255,215,0, alpha)
ctx.lineWidth = 3 + progress * 9
ctx.arc(screenCenter, radius)
```

**触发时机**：`enterJudging('success')` 时创建（phase 为 judging），在 judging 的 1000ms 闪烁期间渲染。`applyJudgeResult()` 时特效数据可随 phase=idle 一起清理。

---

### T0：联连技全屏白色闪白（screen flash）

**目标**：结算瞬间全屏闪一道白光，类似"被闪光弹击中"的感觉，强化力量感。

**视觉设计**：
- 全屏白色遮罩，从透明度 0.4 → 0（300ms）
- 颜色：纯白 `rgba(255,255,255, alpha)`
- 强化联连技：从 0.6 开始衰减

**数据结构**：
```js
state.screenFlash = { startTime, duration: 300, peakAlpha: 0.4 (或 0.6) }
```

**渲染**：在 `render()` 中 judging 阶段绘制，检查 `state.screenFlash` 是否存在而非依赖 phase。全屏矩形填充 `rgba(255,255,255, alpha)`。过期后置 null。

---

### T0：伤害飞字在怪物上方弹出

**目标**：每只受伤怪物头顶弹出伤害数字，玩家能直观看到"打掉了多少血"。

**视觉设计**：
- 复用 AnimationSystem 已有的 `createMonsterDamageAnimation(monsterObj, damage)`
- 每只怪头顶弹出 `-{damage}`，金黄色字体 + 深红描边
- 动画时长：800ms，向上飘移 50px + 淡出
- 自动使用 `CombatFontConfig` 的 damage 字体样式

**实现方式**：在 `applyJudgeResult()` 遍历怪物时，为每只受伤怪物构造临时对象调用：

```js
createMonsterDamageAnimation({ x: mon.x, y: mon.y }, dmg)
```

不需要额外传入颜色或缩放参数——`AnimationSystem.createMonsterDamageAnimation` 已有完整的默认渲染（金黄色字体 + 深红描边 + 缩放 1.0→1.8 + 淡出）。

**依赖注入**：在 game.js 中 LinkChainSystem 和 RhythmSkillSystem 的注入新增：

```js
createMonsterDamageAnimation: function(obj, dmg) {
    createMonsterDamageAnimation(obj, dmg);  // 直接透传
}
```

---

### T1：怪物受击闪烁（hit flash）

**目标**：怪物被联连技击中时短暂变白/变亮，提供"受击确认"。

**视觉设计**：
- 每只怪物在受伤瞬间叠加一层白色 `globalCompositeOperation = 'lighter'`
- 持续 200ms
- 给怪物对象临时添加 `_hitFlashUntil = Date.now() + 200`

**涉及渲染器**（均需检测 `_hitFlashUntil` 标记）：

| 渲染器 | 文件 | 说明 |
|--------|------|------|
| `GameBattleRenderer` | `src/renderers/GameBattleRenderer.js` | 普通战斗模式，覆盖所有联连技/节奏技场景 |
| `BossRenderer` | `src/renderers/BossRenderer.js` | Boss 战——联连技可用但节奏技在 Boss 模式不可用（D5未解锁） |
| `TowerRenderer` | `src/renderers/TowerRenderer.js` | 无尽之塔模式 |
| `StageRenderer` | `src/renderers/StageRenderer.js` | 赛季关卡模式 |

实现方式：各渲染器在绘制怪物本体前检查 `mon._hitFlashUntil`，若未过期则：
```
ctx.globalCompositeOperation = 'lighter';
// 绘制怪物本体
ctx.globalCompositeOperation = 'source-over';
```

如果希望减少改动面，可以只在 `GameBattleRenderer` 中实现（覆盖绝大多数使用场景），Tower/Stage/Boss 作为后续扩展。

---

### T1：节奏技也复用上述特效

节奏技结算 `settle()` 缺少的视觉反馈与联连技完全相同。可以在 `RhythmSkillSystem` 中引入相同的：
- 全屏冲击波（颜色改为青色 `#00FFFF`，体现节奏技的身份色）
- 全屏闪白
- 伤害飞字

**节奏技冲击波差异化**：
- 颜色：青色 `#00FFFF`（与充能条第二段颜色一致）
- 成功次数 ≥ 12 时，叠加 2 层冲击波（金 + 青）
- 成功次数 ≥ 24 时，叠加 3 层（金 + 青 + 紫 `#FF00FF`）

---

### T2：联连技结算屏幕暗角 + 中央光柱

**目标**：联连技结算时屏幕四角变暗，中央升起一道淡金色光柱，营造"大招释放"的仪式感。

**视觉设计**：
- 暗角：全屏径向渐变，中心透明、四角 `rgba(0,0,30,0.5)`，600ms 淡出
- 光柱：屏幕中央纵向 `100px` 宽半透明金色渐变条，从下到上淡出

---

### T2：音效增强

**目标**：联连技结算时播放大招专属音效。

**方式**：在 `applyJudgeResult()` 中调用 `audioSystem.playLinkFinish()`（需 AudioSystem 新增此音效）。

## 三、实施架构

### 3.1 依赖注入变更

**LinkChainSystem** 当前依赖注入不包含 AnimationSystem。需要新增：

```js
// game.js 中 createLinkChainSystem 的依赖注入新增:
createScreenShake: function(i) { createScreenShake(i); },  // 已有
// 新增 ↓
createMonsterDamageAnimation: function(obj, dmg) { createMonsterDamageAnimation(obj, dmg); }
```

**RhythmSkillSystem** 当前已有 `createMeteor` 注入，需要新增：

```js
// game.js 中 createRhythmSkillSystem 的依赖注入新增:
createMonsterDamageAnimation: function(obj, dmg) { createMonsterDamageAnimation(obj, dmg); }
```

注意：`createMonsterDamageAnimation` 的 AnimationSystem 实际签名是 `(monster, damage)`，其中 monster 需要有 `.x`/`.y` 属性。game.js 已有的包装函数 `createMonsterDamageAnimation(x, y, dmg)` 有参数传递问题，这里直接透传对象。调用时使用 `{ x: mon.x, y: mon.y }` 而非 `mon.x, mon.y`。

### 3.2 特效生命周期管理

全屏冲击波环和全屏闪白作为 `LinkChainSystem` 内部状态管理（伤害飞字除外，委托给 AnimationSystem）。

**关键时序问题**：`applyJudgeResult()` 执行后 `state.phase` 立即变为 `idle`，而当前 `render()` 中 `state.phase === 'idle'` 时直接 `return`。因此特效数据必须在 `enterJudging('success')` 时创建（此时 phase 还是 `judging`），在 judging 的 1000ms 闪烁期间渲染。

```js
function enterJudging(result) {
    state.phase = 'judging';
    state.judgeStartTime = Date.now();
    state.judgeResult = result;
    state.swipeActive = false;

    // 创建全屏特效数据（在 judging 1000ms 期间渲染）
    if (result === 'success') {
        state.screenFlash = { startTime: Date.now(), duration: 300, peakAlpha: isEnhanced ? 0.6 : 0.4 };
        state.shockwaveRings = [{
            startTime: Date.now(), duration: 600,
            color: '#FFD700', startRadius: 0, endRadius: maxDimension * 1.2
        }];
        if (isEnhanced) {
            state.shockwaveRings.push({
                startTime: Date.now() + 100, duration: 500,
                color: '#FF8C00', startRadius: 0, endRadius: maxDimension * 1.2
            });
        }
    }
}
```

**渲染顺序**：在 `render()` 中，`judging` 阶段的闪烁效果之后、灵光绘制之前插入特效渲染。不要依赖 `phase === 'judging'` 来判断——改为检查特效数据是否存在：

```js
// render() 中，在 existing "if (state.phase === 'idle') return;" 之前插入:
if (state.screenFlash || state.shockwaveRings.length > 0) {
    // 绘制全屏闪白
    if (state.screenFlash) {
        var flashElapsed = Date.now() - state.screenFlash.startTime;
        if (flashElapsed < state.screenFlash.duration) {
            var flashAlpha = state.screenFlash.peakAlpha * (1 - flashElapsed / state.screenFlash.duration);
            ctx.fillStyle = 'rgba(255,255,255,' + flashAlpha + ')';
            ctx.fillRect(0, 0, screenW, screenH);
        } else {
            state.screenFlash = null;
        }
    }
    // 绘制冲击波环 ...
}
```

这样特效在 judging 阶段可以渲染（phase != idle），judging 结束后特效数据自动过期清理，不影响后续 idle 帧。

`update()` 中同样需要清理过期特效：

```js
// update() 开头追加:
if (state.screenFlash && Date.now() - state.screenFlash.startTime >= state.screenFlash.duration) {
    state.screenFlash = null;
}
// 清理过期冲击波环同理
```

### 3.3 特效绘制顺序（从上到下）

```
1. 游戏画面（灵光、怪物等）
2. 慢动作遮罩 (rgba(0,0,50,0.15))
3. 联连技全屏闪白
4. 联连技冲击波环
5. 联连技光柱（T2）
6. 暗角（T2）
7. 联连灵光 + 链线 + 流星（现有）
```

### 3.4 节奏技同理

`RhythmSkillSystem` 在 `settle()` 中创建特效，在 `render()` 中绘制。

已有的小冲击波（每次点击）保持不变。

**时序注意事项**：与 LinkChainSystem 相同，`settle()` 执行后 `state.rhythmStar = null`，当前 `render()` 第一行 `if (!rs) return` 会导致特效无法渲染。需要改为在 `render()` 开头无条件检查特效数据：

```js
function render(ctx, screenW, screenH, scale) {
    // 结算特效（即使 rhythmStar 为 null 也要渲染）
    if (state.settleFlash || state.settleShockwaveRings.length > 0) {
        // 绘制闪白...
        // 绘制冲击波环...
    }

    var rs = state.rhythmStar;
    if (!rs && !state.settleFlash && state.settleShockwaveRings.length === 0) return;
    // ... 后续现有代码
}
```

新增结算特效 state 和创建逻辑：

```js
// RhythmSkillSystem 新增 state
state.settleFlash = null;
state.settleShockwaveRings = [];

// settle() 中创建
if (skill && count >= 1) {
    state.settleFlash = { startTime: Date.now(), duration: 300, peakAlpha: 0.4 };
    state.settleShockwaveRings = [...];  // 根据 count 决定层数
    // 伤害飞字：遍历怪物调用 createMonsterDamageAnimation({ x, y }, dmg)
}
```

节奏技冲击波层级规则：
- 1 层（count 1-11）：青色 `#00FFFF`
- 2 层（count 12-23）：金 `#FFD700` + 青 `#00FFFF`
- 3 层（count 24+）：金 + 青 + 紫 `#FF00FF`

## 四、实施清单

| 优先级 | 特效 | 系统 | 改动范围 |
|--------|------|------|---------|
| **T0** | 全屏冲击波环 | LinkChainSystem + RhythmSkillSystem | 新增 state + render 绘制 |
| **T0** | 全屏闪白 | LinkChainSystem + RhythmSkillSystem | 新增 state + render 绘制 |
| **T0** | 伤害飞字 | LinkChainSystem + RhythmSkillSystem | 依赖注入 `createMonsterDamageAnimation` + 遍历怪物时构造 `{x,y}` 对象调用 |
| **T1** | 怪物受击闪烁 | LinkChainSystem + GameBattleRenderer（最小改动） | 怪物对象加 `_hitFlashUntil` + `GameBattleRenderer` 检测（可后续扩展到其他渲染器） |
| **T2** | 暗角 + 光柱 | LinkChainSystem | 新增 state + render 绘制 |
| **T2** | 联连技专属音效 | LinkChainSystem + AudioSystem | AudioSystem 新增 `playLinkFinish` |

注：RhythmSkillSystem 每次点击已有小冲击波（保留），本次新增的是 `settle()` 结算瞬间的全屏冲击波环 + 全屏闪白 + 伤害飞字。
