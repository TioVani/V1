# 空格键触发灵光方案

## 一、需求概述

玩家在编队面板中将某个已装备灵光指定为"空格灵光"。战斗中该灵光照常随机生成在舞台上，玩家除了可以点击它，还可以直接按空格键触发它——无论灵光在舞台上的哪个位置。

当玩家首次获得闪避灵光时，触发空格灵光装备引导教程。

## 二、不改变的内容

- 灵光生成机制完全不变（频率、位置、类型池均不动）
- 触摸/鼠标点击灵光的原有行为完全不变
- `equippedStars` 管理方式不变
- `StarSystem`、`BattleEngine`、`ChargeSystem` 内部逻辑不变

## 三、方案设计

### 3.1 空格灵光绑定

存档新增字段：

```
pd.spaceKeyStar = null | 灵光ID
```

必须是 `pd.equippedStars` 中的灵光类型。

#### 编队面板 UI

在 `SquadRenderer.js` 已装备槽位中，点击槽位可将其设为"空格灵光"（已有 5 个槽位，选一个标为空格键触发）。同时只能有一个。

### 3.2 触发逻辑

空格按下后不立即触发灵光，而是进入等待窗口（150ms），由松手时机决定短按还是长按：

```
空格按下 (keydown, e.key === ' ' && !e.repeat)
  → 条件检查：
      - 战斗状态：state === PLAYING/SEASON_PLAYING/STAGE_PLAYING/BOSS_BATTLE/TOWER_COMBAT
      - 未被硬控：playerEffects.isStunned && playerEffects.isStunned() === false
      - 节奏技未激活：!rhythmSkillSystem || !rhythmSkillSystem.isActive()
      - pd.spaceKeyStar 非空
  → 遍历 stars[]（从后往前），找第一个 type === pd.spaceKeyStar && visible === true 的灵光
  → 没找到 → 不响应
  → 找到 → 记录 _spaceKeyHolding = true、_spaceKeyDownTime = Date.now()、_spaceKeyTargetStar = ref
  → 不立即消费灵光，等待 keyup 事件
```

```
空格松手 (keyup, e.key === ' ')
  → 检查 _spaceKeyHolding
  → 计算 holdDuration = Date.now() - _spaceKeyDownTime
  → holdDuration < 150ms → 短按：
      调用 normalBattleAdapter.handleStarClick(_spaceKeyTargetStar.x, _spaceKeyTargetStar.y)
  → holdDuration >= 150ms → 长按（走 3.3 蓄力释放）
  → 清除 _spaceKeyHolding / _spaceKeyTargetStar / _spaceKeyDownTime
```

**多灵光场景**：如果舞台上有多个相同类型的灵光，从后往前遍历取第一个（数组末尾元素最新加入，`handleStarClick` 内部也是从后往前命中上层灵光）。

**管道交互**：空格触发走 `keydown/keyup` 事件，完全独立于 TouchPipeline。空格短按调用 `normalBattleAdapter.handleStarClick` 与管道的 `starClickMiddleware` 走同一个接口，灵光被正常消费。

`BattleEngine.handleSpecialStar` 不是公开 API。通过 `normalBattleAdapter.handleStarClick(x, y)` 用灵光坐标模拟点击是最安全的路径，能走通完整的碰撞检测、扩展钩子、动画和音效。由于坐标精确命中灵光中心，碰撞检测的命中率是 100%。

### 3.3 长按蓄力

空格按住超过 150ms（`holdDuration >= 150ms`）→ 进入蓄力状态。松手释放蓄力技。

**调用路径**（基于 3.2 的状态机）：

1. `keydown` 时记录 `_spaceKeyDownTime`、`_spaceKeyTargetStar`（与 3.2 共用）
2. 在 `game.js` 的 update 循环中检查：`_spaceKeyHolding && Date.now() - _spaceKeyDownTime > 150`
3. 150ms 到达 → 调用 `ChargeSystem.beginMonitoring()`（传入 `touchId = 'spacekey'`、蓄力中心取 `_spaceKeyTargetStar` 的坐标和灵光对象）
4. `keyup` → 若 `holdDuration >= 150ms` → 调用 `ChargeSystem.releaseCharge()` 释放蓄力技
5. 如果蓄力期间灵光被联连冲击波等其他系统消费（`_spaceKeyTargetStar.visible === false`），取消当前蓄力

**关键点**：长按路径下不调用 `normalBattleAdapter.handleStarClick`。`ChargeSystem.beginMonitoring` 会标记灵光的 `_charging` 属性，蓄力释放时 `releaseCharge` 内部调用 `stars.splice` 消费灵光 + 生成流星效果。短按路径和长按路径互斥。

`ChargeSystem.beginMonitoring` 的 `touchId` 参数传入 `'spacekey'`，不与真实触摸 ID 冲突。

### 3.4 空格灵光装备引导教程

#### 3.4.1 触发时机

玩家首次获得闪避灵光时触发。闪避灵光的获取途径是：与猫灵 NPC 对话第 3 次，选择 `'care'` 选项（`NpcDialogueConfig.js` 第 82 行 `unlockedStarTypes.push('dodge')`）。

在 `_handleNpcDialogue` 中，`drv.onChoice()` 返回后（`game.js` 第 4269 行附近），新增引导触发逻辑：

```
var result = drv.onChoice(pd, driverId, state, choiceKey);
if (result && result.toast) {
    $P.showToast({ title: result.toast, icon: 'success', duration: 2500 });
}
worldMapSystem.saveProgress();

// ★ 新增：检测是否首次获得闪避灵光，触发引导
if (choiceKey === 'care' && driverId === 'cat_spirit' && pd.unlockedStarTypes.indexOf('dodge') !== -1 && !pd._spaceKeyTutorialShown) {
    pd._spaceKeyTutorialShown = true;
    _pendingSpaceKeyTutorial = true;  // game.js 闭包变量
}
```

不做任何对 `NpcDialogueConfig.js` 的修改。引导触发逻辑全部在 `game.js` 的 `_handleNpcDialogue` 中完成，基于对已有返回值的判断。

#### 3.4.2 引导流程

```
获得闪避灵光 (toast 提示)
  → 猫灵对话关闭，玩家回到大地图自由状态
  → game.js 在 _handleNpcDialogue 中设置 _pendingSpaceKeyTutorial = true
  → 玩家下次打开编队面板时，game.js 检测 _pendingSpaceKeyTutorial === true
  → 调用 squadRenderer.setTutorialHighlight('dodge')
  → 编队面板中闪避灵光所在的行（已解锁灵光列表中的 dodge 行）高亮闪烁
  → 同时顶部未填满的槽位也高亮闪烁（提示玩家需要先装备再设定空格键）
  → 弹出引导气泡：「获得闪避灵光！点击装备后，再点击装备槽位设为空格键触发。」
  → 玩家点击「装备」→ 灵光进入 equippedStars → 玩家再点击该槽位设为空格灵光
  → pd.spaceKeyStar = 'dodge'
  → SquadRenderer 调用 deps.onTutorialComplete()
  → game.js 设置 _pendingSpaceKeyTutorial = false
  → 引导完成，高亮和气泡消失
```

#### 3.4.3 引导 UI

`SquadRenderer` 新增公开方法 `setTutorialHighlight(starId)`。在 `game.js` 第 2439 行附近的 `createSquadRenderer` deps 对象中新增一项：

```
onTutorialComplete: function() {
    _pendingSpaceKeyTutorial = false;
}
```

编队面板打开时，game.js 检测 `_pendingSpaceKeyTutorial === true`，调用 `squadRenderer.setTutorialHighlight('dodge')`：

- 闪避灵光在已解锁灵光列表中对应行背景高亮闪烁（金色描边 + 呼吸动画）
- 顶部空余装备槽位同步高亮闪烁
- 渲染一个箭头气泡指向该灵光：「获得闪避灵光！点击装备后，再点击装备槽位设为空格键触发。」
- 玩家完成装备 + 设定空格键 → `SquadRenderer` 调用 `deps.onTutorialComplete()` → game.js 清除标记 → 高亮和气泡消失

引导不阻断玩家其他操作（非模态）。玩家直接关闭编队面板则高亮和气泡随面板关闭消失——下次打开面板也不再生效（`pd._spaceKeyTutorialShown` 已为 true）。

#### 3.4.4 状态记录

持久化：
```
pd._spaceKeyTutorialShown: true   // 引导已触发过，不再重复
```

game.js 闭包变量（非持久化）：
```
var _pendingSpaceKeyTutorial = false;  // 待触发的引导标记
var _spaceKeyHolding = false;          // 空格是否正在按住
var _spaceKeyDownTime = 0;             // 空格按下时刻
var _spaceKeyTargetStar = null;        // 空格目标灵光引用
```
