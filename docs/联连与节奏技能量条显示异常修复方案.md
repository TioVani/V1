# 联连与节奏技能量条显示异常修复方案（终版）

## 用户需求

- 充能 100：第一次联连窗口
- 充能 150：第二次联连窗口
- 充能 200：节奏技
- **如果联连窗口还在（150 的 ready 还没超时）时充能冲到 200，直接掐掉联连窗口进节奏技**

## 涉及文件

| 文件 | 改动行数 | 改动内容 |
|------|---------|---------|
| `V1/src/systems/LinkChainSystem.js` | ~10 行 | 删除 `ready_closed` 阶段；200 命中时掐掉 ready 窗口 |

## 当前状态机

```
idle → ready(100) → idle → ready(150) → ready_closed → rhythm_ready(200)
                ↑超时2000ms       ↑超时2000ms    ↑充能到200
```

问题：
1. `ready_closed` 阶段能量条不渲染（`showBar` 不包含此阶段），能量条消失
2. `ready_closed` 阶段是只充能无窗口的过渡阶段，没有存在必要

## 目标状态机

```
idle → ready(100) → idle → ready(150) → rhythm_ready(200, 掐掉 ready)
                ↑超时2000ms       ↑超时2000ms 或充能到200
```

变化：
1. `ready` 窗口存续期间充能到 200 → 直接调用 `enterRhythmReady()` 掐掉联连窗口
2. 彻底删除 `ready_closed` 阶段
3. 能量条在 `idle → ready → rhythm_ready` 全程显示，无断层

## 具体改动

所有改动在 `LinkChainSystem.js`。

### 改动 1：`addCharge()` — 200 命中时主动掐掉 ready 窗口

```javascript
// 当前代码（行 155-158）：
// ready → rhythm_ready at 200
if (state.phase === 'ready' && state.charge >= RHYTHM_THRESHOLD) {
    enterRhythmReady();
}

// 改为：
// ready → rhythm_ready at 200（如果联连窗口还在，直接掐掉进节奏）
if (state.phase === 'ready' && state.charge >= RHYTHM_THRESHOLD) {
    addMessage('充能满溢! 联连窗口已跳过!', '#00FFFF', true);
    enterRhythmReady();  // 统一在 enterRhythmReady 中清理 triggerStar
    return;
}
```

**说明**：`ready` 窗口存续期间充能到 200，不再等待超时，直接进节奏。triggerStar 由 `enterRhythmReady()` 统一清理。消息提示告知玩家联连窗口被跳过（避免与 `enterRhythmReady()` 自带的"进入节奏阶段"消息重复刷屏）。

### 改动 2：`addCharge()` — 删除 `ready_closed` 相关分支

```javascript
// 删除以下代码块：
// ready_closed 阶段：联连窗口已关闭，只充能不弹窗，直到200触发节奏技

```

**说明**：`ready_closed` 阶段不再存在，充能到 200 的节奏触发由其他分支（`ready` 阶段命中 200 或 `idle` 阶段命中等）处理。

### 改动 3：`addCharge()` — 充能封锁列表中删除 `ready_closed`

### 改动 4：`addCharge()` — `idle` 阶段直接到 200 的处理

`idle` 阶段如果一次充能直接冲到 200（例如蓄力释放 +40），需要直接进节奏：

```javascript
// 当前代码中 idle → rhythm_ready 没有分支。
// 在 idle 的两个 ready 判断之后增加：
if (state.phase === 'idle' && state.charge >= RHYTHM_THRESHOLD) {
    enterRhythmReady();
    return;
}
```

**说明**：如果充能来源一次性给超过 50，可能从 idle 直接跳到 200（跳过 100 和 150 的联连窗口）。这个分支确保直接进节奏技不卡住。

### 改动 5：`update()` — 删除 `ready_closed` 超时处理

```javascript
// 当前 update() 中 ready 超时处理（行 694-710）：
if (state.phase === 'ready') {
    if (Date.now() - state.readyStartTime >= READY_TIMEOUT_MS) {
        if (state.triggerStar) {
            state.triggerStar._linking = false;
            state.triggerStar.disappearTime = ...;
        }
        state.triggerStar = null;
        // 根据充能量决定后续阶段
        if (state.charge >= SECOND_READY_THRESHOLD) {
            // 第二次窗口超时 → 联连窗口永久关闭，继续向200推进
            state.phase = 'ready_closed';  // ← 这个分支改为回到 idle
            addMessage('联连窗口已关闭，继续充能...', '#ffaa00');
        } else {
            // 第一次窗口超时 → 可等待第二次窗口
            state.phase = 'idle';
            addMessage('联连超时，继续充能...', '#ffaa00');
        }
    }
    return;
}

// 整个 if-else 改为：
if (state.phase === 'ready') {
    if (Date.now() - state.readyStartTime >= READY_TIMEOUT_MS) {
        if (state.triggerStar) {
            state.triggerStar._linking = false;
            state.triggerStar.disappearTime = state.triggerStar._linkingOriginalDisappearTime || Date.now() + 5000;
        }
        state.triggerStar = null;
        state.phase = 'idle';
        addMessage('联连超时，继续充能...', '#ffaa00');
    }
    return;
}
```

**说明**：联连窗口超时后直接回 `idle`，不再区分第一次还是第二次窗口。充能继续推进，150 时自然触发第二次 `ready`，200 时自然触发节奏技（如果此时又恰好处于 `ready`，则被改动 1 掐掉）。

## 改动后的完整 `addCharge()`

```javascript
function addCharge(amount) {
    if (!isUnlocked()) return;
    if (state.phase === 'revealing' || state.phase === 'waiting' ||
        state.phase === 'swiping'   || state.phase === 'judging' ||
        state.phase === 'rhythm_ready') return;
    if (rhythmSkillSystem && rhythmSkillSystem.isActive()) return;

    state.charge = Math.min(RHYTHM_THRESHOLD, state.charge + amount);

    // idle → ready at 100 (第一次联连窗口)
    if (state.phase === 'idle' && state.charge >= LINK_THRESHOLD && state.charge < SECOND_READY_THRESHOLD) {
        enterReady();
        return;
    }
    // idle → ready at 150 (第二次联连窗口)
    if (state.phase === 'idle' && state.charge >= SECOND_READY_THRESHOLD && state.charge < RHYTHM_THRESHOLD) {
        enterReady();
        return;
    }
    // idle 阶段直接冲到 200 → 跳过联连，直接节奏
    if (state.phase === 'idle' && state.charge >= RHYTHM_THRESHOLD) {
        enterRhythmReady();
        return;
    }
    // ready 阶段充到 200 → 掐掉联连窗口，进节奏
    if (state.phase === 'ready' && state.charge >= RHYTHM_THRESHOLD) {
        addMessage('充能满溢! 联连窗口已跳过!', '#00FFFF', true);
        enterRhythmReady();
        return;
    }
}
```

**关键**：`idle` 的两个 ready 分支加了上界判断（`< SECOND_READY_THRESHOLD` 和 `< RHYTHM_THRESHOLD`），防止一次大量充能时命中两个 ready 分支后又命中 rhythm 分支，导致重复 `enterReady()`。

## 状态流转验证

验证所有充能路径：

| 起始 | 充能后 charge | 结果 |
|------|-------------|------|
| idle, 0 | +100 → 100 | enterReady()，第一次联连窗口 |
| idle, 50 | +50 → 100 | enterReady()，第一次联连窗口 |
| idle, 0 | +150 → 150 | enterReady()，**跳过一次联连**，直接第二次窗口 |
| idle, 0 | +200 → 200 | **跳过两次联连**，直接 enterRhythmReady() |
| idle, 100 | +50 → 150 | enterReady()，第二次联连窗口 |
| idle, 150 | +50 → 200 | enterRhythmReady()，直接节奏（150 窗口已超时回到 idle） |
| ready(150), 170 | +30 → 200 | 掐掉 ready 窗口，enterRhythmReady() |
| ready(100), 120 | +80 → 200 | 掐掉 ready 窗口，enterRhythmReady() |
| ready(100), 100 | 超时 2000ms | 回 idle，charge 保持 100，继续充能等 150 |

所有路径都工作，没有卡死分支。

## 回答你的问题

> 如果联连存在还未到消失时间那么就直接消失就好了，在你觉得呢？

**完全同意**，这是最简洁的设计。理由：

1. **节奏技优先级高于联连技** — 充能满 200 说明玩家已经过两轮联连窗口的选择（点了就进联连，不点就继续充），到 200 时还没进联连说明玩家更想要节奏技
2. **消除中间过渡阶段** — `ready_closed` 阶段只是为了让能量条"等着到 200"，但它导致能量条不显示的 UI bug。直接掐掉联连窗口进节奏，状态机更干净
3. **用户体验一致** — 玩家看到能量条始终显示（idle→ready→rhythm_ready），不会出现"能量条消失又出现"的困惑
