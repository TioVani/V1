# 联连与节奏技能量条显示异常分析与优化方案

## 涉及文件

| 文件 | 角色 |
|------|------|
| `V1/src/systems/LinkChainSystem.js` | 充能条状态机（0→200）、联连窗口/节奏窗口切换、充能条渲染 |
| `V1/src/systems/RhythmSkillSystem.js` | 节奏灵光缩圈玩法、判定、结算、pending 超时重试 |
| `V1/src/renderers/GameBattleRenderer.js` | 渲染调度入口，按序调用 LinkChain → RhythmSkill 的 render |
| `V1/game.js` | 初始化、注入、触摸分发优先级 |

## 状态机概览

```
LinkChainSystem phase:
  idle → ready → ready_closed → rhythm_ready → idle
         ↓ (玩家触摸)              ↓ (enterRhythmReady)
    revealing → waiting → swiping → judging → idle

RhythmSkillSystem phase:
  idle → pending → active → idle (settle)
               ↓ (超时4000ms)
             idle (respawnTimer=4000ms → 重新 enter)
```

## 问题一：充能到 200 后联连灵光仍在出现

### 根因

`addCharge()` 中，当 charge 达到 200 时进入 `enterRhythmReady()`，会清理触发灵光：

```javascript
// LinkChainSystem.js:178-190
function enterRhythmReady() {
    if (state.triggerStar) {
        state.triggerStar._linking = false;
        state.triggerStar.disappearTime = ...;
        state.triggerStar = null;
    }
    state.phase = 'rhythm_ready';
    if (rhythmSkillSystem) rhythmSkillSystem.enter();
}
```

但问题在于 `addCharge()` 中充能封锁的条件：

```javascript
// LinkChainSystem.js:133-138
if (state.phase === 'revealing' || state.phase === 'waiting' ||
    state.phase === 'swiping'   || state.phase === 'judging' ||
    state.phase === 'rhythm_ready') return;
if (rhythmSkillSystem && rhythmSkillSystem.isActive()) return;
```

**关键漏洞**：`addCharge()` 在 `rhythm_ready` 阶段确实被封锁，但 `enterRhythmReady()` 之后，`rhythmSkillSystem.isActive()` 返回 `false` 的时间窗口很短（仅在 `enter()` 调用后到 `phase = 'pending'` 赋值之间）。如果在此窗口内又有充能事件触发 `addCharge()`，且 phase 尚未变为 `rhythm_ready`（实际上 `enterRhythmReady()` 先设置 `phase` 再调用 `rhythmSkillSystem.enter()`），不会有问题。

**真正的问题**在于：`enterRhythmReady()` 中调用 `rhythmSkillSystem.enter()` 创建了一颗节奏灵光，但**场上原有的普通灵光没有被清理**。`enterRhythmReady()` 只清理了 `triggerStar`，其他灵光继续正常生成。所以用户看到的"联连灵光还在出现"实际上是**普通灵光正常生成**，而不是联连触发灵光。

### 脉络

1. 充能到 200 → `enterRhythmReady()` → 清理触发灵光 → 进入 `rhythm_ready`
2. `rhythmSkillSystem.enter()` 创建节奏灵光，进入 `pending`
3. 场上普通灵光（stars 数组）继续由 `StarSystem` 正常生成，与节奏技无关
4. 由于 `addCharge()` 在 `rhythm_ready` 阶段被封锁，不会再充能，也不会再触发联连窗口

**结论**：这是设计预期行为，不是 bug。但用户可能混淆了"普通灵光"和"联连触发灵光"。如果期望节奏阶段完全清空场上灵光，需要在 `enterRhythmReady()` 中额外清理。

## 问题二：节奏灵光半天不出来

### 根因

节奏灵光"半天不出来"有两条路径：

**路径 A：联连窗口未关闭，充能卡在 100-200 之间**

充能到 100 触发第一次联连窗口（`ready`），此时有 2000ms 等待玩家触摸。超时后：
- 如果 charge < 150：回到 `idle`，继续充能，可以等第二次窗口
- 如果 charge >= 150：进入 `ready_closed`，联连窗口永久关闭，继续充能直到 200

在 `ready` 阶段和 `ready_closed` 阶段，充能都是从 0 开始继续累积的。如果玩家充能速度慢，可能在 100-200 之间停留较长时间。

**路径 B：节奏灵光 pending 超时重新出现**

`RhythmSkillSystem.enter()` 创建节奏灵光后进入 `pending`，玩家有 4000ms 时间点击激活。如果超时：

```javascript
// RhythmSkillSystem.js:458-469
if (Date.now() - state.pendingStartTime >= ACTIVATE_TIMEOUT_MS) {
    state.rhythmStar = null;
    state.phase = 'idle';
    state.pendingStartTime = 0;
    state.respawnTimer = Date.now() + RESPAWN_DELAY_MS;  // 4000ms
    state.shockwaveTime = 0;
    // 清除闪避
    if (playerEffects) {
        playerEffects.dodging = false;
        playerEffects.dodgeEndTime = 0;
        playerEffects._rhythmActive = false;
    }
}
```

**关键问题**：节奏灵光 pending 超时后，`RhythmSkillSystem` 回到 `idle`，但 `LinkChainSystem` 仍然处于 `rhythm_ready`。两个系统的状态机在此刻**脱钩**。

- `RhythmSkillSystem.isActive()` 返回 `false`（idle 阶段）
- `LinkChainSystem.phase` 仍是 `rhythm_ready`
- 等 4000ms respawnTimer 到期后，`RhythmSkillSystem.update()` 重新调用 `enter()`

**在此期间，`LinkChainSystem.addCharge()` 的封锁是有效的**（`rhythm_ready` 在封锁列表中），但能量条是否显示取决于 `showBar` 条件（见问题三）。

### 脉络

1. 充能到 200 → `enterRhythmReady()` → `RhythmSkillSystem.enter()` → pending
2. 玩家 4000ms 内未点击 → pending 超时 → `RhythmSkillSystem` 回到 idle，respawnTimer=4000ms
3. 4000ms 后自动重新 `enter()` → 重新进入 pending
4. 这样节奏灵光会以 4000ms 间隔反复出现，直到玩家点击或战斗结束

**结论**：pending 超时重试机制本身是合理的，但两个系统的状态机缺乏协调。`LinkChainSystem` 在 `rhythm_ready` 阶段没有感知到节奏灵光已消失，也没有任何超时保护。

## 问题三：节奏灵光快出来时能量条消失了，点击后节奏条又出现

### 根因

这是**三个问题叠加**的结果：

**a) `ready_closed` 阶段能量条不渲染**

```javascript
// LinkChainSystem.js render(): showBar 条件
var showBar = isUnlocked() && (
    state.phase === 'idle' ||
    state.phase === 'ready' ||
    state.phase === 'rhythm_ready'
);
```

`ready_closed` 阶段不在列表中。当联连窗口永久关闭后（第二次窗口超时），充能从 150 继续往 200 推，但能量条不显示。

**b) 节奏灵光 pending 超时后 `rhythm_ready` 阶段能量条仍在渲染**

`rhythm_ready` 在 showBar 中，所以能量条会渲染。但 `LinkChainSystem.render()` 中有这段：

```javascript
// 节奏阶段：不渲染联连相关内容（节奏灵光由 RhythmSkillSystem 渲染）
if (state.phase === 'rhythm_ready') return;
```

这个 return 在 showBar 渲染**之后**，所以能量条会正常渲染，但联连相关的灵光特效不会渲染——这是正确的。

**c) 用户描述的"能量条消失"对应的是 `ready_closed` 阶段**

时间线：
1. 第一次联连窗口（100）超时 → 回到 idle → 能量条显示
2. 第二次联连窗口（150）出现 → 玩家没点 → 2000ms 超时 → 进入 `ready_closed`
3. **`ready_closed` 阶段能量条不显示** → 这就是用户说的"能量条消失了"
4. 充能继续推进到 200 → `enterRhythmReady()` → `rhythm_ready` → 能量条重新显示
5. 节奏灵光出现（pending）→ 玩家点击 → 缩圈开始（active）→ 结算 settle()
6. settle() → `onComplete()` → `onRhythmSkillComplete()` → 消耗 200 → phase 回到 idle → 能量条继续显示

**d) 用户说"点击节奏灵光后节奏条又出现了"**

这里的"节奏条"实际上就是能量条。在 `rhythm_ready` 阶段能量条是显示的（因为 showBar 包含 `rhythm_ready`），但 pending 超时后：

- `RhythmSkillSystem.isActive()` 返回 false → `LinkChainSystem.addCharge()` 封锁**不再由 rhythmSkillSystem.isActive() 提供**（但 `rhythm_ready` 本身在封锁列表中）
- 如果此时玩家重新点击重新出现的节奏灵光，一切正常

**真正的问题场景**：用户看到的是 `ready_closed` 阶段的能量条消失，然后等到 200 时节奏灵光出现，但由于 pending 超时重试，节奏灵光出现后可能又消失，给用户造成"节奏灵光半天不出来，能量条又消失了"的体验。

## 优化方案

### 方案一：`ready_closed` 阶段显示能量条（最小改动）

**位置**：`LinkChainSystem.js` render() 的 showBar 条件

**改动**：将 `ready_closed` 加入 showBar 条件

```javascript
var showBar = isUnlocked() && (
    state.phase === 'idle' ||
    state.phase === 'ready' ||
    state.phase === 'ready_closed' ||  // 新增
    state.phase === 'rhythm_ready'
);
```

**效果**：联连窗口关闭后充能条继续显示，玩家能看到充能从 150 推进到 200 的过程，不会感觉能量条"凭空消失"。

**风险**：无。`ready_closed` 阶段没有任何其他 UI 元素与之冲突。

---

### 方案二：`ready_closed` 阶段渲染提示文字

**位置**：`LinkChainSystem.js` render()

**改动**：在 `ready_closed` 阶段渲染一行提示文字，告诉玩家节奏技即将到来

```javascript
if (state.phase === 'ready_closed') {
    var chargePercent = Math.floor(state.charge / RHYTHM_THRESHOLD * 100);
    ctx.font = 'bold ' + (12 * scale) + 'px sans-serif';
    ctx.fillStyle = '#00FFFF';
    ctx.textAlign = 'center';
    ctx.fillText('节奏充能中 ' + chargePercent + '%', screenW / 2, barY - 8 * scale);
}
```

**效果**：联连窗口关闭后，玩家看到充能条持续增长并伴随文字提示，对节奏技的到来有明确预期。

---

### 方案三：`ready_closed` 阶段充能条使用不同视觉效果

**位置**：`LinkChainSystem.js` render() 充能条渲染部分

**改动**：在 `ready_closed` 阶段，充能条使用纯青色 + 脉动效果，区别于 `ready` 阶段的"金+青双色"

```javascript
// 在 showBar 条件改为 true 后，color 选择逻辑中增加：
if (state.phase === 'ready_closed') {
    // 纯青色，节奏技方向推进中
    ctx.fillStyle = '#00FFFF';
    ctx.shadowBlur = 6 * scale;
    ctx.shadowColor = '#00FFFF';
    ctx.fillRect(barX, barY, barW * state.charge / RHYTHM_THRESHOLD, barH);
    // 脉动提示
    var pulse = 0.3 + 0.3 * Math.abs(Math.sin(Date.now() / 100));
    ctx.fillStyle = 'rgba(0, 255, 255, ' + pulse.toFixed(2) + ')';
    ctx.fillRect(barX - 2 * scale, barY - 2 * scale, barW * state.charge / RHYTHM_THRESHOLD + 4 * scale, barH + 4 * scale);
}
```

**效果**：颜色从"金+青"切换为"纯青"，给出清晰的视觉信号：联连阶段已结束，现在正向节奏技推进。

---

### 方案四：节奏灵光 pending 超时后 LinkChainSystem 同步感知

**位置**：`RhythmSkillSystem.js` update() pending 超时处理 + `LinkChainSystem.js`

**问题**：pending 超时后 RhythmSkillSystem 回到 idle，但 LinkChainSystem 仍在 `rhythm_ready`，两者状态脱钩。

**改动 A**：在 RhythmSkillSystem 的 pending 超时处理中，增加回调通知 LinkChainSystem

```javascript
// RhythmSkillSystem.js update() pending 超时
if (Date.now() - state.pendingStartTime >= ACTIVATE_TIMEOUT_MS) {
    state.rhythmStar = null;
    state.phase = 'idle';
    state.pendingStartTime = 0;
    state.respawnTimer = Date.now() + RESPAWN_DELAY_MS;
    // ... 清除闪避 ...
    if (typeof _onPendingTimeout === 'function') _onPendingTimeout();  // 新增回调
    return;
}
```

**改动 B**：在 LinkChainSystem 中增加 `_onPendingTimeout` 回调注入接口

```javascript
// LinkChainSystem.js
function _onRhythmPendingTimeout() {
    // 节奏灵光消失但未结算，保持 rhythm_ready 等待重试
    // 显示提示
    addMessage('节奏灵光即将重现...', '#00FFFF');
}
```

**改动 C**：在 game.js 初始化时注入回调

```javascript
rhythmSkillSystem._onPendingTimeout = function() {
    addGameMessage('节奏灵光即将重现...', '#00FFFF');
};
```

**效果**：状态机脱钩问题得到缓解，玩家看到提示知道节奏灵光会重新出现。

---

### 方案五（推荐）：`rhythm_ready` 阶段增加超时保护

**位置**：`LinkChainSystem.js` update()

**问题**：如果 RhythmSkillSystem 因某种原因一直无法完成（持续的 pending 超时重试循环），LinkChainSystem 永远卡在 `rhythm_ready`。

**改动**：在 `rhythm_ready` 阶段增加一个总超时（例如 30 秒），超时后强制结算

```javascript
// 在 state 中增加
state.rhythmReadyStartTime: 0,  // 新增

// 在 enterRhythmReady() 中设置
state.rhythmReadyStartTime = Date.now();

// 在 update() rhythm_ready 分支中
if (state.phase === 'rhythm_ready') {
    if (Date.now() - state.rhythmReadyStartTime >= 30000) {
        // 30秒超时，强制结束节奏技
        Logger.warn('[LinkChainSystem] rhythm_ready timeout, force complete');
        if (rhythmSkillSystem) rhythmSkillSystem.forceComplete();
        onRhythmSkillComplete();
        return;
    }
    if (rhythmSkillSystem) rhythmSkillSystem.update(dt);
    return;
}
```

**效果**：防止节奏技永久卡住，兜底保护。

## 推荐实施顺序

1. **方案一**（立即执行）：补上 `ready_closed` 显示能量条，成本最低，直接解决用户感知到的"能量条消失"问题
2. **方案二**（推荐）：在 `ready_closed` 阶段渲染提示文字，改善用户体验
3. **方案四**（建议）：增加 pending 超时回调，让两个系统的状态机保持协调
4. **方案五**（兜底）：增加 `rhythm_ready` 超时保护，防止极端情况

方案三可根据 UI 效果需求选择性实施。

## 异常场景复现路径

### 场景 1：能量条消失（ready_closed 阶段）

1. 充能到 100 → 触发灵光出现（第一次联连窗口）
2. 不点击触发灵光，等待 2000ms 超时 → 回到 idle（能量条显示）
3. 继续充能到 150 → 触发灵光再次出现（第二次联连窗口）
4. 不点击，等待 2000ms 超时 → 进入 `ready_closed`（**能量条消失** ← 异常）
5. 继续充能到 200 → 进入 `rhythm_ready`（能量条重新出现）

### 场景 2：节奏灵光反复出现但不被点击

1. 充能到 200 → 节奏灵光出现（pending）
2. 玩家 4000ms 内不点击 → pending 超时，节奏灵光消失
3. 4000ms 后自动重新出现（respawnTimer）
4. 循环 2-3，直到玩家点击或战斗结束

### 场景 3：节奏灵光 pending 超时期间能量条状态

1. 充能到 200 → `rhythm_ready` → 能量条显示（showBar 包含 `rhythm_ready`）
2. 节奏灵光 pending 超时 → RhythmSkillSystem 回到 idle
3. LinkChainSystem 仍在 `rhythm_ready` → 能量条继续显示（正确行为）
4. 4000ms 后节奏灵光重新出现 → 玩家点击 → 正常流程

场景 3 中能量条行为是正确的，问题只在场景 1 的 `ready_closed` 阶段。
