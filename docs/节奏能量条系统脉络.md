## 一、系统全貌

```
                  充能累积 (各种战斗操作)
                       │
                       ▼
  ┌──────────────────────────────────────────┐
  │           LinkChainSystem                │
  │         联连冲能条 (0→200)               │
  │                                          │
  │  0 ─────────── 100 ─────────── 200       │
  │     第一阶段:联连      第二阶段:节奏      │
  │     金色充能          金+青双色          │
  └──────┬──────────────────────┬────────────┘
         │                      │
    charge=100             charge=200
         │                      │
         ▼                      ▼
  触发灵光出现           RhythmSkillSystem
  (跳动+GC发光)           节奏缩圈灵光
  2000ms等待              (1000ms/圈)
         │                      │
    ┌────┴────┐           ┌─────┴─────┐
    ▼         ▼           ▼           ▼
  点击      不点击     Perfect/     Miss →
  进入联连   继续充能   Great       结算节奏技
                      计数+1
                      缩圈重置
```

系统由 **5 个核心模块** 组成：

| 模块 | 文件 | 职责 |
|------|------|------|
| 充能条+联连 | `LinkChainSystem.js` | 0→200双阶段充能、联连状态机 |
| 节奏技 | `RhythmSkillSystem.js` | 200满时缩圈玩法、结算 |
| 节拍判定 | `RhythmSystem.js` | 每个灵光的缩圈判定 (D5) |
| 体力条 | `SaturationState.js` | D2/D3共享资源，被节奏技恢复 |
| 手势协调 | `TouchGestureSystem.js` | D1-D4触摸分发 |

## 二、充能条数值

充能上限 **200**，通过以下行为累积：

| 行为 | 增量 |
|------|------|
| 蓄力吸收灵光 | +5 |
| 拖拽聚合灵光 | +5 |
| 蓄力轻蓄阶段 | +8 |
| 蓄力中蓄阶段 | +12 |
| 蓄力轻蓄释放 | +15 |
| 蓄力中蓄释放 | +25 |
| 蓄力满蓄释放 | +40 |
| 拖拽技释放 | +40 |
| 联连每划一颗 | +5 |

## 三、充能条生命周期

```
IDLE (0–99)
  │  蓄力/拖拽/联连判定的 addCharge() 被调用
  ▼
LINK_READY (charge=100)
  │  随机一颗灵光 → 触发灵光 (跳动+GC发光, 2000ms)
  ├─ 玩家点击 → 消耗100, 进入联连流程 (revealing→waiting→swiping→judging)
  └─ 玩家不碰 → 2000ms后触发灵光消失, 继续充能, 从100往上加
  ▼
RHYTHM_READY (charge=200)
  │  触发灵光清除 → RhythmSkillSystem.enter() 创建节奏灵光
  │  每次 Perfect/Great → 计数+1, 缩圈重置 (不限次数)
  │  Miss → settle() 结算, 根据成功次数查表
  │  结算后 → 充能归零
  ▼
COOLDOWN (8000ms)
  │  禁止充能
  ▼
IDLE
```

**关键互斥规则：**
- 联连进行中 (revealing/swiping/judging)：**不再充能**
- 节奏灵光在场时：**蓄力和拖拽不再充能**（防止重复触发）
- 灵光保护标记：`_rhythm` / `_linking` / `_charging` / `_dragging`，StarSystem 不会清理标记灵光

## 四、节奏技结算表

| 成功次数 | 技能名称 | 效果 |
|---------|---------|------|
| 1–2 | 节奏微震 | 单目标 ×2.0 伤害 |
| 3 | 节拍技 | 全屏 ×3.0 + 恢复15%体力 |
| 4 | 强化节拍技 | 全屏 ×4.5 + 恢复25%体力 + 破盾 |
| 5 | 完美节拍技 | 全屏 ×6.0 + 恢复35%体力 + 破盾 + 屏幕强震 |
| 6+ | 极限节拍技 | 全屏 ×8.0 + 恢复50%体力 + 破盾 + 屏幕强震 |

每次成功点击额外 +5 分，结算时按技能等级加分 (15/30/40/50/60)。

判定窗口：**Perfect ±50ms** / **Great ±150ms** / **>150ms = Miss**

## 五、模块间数据流向

```
                 NormalBattleAdapter (战斗入口)
                       │
              ┌────────┼────────┐
              ▼        ▼        ▼
       addLinkCharge  judgeTiming  (伤害/分数计算)
              │        │
              ▼        ▼
       LinkChainSystem  RhythmSystem (D5)
         (充能累积)       (节拍判定 → damageMult)
              │
         charge≥100 → 触发灵光
         charge≥200 → enterRhythmReady()
              │
              ▼
       RhythmSkillSystem
         enter() → 创建节奏灵光
         handleTouch() → 判定 Perfect/Great/Miss
         settle() → 查结算表, recover() 体力, onComplete()
              │
         onComplete → LinkChainSystem 重置+冷却
```

**依赖注入关系：**

```
game.js 初始化顺序:
  rhythmSystem → ... → linkChainSystem → rhythmSkillSystem
  ↓ 后注入
  linkChainSystem._injectRhythmSkillSystem(rhythmSkillSystem)

touchGestureSystem 注入:
  依赖 linkChainSystem + rhythmSystem + chargeSystem + dragSystem
```

## 六、触摸优先级 (game.js 主循环)

```
1. rhythmSkillSystem.handleTouch(touch)
   → 节奏灵光在场时消费所有触摸
2. linkChainSystem.handleTriggerTouch(touch)
   → 触发灵光在场时判断是否命中
3. touchGestureSystem.handleGestureStart()
   → 通用手势 (D1击打/D2拖拽/D3蓄力/D4联连滑动)
```
