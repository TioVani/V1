# 被怪物攻击扣时间机制分析与优化方案

## 一、现状总览

| 模式 | 攻击路径 | 扣时间实现 | 动画显示 | 问题 |
|---|---|---|---|---|
| 普通 `PLAYING` | `NormalBattleAdapter.monsterAttackPlayer` | `timeDamage=0`（硬编码） | `-0s` | 冗余动画 |
| 赛季 `SEASON_PLAYING` | 同上 | 同上 | `-0s` | 冗余动画 |
| 闯关 `STAGE_PLAYING` | 同上 | 同上 | `-0s` | 冗余动画 |
| 无尽之塔 `TOWER_COMBAT` | `TowerSystem.monsterAttackPlayer` | `combatTime -= 5`（硬编码） | `-5s` | 扣了局部变量，但每帧又被 BattleEngine 覆写 |
| Boss `BOSS_BATTLE` | `BattleEngine.updateAttackers` | `timeLeft -= 8`（配置） | `-8s` | 正常 |

## 三、根因分析

### 问题1：普通/赛季/闯关模式显示 `-0s`

**因果链**：

1. 产品"被攻击不再减少时间" → `NormalBattleAdapter.js:1573` 设置 `timeDamage = 0`
2. 但漏掉了同级动画调用 → 第 1644 行仍执行 `createTimeDamageAnimation(0)`
3. 动画系统拿到 `timeLoss=0` → 渲染 `-0s`

**根因**：扣时间逻辑被关闭，但动画未被一同关闭。两段代码紧耦合但只有一半被修改。

### 问题2：无尽之塔显示 `-5s` 但实际没扣时间

**因果链**：

1. `TowerSystem.monsterAttackPlayer`：`combatTime -= 5`（Line 1125）
2. TowerSystem 的 `updateCombatTick` 每帧执行 `battleEngine.update()` 然后 `combatTime = st.timeLeft`（Line 1328）
3. BattleEngine 内部 `timeLeft` 没有被 TowerSystem 的 `combatTime` 反向同步
4. 所以：扣了 `combatTime` → 下一帧被 `st.timeLeft` 覆盖回来 → 扣减丢失

**根因**：TowerSystem 的两套时间源单向同步——只从 BattleEngine → TowerSystem，没有反向同步。`combatTime` 的局部修改被下一帧的同步操作覆盖。

### 问题3：Boss模式正常

单一时钟源 `BattleEngine.timeLeft`，扣时间逻辑和倒计时共用同一变量。攻击路径、时间源、动画都在 BattleEngine 内部闭环。

## 四、架构矛盾总结

```
                    当前：三套攻击路径 + 三种时间源，彼此无协作

NormalBattleAdapter           TowerSystem                BattleEngine (Boss路径)
      │                           │                           │
  timeDamage=0               combatTime -= 5             timeLeft -= 8
  setTimeLeft(-0)            createTimeDamage(-5)        createTimeDamage(-8)
  createTimeDamage(-0)        │                           │
      │                   下一帧 combatTime=st.timeLeft    │
      │                   5秒丢失 ◄───────────────────────┘
      │
  冗余 -0s
```

## 五、优化方案

### 5.1 设计目标

1. **单一职责**：每个模式下只有**一条**攻击路径 + **一个**时间源
2. **配置驱动**：是否扣时间、扣多少，统一从模式配置读取
3. **动画与逻辑解耦**：动画的"是否显示"与扣时间的"是否执行"由同一开关控制
4. **可扩展**：新增模式只需增加配置条目，不动代码

### 5.2 方案：攻击路径收敛 + 时间源统一

**思路**：让 BattleEngine 成为**所有模式**怪物攻击的唯一执行路径，各适配器不再独立实现 `monsterAttackPlayer`，只负责：
- 配置注入（`combatOverrides` 包含 `timeDamageOnHit`）
- 生命周期管理（init / destroy）
- 适配层回调（`onMonsterDeath`、`onPlayerDeath` 等）

#### 5.2.1 新增配置结构

在 `CombatSpec.js` 中，每种模式通过 `combatOverrides` 明确表达扣时间策略：

```javascript
// CombatSpec.js — 按模式的 combatOverrides

const MODE_COMBAT_OVERRIDES = {
    normal: {
        TIME_DAMAGE_ON_HIT_S: 0,        // 0 表示不扣时间
    },
    season: {
        TIME_DAMAGE_ON_HIT_S: 0,
    },
    stage: {
        TIME_DAMAGE_ON_HIT_S: 0,
    },
    tower: {
        TIME_DAMAGE_ON_HIT_S: 0,        // 无尽之塔不扣时间（与普通模式统一）
    },
    boss: {
        TIME_DAMAGE_ON_HIT_S: 8,        // Boss 保留扣时间
    },
};
```

`TIME_DAMAGE_ON_HIT_S: 0` 即为**统一的"不扣时间"信号**——不需要额外加 `TIME_DAMAGE_ENABLED` 字段，`0` 本身就是语义最清晰的"关闭"表达。

#### 5.2.2 修改点

| 序号 | 文件 | 修改内容 |
|---|---|---|
| 1 | `CombatSpec.js` | 新增 `MODE_COMBAT_OVERRIDES`，各模式配置 `TIME_DAMAGE_ON_HIT_S` |
| 2 | `BattleEngine.js:481` | 增加守卫：`if (S.timeDamageOnHit <= 0) return;` — 使 BattleEngine 内部的扣时间和动画一并跳过 |
| 3 | `NormalBattleAdapter.js:1573` | 删除硬编码 `timeDamage = 0`，不再自行管理扣时间（该函数后续可整体废弃，见步骤4） |
| 4 | `NormalBattleAdapter.js:1716-1725` | 删除 `monsterAttackPlayer` 方法和其定时器调用。普通/赛季/闯关改为由 BattleEngine 的 `updateAttackers` 接管攻击，`skipAutoTimers` 改为 `false` |
| 5 | `NormalBattleAdapter.js:868` | `skipAutoTimers: true` → `false`，让 BattleEngine 注册怪物为攻击者 |
| 6 | `TowerSystem.js:1123-1127` | 删除硬编码 `timeDamage=5` 和 `combatTime -= timeDamage`。Tower 攻击由 BattleEngine 的 `updateAttackers` 接管 |
| 7 | `TowerSystem.js:1020-1022` | 倒计时逻辑保留，但改为从 `st.timeLeft` 读取而非本地递减（或直接删除本地倒计时，完全依赖 BattleEngine 的 `onTimeUp` 回调） |
| 8 | `BossBattleAdapter.js:635` | 无需修改（已在使用 `combatOverrides`） |

#### 5.2.3 修改后的数据流

```
                    统一后：BattleEngine 为唯一攻击路径

game.js 主循环
│
├─ NormalBattleAdapter (普通/赛季/闯关)
│   └── BattleEngine.init({ combatOverrides: { TIME_DAMAGE_ON_HIT_S: 0 } })
│       └── update() → updateAttackers()
│           └── handleProjectileHit()
│               ├─ timeDamageOnHit = 0 → 守卫跳过，不扣也不显示动画
│               └─ 仅扣 HP + 护盾吸收 + 中毒/眩晕
│
├─ TowerSystem
│   └── BattleEngine.init({ combatOverrides: { TIME_DAMAGE_ON_HIT_S: 0 } })
│       └── update() → updateAttackers()  [接管怪物攻击]
│           └── handleProjectileHit()
│               ├─ timeDamageOnHit = 0 → 守卫跳过
│               └─ HP + 护盾 + 中毒
│       └── 倒计时由 BattleEngine 的 onTimeUp 或 Tower 继续管理
│
└─ BossBattleAdapter
    └── BattleEngine.init({ combatOverrides: { TIME_DAMAGE_ON_HIT_S: 8 } })
        └── update() → updateAttackers()
            └── handleProjectileHit()
                ├─ timeLeft -= 8  → 扣时间
                └─ createTimeDamage(8)  → 显示 -8s
```

#### 5.2.4 BattleEngine 单点修改（关键守卫）

`BattleEngine.js` 第 481 行，在扣时间之前增加守卫：

```javascript
// 修改前：
if (damage > 0) {
    S.timeLeft = Math.max(0, S.timeLeft - S.timeDamageOnHit);
    anim.createPlayerDamage(damage, false);
    anim.createTimeDamage(S.timeDamageOnHit);       // 0 也会触发 -0s
    ...
}

// 修改后：
if (damage > 0) {
    if (S.timeDamageOnHit > 0) {
        S.timeLeft = Math.max(0, S.timeLeft - S.timeDamageOnHit);
        anim.createTimeDamage(S.timeDamageOnHit);
    }
    anim.createPlayerDamage(damage, false);
    ...
}
```

这一处修改即可：
- `timeDamageOnHit = 0` → 不扣时间、不显示动画
- `timeDamageOnHit = 8` → 扣 8 秒、显示 -8s（Boss 模式）
- 未来任何新模式，只需在 `combatOverrides` 中设值

#### 5.2.5 兼容处理

对于 `TowerSystem` 的隐藏之路守卫（`isHiddenPathBoss=true`，不走 BattleEngine），保留其独立的扣时间逻辑，从配置读取而非硬编码：

```javascript
// TowerSystem.monsterAttackPlayer 内，damage > 0 分支
if (damage > 0) {
    var timeDamage = (getCombatOverrides && getCombatOverrides().TIME_DAMAGE_ON_HIT_S) || 0;
    if (timeDamage > 0) {
        combatTime = Math.max(0, combatTime - timeDamage);
        createTimeDamageAnimation(timeDamage);
    }
    ...
}
```

### 5.3 扩展性

此方案下，未来新增模式（如"限时挑战"、"竞速赛"）只需：

1. 在 `CombatSpec.js` 的 `MODE_COMBAT_OVERRIDES` 中增加一条配置
2. 创建适配器，注入 `combatOverrides` 给 BattleEngine
3. 攻击逻辑和动画由 BattleEngine 统一处理

无需在适配器中自行实现 `monsterAttackPlayer` 或管理扣时间。

### 5.4 预期效果

| 模式 | 修改前 | 修改后 |
|---|---|---|
| 普通/赛季/闯关 | 显示 `-0s` 浮字 | 不扣时间，无动画 |
| 无尽之塔 | 显示 `-5s`，扣减被覆盖 | 不扣时间，无动画 |
| Boss模式 | 显示 `-8s`，正常扣时间 | 保持不变 |
| 隐藏之路守卫 | 扣 `-5s`（硬编码，生效） | 从配置读取，可扩展 |

## 六、实施优先级

| 步骤 | 内容 | 影响范围 | 风险 |
|---|---|---|---|
| **P0** | BattleEngine 单点守卫修改 | 一处改，全模式生效 | 极低 |
| **P0** | CombatSpec 新增 `MODE_COMBAT_OVERRIDES` | 纯配置新增 | 无 |
| **P1** | NormalBattleAdapter 废弃自行攻击，改由 BE 接管 | 普通/赛季/闯关 | 中（攻击频率、弹幕动画需验证） |
| **P1** | TowerSystem 废弃自行攻击，改由 BE 接管 | 无尽之塔 | 中（需验证与隐藏之路的兼容） |
| **P2** | 清理 NormalBattleAdapter 和 TowerSystem 中的残余扣时间代码 | 代码清理 | 低 |

**建议分批实施**：P0 先上线解决 `-0s` 和无尽之塔 `-5s` 的显示问题；P1 解决架构碎化问题，P2 做清理。
