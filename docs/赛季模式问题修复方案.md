# 赛季模式问题分析与修复方案

## 问题一：玩家退出后游戏仍在后台运转

### 根因分析

赛季模式的定时器（倒计时、灵光生成、怪物攻击、宠物攻击）使用的是 `game.js` 中的全局单例变量：

| 变量 | L55-59 |
|------|--------|
| `timerInterval` | 倒计时定时器 |
| `moveInterval` | 灵光生成定时器 |
| `monsterAttackInterval` | 怪物攻击定时器 |
| 宠物攻击定时器 | PetSystem 内部 |

**退出路径一：暂停 → 返回菜单**

```
game.js L4410-4415: modeLifecycle.cleanupMode('season') → endSeasonGame() → 清理定时器 ✓
```

**退出路径二：倒计时结束 → GAMEOVER → 返回菜单**

```
GameLifecycleSystem.js L398-410: endSeasonGame() → 清理定时器 ✓
game.js   L5333-5336: transitionTo(WORLDMAP) → 定时器已在 endSeasonGame 中清理 ✓
```

**退出路径三：切微信后台（`onHide`）**

```
game.js L3541-3543: 只调用了 dataStore.flush()，没有暂停定时器 ✗
```

玩家切后台后，`setInterval` 在微信环境中可能继续执行（取决于微信版本和平台策略）。这意味着：
- 倒计时继续走，直到减到0 → 自动触发 `endSeasonGame()`
- 灵光持续生成、怪物持续攻击玩家
- 玩家切回来时发现游戏已经输了，但没有任何提示

**退出路径四：直接从战斗中关闭小游戏（微信 onUnload）**

无任何生命周期钩子，定时器自然终止（进程被销毁）。

### 结论

**路径三是核心问题**。玩家切后台后，赛季战斗的四个定时器继续运转，且 `onHide` 没有调用暂停逻辑。

### 修复方案

在 `onHide` 回调中增加对活跃战斗模式的暂停处理：

```javascript
// game.js L3541-3543 修改为：
$P.onHide(function() {
    _log('游戏隐藏 - 保存数据并暂停战斗');
    dataStore.flush();
    // 如果当前处于战斗状态，自动暂停
    if (state === GAME_STATE.SEASON_PLAYING ||
        state === GAME_STATE.PLAYING ||
        state === GAME_STATE.STAGE_PLAYING ||
        state === GAME_STATE.BOSS_BATTLE ||
        state === GAME_STATE.TOWER_COMBAT) {
        previousState = state;
        PauseCoordinator.instance.pause();
        stateMachine.transitionTo(GAME_STATE.PAUSED);
    }
});
```

同时在 `onShow` 中恢复暂停状态（可选，用户体验更好）：

```javascript
$P.onShow(function() {
    _log('游戏显示');
    // 如果处于暂停状态，不做额外操作（让玩家手动继续）
});
```

## 问题二：赛季模式闪白屏

### 根因分析

整个渲染管线没有 `ctx.clearRect()` 清屏，所有界面依赖"全屏绘制覆盖"来隐式清屏。

**关键渲染路由**（`game.js` L5612-5623）：

| 状态 | 渲染函数 |
|------|----------|
| `SEASON_MENU` | `renderSeasonMenu()` |
| `SEASON_SELECT` | `renderSeasonSelect()` |
| `SEASON_PLAYING` | `renderGame()` (同普通战斗) |

**闪白屏的产生链路：**

1. **SEASON_SELECT → SEASON_PLAYING 过渡**：
   - `startSeasonGame()` 被调用（`game.js` L5207）
   - `startSeasonGame` 中 `setGameState(SEASON_PLAYING)`（`GameLifecycleSystem.js` L326）
   - 下一帧 `render()` 分发到 `renderGame()`，但战斗场景渲染可能在前几帧还没准备好（`normalBattleAdapter` 初始化需要时间）
   - `renderGame()` 内部的 `GameBattleRenderer` 在首次绘制时若 `bgImage` 未就绪，只画了纯色 `#1a1a2e`（`GameBattleRenderer.js` L463）
   - SEASON_SELECT 绘制了深色卡片和文字，而战斗场景第一帧只有纯色背景 → **过渡中间帧显示为空白（白/灰色）**

2. **战斗结束 → GAMEOVER**：
   - `endSeasonGame()` 设置 `GAMEOVER` → `renderGameOver()` 
   - `renderGameOver()` 用 `bgPositionCache` 绘制背景（`MenuRenderer.js` L839-841）
   - 如果 `bgPositionCache` 不存在（从未进入过大地图菜单），走 else 分支画纯色 `rgba(30,10,10,0.95)`（L847-849）
   - **但战斗背景 `fightBgPositionCache` 和大地图背景 `bgPositionCache` 是不同的比例**，切换时可能出现短暂残留

3. **屏幕震动叠加**（见问题三）：
   - 赛季战斗中的 `createScreenShake` 通过 `ctx.translate()` 影响全局渲染坐标系
   - 震动期间切换状态，新状态页面的所有元素也被震动偏移
   - 如果震动恰好在状态切换时处于高偏移量，整个画面会"闪白"（实际上是被大幅偏移后画到了屏幕外的区域，可见区域刚好是空白/背景色）

### 结论

根本原因是 **无 `clearRect` + 多状态渲染复用同一画布 + 震动全局坐标系污染**。

### 修复方案

**方案A（最小改动）**：在 `render()` 入口处增加清屏，确保每帧从纯净画布开始：

```javascript
// game.js render() 函数开头，在所有渲染之前
function render() {
    // ... 现有变量计算 ...
    ctx.clearRect(0, 0, screenWidth, screenHeight);  // 新增
    // ... 后续渲染 ...
}
```

**注意**：`clearRect` 必须在 `ctx.save()/translate()` 震动偏移之前调用，否则清屏区域也是偏移后的。

**方案B（根本解决）**：为每个战斗模式使用独立的离屏 Canvas，避免交叉污染。改动较大，建议先实施方案A。

## 问题三：闪白屏后背景舞台偏移

### 根因分析

屏幕震动系统（`AnimationSystem.js` L2188-2221）通过全局 `ctx.translate()` 实现：

```
game.js 主渲染循环 L5560-5739:
┌─────────────────────────────────────────┐
│ updateScreenShake()                      │
│ shakeOffset = { offsetX, offsetY }       │
│ if (offset != 0) { ctx.save();           │
│   ctx.translate(offsetX, offsetY); }     │  ← 全局坐标系被偏移
│ try {                                    │
│   渲染分发表 (WORLDMAP/MENU/BATTLE...)   │  ← 所有渲染都受偏移影响
│ } catch { }                              │
│ if (offset != 0) { ctx.restore(); }      │
└─────────────────────────────────────────┘
```

**震动触发源**（赛季战斗中的伤害计算）：

| 触发点 | 强度 |
|--------|------|
| `BattleEngine.js` 暴击 | `createScreenShake(3)` |
| `BattleEngine.js` 击杀 | `createScreenShake(1)` |
| `LinkChainSystem.js` 连链 | `createScreenShake(8)` |
| `ChargeSystem.js` 蓄力释放 | `createScreenShake(4-8)` |
| `RhythmSkillSystem.js` 节奏技 | `createScreenShake(skill.shake)` |

**震动参数**：`duration = 150ms`，`intensity × decay`（每帧衰减）。

**偏移产生的链路：**

1. 赛季战斗中某事件触发 `createScreenShake(8)` → `screenShakeState.active = true`
2. 下一帧 `updateScreenShake()` 计算出随机 offset（可能多帧连续有非零偏移）
3. 震动期间玩家点击暂停 → 返回菜单
4. 下一帧渲染状态变为 WORLDMAP，但 `screenShakeState` 仍然 `active=true`
5. WORLDMAP 的 `renderWorldMap()` 在 `ctx.translate(shakeX, shakeY)` 的坐标系下绘制
6. WorldMap 使用相机偏移 `_camX/_camY` 定位，震动偏移叠加上去 → **整个地图/背景视觉偏移**

**为什么偏移是"闪白屏后"出现：**

震动导致画面抖动离开屏幕原点区域，如果 WorldMap 背景图还未加载完成（`bgImg.complete === false`），画布上只有网格线和实体被偏移，其他区域空白 → 表现为"闪白屏 + 偏移"。

震动结束后（150ms 后 `screenShakeState.active = false`），`offsetX/Y` 变为 0，后续帧恢复正常。但震动期间的非零偏移已经给玩家造成了"背景舞台偏移"的印象。

### 修复方案

**方案A（最小改动）**：非战斗状态禁止屏幕震动生效：

```javascript
// game.js L5560-5565 修改为：
updateScreenShake();
var shakeOffset = getScreenShakeOffset();
var isCombatState = state === GAME_STATE.PLAYING || state === GAME_STATE.PAUSED ||
    state === GAME_STATE.SEASON_PLAYING || state === GAME_STATE.STAGE_PLAYING ||
    state === GAME_STATE.BOSS_BATTLE || state === GAME_STATE.TOWER_COMBAT;
    
if (isCombatState && (shakeOffset.offsetX !== 0 || shakeOffset.offsetY !== 0)) {
    ctx.save();
    ctx.translate(shakeOffset.offsetX, shakeOffset.offsetY);
}
// ... 渲染 ...
if (isCombatState && (shakeOffset.offsetX !== 0 || shakeOffset.offsetY !== 0)) {
    ctx.restore();
}
```

**方案B（彻底解决）**：状态切换时强制清除震动状态：

```javascript
// 在 stateMachine 的 setGameStateRaw 中增加：
if (prevState 是战斗状态 && newState 不是战斗状态) {
    animationSystem.clearScreenShake();  // 需要新增此API
}
```

## 数据流总结

```
玩家进入赛季:
  WORLDMAP → SEASON_MENU → SEASON_SELECT → SEASON_PLAYING
                                              │
                           ┌──────────────────┤
                           │                  │
                      倒计时归零          暂停→返回菜单
                           │                  │
                      endSeasonGame()    cleanupMode('season')
                           │                  │
                      clearTimer()        endSeasonGame()
                      clearMove()         (同上)
                      clearAttack()
                      stopPetTimer()
                           │                  │
                       GAMEOVER              │
                           │                  │
                      返回菜单按钮            │
                      transitionTo(WORLDMAP)  │
                      (定时器已清理 ✓)        │
                                              │
                                     transitionTo(WORLDMAP)
                                     (定时器已清理 ✓)

玩家切后台:
  onHide → 仅 dataStore.flush() → 定时器继续运行 ✗
```

**核心矛盾**：定时器是全局单例，但清理只发生在显式的游戏结束流程中。`onHide` 缺少"暂停战斗"的感知，切后台 = 放任定时器继续。

## 附加发现：season handler 的 resume 回调有隐患（与本次修复无直接冲突）

`modeLifecycle.registerMode('season', ...)` 中 `resume` 回调指向 `resumeNormalTimers()`（`game.js` L3442），该函数会将游戏状态设为 `GAME_STATE.PLAYING` 而非 `SEASON_PLAYING`。

当前文档中的修复方案没有触发此路径（`onShow` 不做自动 resume，让玩家手动点继续按钮——走的是 `startSeasonGame()` 重新进入）。但若未来在 `onShow` 中增加自动恢复逻辑，需要先将 season 的 resume handler 修正为独立实现（例如 `resumeSeasonTimers()`，保持 `SEASON_PLAYING` 状态、60秒倒计时和赛季计分逻辑）。
