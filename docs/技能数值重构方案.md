## 一、现状诊断

### 1.1 代码层 vs 配置层的断裂

**代码层已有百分比化逻辑**，但配置层仍滞留固定值：

| 位置 | 状态 |
|------|------|
| `SkillConfig.js` — `damage` 字段 | **固定值**（40-1500），来自 Excel 导出，是冗余旧数据 |
| `SkillConfig.js` — `getSkillAttackRatio(rarity)` | **已定义 8 级映射**（UC:0.4 → LR:15.0），函数存在但无消费者 |
| `BattleEngine.js:1072` — `useSkill()` | **已使用** `getSkillAttackRatio(skill.rarity)` 实现 `stats.attack × ratio × (1+combo×0.05)` |
| `SkillSystem.js:91` — `useSkill()` | **已使用** `getSkillAttackRatio(skill.rarity)` 实现 `stats.attack × ratio` |
| `TowerSystem.js:1243` — `useSkillInCombat()` | **已使用** `getSkillAttackRatio(skill.rarity)` 降级逻辑中也用了 |

**结论**：三个消费点都已迁移到百分比公式。`SkillConfig.js` 中的 `damage` 固定值字段是**死代码**，只在新旧代码降级路径中存在理论意义。

### 1.2 当前伤害公式（代码实际行为）

```
attackRatio = getSkillAttackRatio(skill.rarity)    // 稀有度 → 倍率
baseAtk     = stats.attack                          // 角色当前攻击力（含装备+被动+升星）
comboMult   = 1 + comboCount × 0.05                 // 连击加成（BattleEngine中）
critMult    = stats.critDamage（若判定成功）         // 暴击加成

skillDamage = floor(baseAtk × attackRatio × comboMult × critMult)
```

### 1.3 但辅助技能仍是固定值（未改造）

| 技能效果 | 当前公式 | 问题 |
|---------|---------|------|
| **damage** | `baseAtk × ratio` | 已完成 |
| **heal** | `skill.heal`（固定值） | Lv.90 角色 HP 3000 时，R 级"愈灵光"治疗 50 点 = 1.7%，无存在感 |
| **shield** | `skill.shield`（固定值） | Lv.90 角色 HP 3000 时，R 级"守灵光"护盾 30 点 = 1.0%，形同虚设 |
| **buff** | `skill.attack/critRate`（固定值） | R 级"文昌灵光"攻击+30，Lv.90 UR 已有 1188 攻击力时加 2.5%，无感知 |
| **debuff** | 无实现 | 暂无，留空 |

## 三、辅助技能百分比化方案

### 3.1 治疗技能

**当前**：固定值（20/50/100），在后期完全无意义。

**方案**：改为 `player.maxHp × healRatio`，保留最小值保底。

```javascript
// healRatio 按稀有度分级
healRatioMap = {
    UC: 0.05,   // 5% 最大生命
    R:  0.10,   // 10%
    SR: 0.15,   // 15%
    SSR:0.25,   // 25%
    UR: 0.40,   // 40%
    LR: 0.60,   // 60%
    SP: 0.30    // 30%
};

// 实际治疗量
healAmount = max(healMin, floor(player.maxHp × healRatio));
healMin = { UC: 10, R: 20, SR: 40, SSR: 80, UR: 150, LR: 250, SP: 100 };
```

**效果对比**：

| 技能 | 稀有度 | 旧治疗(Lv.90UR, HP3000) | 新治疗(HP3000) | 占HP% |
|------|--------|------------------------|---------------|-------|
| 微愈灵光 | UC | 20 | max(10, 3000×0.05)=**150** | 5% |
| 愈灵光 | R | 50 | max(20, 3000×0.10)=**300** | 10% |
| 大愈灵光 | SR | 100 | max(40, 3000×0.15)=**450** | 15% |
| 灵核归位(复活) | SSR | 50%HP（已有百分比） | 不变 | 50% |

**减法设计**：治疗不应完全替代技巧，5%-25% 的范围让一次治疗最多抵消 1-2 次怪物攻击（怪物单次攻击约 40-100），刚好缓解压力但不会让战斗变成"无限回血"。

### 3.2 护盾技能

**当前**：固定值（30/60/100），同治疗一样在后期无意义。

**方案**：改为 `player.maxHp × shieldRatio`。

```javascript
shieldRatioMap = {

    SR: 0.15,   // 15%
    SSR:0.25,   // 25%
    UR: 0.40,   // 40%

```

**效果对比**：

| 技能 | 稀有度 | 旧护盾(Lv.90UR, HP3000) | 新护盾(HP3000) | 可抗几击(每次~70) |
|------|--------|------------------------|---------------|-----------------|
| 守灵光 | R | 30 | max(15, 3000×0.08)=**240** | ~3.4 次 |
| 青铜灵光·坚壁 | SR | 60 | max(30, 3000×0.15)=**450** | ~6.4 次 |
| 玉蝉灵光·羽化 | SSR | 100 | max(60, 3000×0.25)=**750** | ~10.7 次 |
| 灵域屏障 | UR | 0(+免疫) | max(100, 3000×0.40)=**1200** | ~17 次 |
| 灵脉奇点 | LR | 0(+吸收) | max(200, 3000×0.60)=**1800** | ~25 次 |

### 3.3 Buff 技能（临时属性提升）

**当前**：固定值攻击+30/50/80/100，在后期加成比例太低。

**方案**：改为百分比加成 + 固定基准的组合。让低稀有度 Buff 对新手有用，高稀有度 Buff 对满级玩家同样有价值。

```javascript
// buff 双通道：固定基础 + 百分比加成
buffAttack = baseAttack + floor(stats.attack × attackRatio)
buffCritRate = baseCrit + critRateBonus          // 暴击率直接加百分比点
buffCritDamage = baseCritDmg + critDmgBonus     // 暴击伤害加法叠加
```

| 技能 | 稀有度 | 旧Buff | 新Buff(Lv.90UR) | 设计意图 |
|------|--------|--------|-----------------|---------|
| 文昌灵光·开运 | R | 攻击+30, 暴率+10 | 攻击+50(固定)+**攻击×0.05**(=109), 暴率+10 | 新手有用(186→109%提升)，老手有体感(~9%提升) |
| 万灵共鸣 | SSR | 攻击+50, 暴率+20, 暴伤+0.3 | 攻击+100+**攻击×0.10**(=219), 暴率+20, 暴伤+0.3 | 全面提升，约18%攻击增幅 |
| 全灵共鸣 | UR | 攻击+100, 暴率+25, 暴伤+0.5 | 攻击+150+**攻击×0.15**(=328), 暴率+25, 暴伤+0.5 | UR级别的显著提升 |

## 四、冷却时间重新标定

### 4.1 冷却与伤害的匹配原则

技能冷却应与一星伤害的期望产出形成等价。一星伤害在 Combo 10（常态）下约为 `一星基础 × 1.5`。

以 **Lv.90 UR（攻击 1188）** 为基准，一星伤害（Combo 10）= 31.9 × 1.5 = **~48**。

| 技能 | attackRatio | 期望伤害(Combo10) | 等效星数 | 合理冷却 | 当前冷却 | 差距 |
|------|------------|------------------|---------|---------|---------|------|
| 微灵光(UC) | 0.4 | ~475 | **10颗** | 15-20s | 20s | **合理** |
| 火灵光·迸发(R) | 1.0 | ~1,188 | **25颗** | 25-35s | 30s | **合理** |
| 灵光爆发(SSR) | 4.0 | ~4,752 | **99颗** | 60-90s | 60s | **偏短？** |
| 灵光洪流(UR) | 10.0 | ~11,880 | **248颗** | 90-120s | 90s | **偏短** |
| 归一灵光(UR) | 10.0 | ~11,880 | **248颗** | 100-150s | 100s | **偏短** |
| 源灵回响(LR) | 15.0 | ~17,820 | **371颗** | 120-180s | 120s | **偏短** |

> 注：等效星数 = 期望伤害 ÷ 一星伤害(48)。30 秒战斗中约 50 颗有效攻击星。

**分析**：SSR 及以上技能等效 99-371 颗星，在 30 秒常规模战斗中**只能使用 1 次**。这是正确的——高稀有度技能应该是一种"大招"体验。但如果让玩家在一局内用 2 次 99+ 等效星的技能，会导致战斗节奏从"技巧型"变为"技能循环型"，偏离灵光点击的核心玩法。

### 4.2 冷却优化建议

**保持 SSR+ 长冷却，但加入"冷却缩减"被动技能作为养成维度**。

| 调整项 | 当前 | 建议 | 理由 |
|--------|------|------|------|
| 微灵光(UC) | 20s | 15s | 新手阶段的技能应该频繁可用，建立使用习惯 |
| 灵光爆发(SSR) | 60s | 70s | SSR 技能在 30 秒战斗中最多 1 次，70s 不影响常规战斗但拉开冷却梯度 |
| 灵光洪流(UR) | 90s | 120s | UR 技能应确保在常规战斗中最多 1 次，Tower/Boss 战中可能 2 次 |
| 归一灵光(UR) | 100s | 130s | 同上 |
| 源灵回响(LR) | 120s | 180s | LR 技能的终极感——大多数战斗中只能用 1 次 |
| 新增：冷却缩减被动 | 无 | SSR被动, 叠满-20%冷却 | 成为有价值的养成目标 |

## 五、技能升级/升星对伤害的影响

### 5.1 当前技能升级系统

```
技能满级：10 级
经验公式：100 + level × 50
升级灵币消耗：floor(40 × level × 0.5)
statGrowth.damage: 5/级（固定值增长）
满星：3 星，倍率 ×2.0
```

**问题**：`statGrowth.damage: 5/级` 在固定值时代有意义，在百分比化后应改为对 `attackRatio` 或独立倍率的提升。

### 5.2 升级方案

**改 `statGrowth` 从 `{ damage: 5 }` 为 `{ attackRatioBonus: 0.05 }`**：

```
升级后 attackRatio = 基础ratio + level × 0.05
满级(Lv.10) attackRatio = 基础ratio + 0.5
```

| 技能 | 基础ratio | Lv.1 ratio | Lv.10 ratio | Lv.90 UR 伤害 | 增幅 |
|------|----------|-----------|------------|-------------|------|
| 微灵光(UC) | 0.4 | 0.4 | **0.9** | 475→1,069 | +125% |
| 灵光爆发(SSR) | 4.0 | 4.0 | **4.5** | 4,752→5,346 | +12.5% |
| 归一灵光(UR) | 10.0 | 10.0 | **10.5** | 11,880→12,474 | +5% |

**乘法设计**：低稀有度技能升级收益更大（+125%），高稀有度技能升级收益递减（+5%）。这鼓励玩家也养成低稀有度技能，而非只盯 SSR+。

### 5.3 升星方案

**升星倍率 `starMultiplier: [1.0, 1.2, 1.5, 2.0]` 作用于最终 skillDamage**：

| 升星 | 倍率 | Lv.10 UC 伤害 | Lv.10 UR 伤害 |
|------|------|-------------|-------------|
| ★0 | ×1.0 | 1,069 | 12,474 |
| ★1 | ×1.2 | 1,283 | 14,969 |
| ★2 | ×1.5 | 1,604 | 18,711 |
| ★3 | ×2.0 | 2,138 | 24,948 |

## 六、技能伤害在四个模式中的表现对比

### 6.1 普通模式（30 秒）

Lv.90 UR（攻击 1188），Combo 10 为常态：

| 技能 | 伤害 | 占30秒总输出(44250) | 冷却 | 可放次数 | 占总输出% |
|------|------|-------------------|------|---------|----------|
| 微灵光(UC) | 713(Combo10) | 1.6% | 20s | 1-2次 | 1.6-3.2% |
| 灵光爆发(SSR) | 7,128 | 16.1% | 60s | 0-1次 | 0-16% |
| 归一灵光(UR) | 17,820 | 40.3% | 100s | 0-1次 | 0-40% |

**设计意图**：
- 低稀有度技能是"顺手用的"，不会大幅改变战斗结果
- 高稀有度技能是"底牌"，一次释放可能扭转战局
- UR 技能在 30 秒战斗中如果能在第 1 秒释放，最多贡献 40% 伤害（合理，不让技能替代点击）

### 6.2 Boss 战（60 秒）

| 技能 | 可放次数 | 占总输出(60秒) | 设计意图 |
|------|---------|--------------|---------|
| 微灵光(UC) | 3-4次 | 5-6% | 持续小补 |
| 灵光爆发(SSR) | 1-2次 | 16-32% | 关键爆发 |
| 归一灵光(UR) | 1次 | 40% | 斩杀技 |

### 6.3 Tower 模式（30-40 秒/场）

Tower 的战斗引擎与普通模式共享技能公式，因此伤害数值一致。但由于 Tower 怪物 HP 高（方案中重标定后 floor 1 为 100k），技能的价值在 Tower 中会被**放大**——一颗满 BUFF 星伤害约 7k-14k，一个 UR 技能等效 130-250 颗星的伤害。

**这是合理的**：Tower 作为终局内容，技能应该是通关的关键手段之一。但需要注意：技能冷却在 Tower 中不应跨战斗继承（当前实现：战斗隔离，冷却独立）。

### 6.4 关卡模式（60-150 秒）

关卡模式中技能的表现与时间正相关——时间越长，UR 技能越可能放出 2 次（如果冷却 ≤ 75s），通关难度被显著降低。这是关卡难度标定的一个重要考量维度。

## 七、配置清理方案

### 7.1 SkillConfig.js 改造

**删除**：所有技能中的 `damage` 固定值字段（改为从 `getSkillAttackRatio()` 动态计算）。

**新增**：`healRatio`、`shieldRatio`、`buffAttackRatio` 等字段替代 `heal`、`shield`、`attack`（buff 中的）。

**同步**：`Skills.xlsx` → 运行 `npm run convert` → 重新生成 `SkillConfig.js`。

### 7.2 消费点统一

三个消费点（BattleEngine、SkillSystem、TowerSystem）都使用同一个公式：

```javascript
// 统一入口（加到 SkillConfig.js 的导出）
function getSkillDamage(skill, stats, comboCount) {
    var ratio = getSkillAttackRatio(skill.rarity);
    var baseDmg = Math.floor(stats.attack * ratio);
    // 暴击
    var totalCritRate = stats.critRate || 0;
    if (Math.random() * 100 < totalCritRate) {
        baseDmg = Math.floor(baseDmg * (stats.critDamage || 2.0));
        return { damage: baseDmg, isCrit: true };
    }
    // Combo 加成（BattleEngine 专属，SkillSystem 无）
    if (comboCount !== undefined) {
        baseDmg = Math.floor(baseDmg * (1 + comboCount * 0.05));
    }
    // 升星倍率（待接入 UpgradeConfig）
    return { damage: baseDmg, isCrit: false };
}
```

| 文件 | 改动 | 行数 |

| `BattleEngine.js` | `useSkill()` 中的 heal/shield/buff 改为百分比公式 | ~30 行 |

## 十、风险与边界

1. **低稀有度技能的早期伤害过低**：UC 技能在 Lv.1 时只打 4 点伤害，可能让新手觉得"技能没用"。需要确保新手引导阶段第一只怪物 HP ≤ 50，让 4 点伤害仍有体感。

2. **技能成为 Tower 通关瓶颈**：如果 Tower 怪物 HP 未按《全模式数值策划方案》重标定，攻击技能在 Tower 中依旧无用。两篇文档需同步实施。

3. **Excel 导出链路**：`Skills.xlsx` → `convert.js` → `SkillConfig.js` 的自动生成链路需要更新。如果手动改 JS 而不改 Excel，下次 `npm run convert` 会覆盖改动。

4. **SP 稀有度的 ratio 设计**：SP（6.0）介于 SSR（4.0）和 UR（10.0）之间。SP 是特殊限定角色（雅典娜），数值不应超过常驻 UR，但应显著高于 SSR。6.0 的定位合理——约为 UR 的 60%，SSR 的 1.5 倍。
