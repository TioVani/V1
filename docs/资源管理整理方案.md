# 资源管理整理方案

## 一、现状问题

| 维度 | 图片 | 音频 |
|---|---|---|
| 集中管理 | ❌ 散装在 game.js（23 个主图 + 16 个美颜帧） | ✅ AudioSystem 独立模块（11 个音效） |
| 统一加载 | ❌ 逐个 `$P.createImage()` + `.src = '...'` | ✅ 批量加载到 Web Audio buffer |
| 配置与代码分离 | ❌ 路径硬编码在 game.js 各处 | ❌ 路径硬编码在 AudioSystem 内部 |
| 按需/懒加载 | ❌ 启动时一股脑全加载 | ❌ 启动时全加载 |
| 生命周期/回收 | ❌ 无，大图（2-5MB）常驻内存 | ⚠️ 有 destroy() 但从未调用 |
| 目录结构 | ❌ 26 个游戏用文件 + 子目录混在 `assets/images/` 根目录 | ⚠️ 11 个文件平铺在 `assets/audio/`，无分类 |
| 未使用资源 | ⚠️ `emission/` 目录（16 张与 `beauty/` 同名文件）用途不明，未纳入管理 | — |

**关键约束：** 当前 `init()` 是同步流程，图片通过 `onload`/`onerror` 异步加载但不阻塞启动。新方案必须兼容这一模式。

### 2.0.3 已发现的现有 Bug（与资源相关）

**Bug 1：`Assets.fightBg1` 不存在**

`GameBattleRenderer.js` 第 415 行引用了 `Assets.fightBg1`，但这个属性在 `Assets` 对象定义和 `init()` 加载中从未创建。塔模式下的背景回退链：

```js
Assets.fightBg1 || Assets.fightBgImage || Assets.backgroundImage
```

`Assets.fightBg1` 永远是 `undefined`，塔模式实际用的是普通战斗背景 `fightBgImage`。

**Bug 2：`Assets.bgOverlayImage` 不存在**

`MenuRenderer.js` 第 173 行引用 `Assets.bgOverlayImage`，但从未创建和加载。这段代码永远走 `if` 的 false 分支，等于死代码。

**Bug 3：磁盘上存在从未被引用的图片文件**

| 文件 | 状态 |
|---|---|
| `Bluelight.png` | 代码中无引用 |
| `background-transparent.png` | 代码中无引用 |
| `游戏封面(1).png`（images 根目录） | 代码中无引用 |

**Bug 4：`PoisonPuddleSystem` 中 `Assets` 通过参数传入，非死代码**

`PoisonPuddleSystem.js` 第 89 行 `drawPoisonPuddles(scale, Assets)` 的 `Assets` 是**函数参数**，由 `MonsterDrawRenderer.js` 第 263 行调用时传入 `getAssets()` 的返回值。调用链：

```js
// MonsterDrawRenderer.js:261-264
function drawPoisonPuddles(scale) {
    var pps = getPoisonPuddleSystem();
    var Assets = getAssets();
    if (pps) pps.drawPoisonPuddles(scale, Assets);
}
```

因此 `Assets && Assets.normalStarImage` 在运行时**可以正常访问**，毒液滩的星形绘制功能是有效的。该模块不需要通过 `getAssets` DI 注入，也不需要删除。迁移时需确保 AssetManager 的适配层仍然让 `getAssets()` 返回包含 `normalStarImage` 的对象即可。

### 2.0.4 代码中的特殊访问模式

这些模式必须在迁移方案中特殊处理：

1. **动态 key 访问 `characterImages`**：`MenuRenderer`、`BackpackRenderer`、`SquadRenderer` 都用 `Assets.characterImages[mappedCharId]` 或 `Assets.characterImages[mappedCharId + 'Portrait']` 做动态取值。不能简单用 `assetManager.get('char_xxx')` 替换。

2. **位置缓存挂载在 Assets 上**：`bgPositionCache`、`fightBgPositionCache`、`fightBgPositionCache2` 是渲染器计算出的缓存数据，挂载在 `Assets` 对象上作为临时存储。`GameBattleRenderer` 甚至用 `Assets[bgCacheKey]` 做动态 key 读写。迁移后这些缓存不应放在资源管理器上。

3. **`beautyFrames` 数组遍历**：`UICoreRenderer` 直接通过 `Assets.beautyFrames` 取数组遍历；`LinkChainSystem` 通过 `getBeautyFrames()` 回调获取数组后遍历。两者都依赖数组结构。AssetManager 的 `get('beauty_0000')` 扁平结构无法直接满足，需要额外提供 `getFrames('beauty')` 方法。

### 3.2 统一资源管理器

**新建** `src/systems/AssetManager.js` — 统一加载/获取/释放入口。

**接口设计：**

| 方法 | 说明 |
|---|---|
| `init(imageConfig, audioConfig, platformAPI)` | 传入配置 + 平台 API（`$P.createImage`、`fetch` 等） |
| `loadGroup(groupId)` | 按分组加载，返回 Promise；同时兼容异步回调模式（见 3.5） |
| `loadAll()` | 一次性加载所有分组 |
| `get(id)` | 获取已加载的资源（图片对象 / AudioBuffer），未加载返回 null |
| `getOrDefault(id, fallback)` | 获取资源，未加载/失败时返回 fallback |
| `unloadGroup(groupId)` | 释放指定分组（`img.src = ''`，置 null） |
| `isGroupLoaded(groupId)` | 查询分组是否已加载 |
| `getFrames(groupId)` | 获取指定分组的所有图片对象数组（用于 `beautyFrames` 等序列帧遍历） |
| `getLoadingProgress()` | 当前加载进度（已加载/总数） |

**关键设计决策：**

1. **`get(id)` 返回 null 是合法值**，所有调用方必须处理 null。渲染器中统一走 `getOrDefault(id, fallback)` 模式。
2. **卸载安全守卫**：`unloadGroup` 前检查是否有渲染帧正在使用该分组资源，若分组内存在正在显示的图片则跳过并打印警告（防御性设计，不做严格阻塞）。
3. **beauty 帧自动生成**：`beauty` 组的 16 条记录由 `init()` 根据 `beautyFrameCount`（默认 16）自动生成，无需手动维护。
4. **图片和音频共用同一个 Manager**，但内部走不同的 loader 分支。图片用 `$P.createImage()` + `.src`，音频用 `fetch` + `decodeAudioData`。

**分组按需加载策略：**

| 时机 | 加载分组 | 说明 |
|---|---|---|
| 游戏启动 | `core` + `menu` | 标题画面 + 菜单所需资源 |
| 进入世界地图 | `core` + `menu` + `character` + `worldmap` | 加上角色立绘和地图资源 |
| 进入战斗 | `+ battle` | 战斗背景（可预加载） |
| 战斗结束返回 | `- battle` | 卸载战斗资源释放内存 |
| 打开美颜/抽卡 | `+ beauty` | 按需加载 16 帧 |
| 关闭美颜/抽卡 | `- beauty` | 释放 |
| 退出世界地图 | `- character` `- worldmap` | 释放大图 |

### 3.3 音频配置抽离

`AudioSystem.js` 内部的音效路径、音量和变调参数全部移到 `AssetConfig.js` 的 `AUDIO_CONFIG` 中。

改动要点：

1. **AudioSystem 不再自己加载文件**，改为接收 AssetManager 的音频 buffer：
```js
// 之前：AudioSystem 内部硬编码路径 + 自行 fetch
audioSystem.init();

// 之后：AudioSystem 从 AssetManager 获取音频 buffer
audioSystem.init({
    getBuffer: function(id) { return assetManager.get(id); }
});
```
2. **AudioSystem 保留播放逻辑**（`_play`、各 `playXxx` 方法），但不再关心文件从哪来。
3. **音效加载由 AssetManager 统一负责**，AudioSystem 只在播放时从 AssetManager 取 buffer。
4. **增加 destroy 调用点**：在游戏退出/重置时调用 `audioSystem.destroy()`，同时在 `AssetManager.unloadGroup('audio')` 时也触发。

### 3.4 目录整理

**搬迁前先确认 `emission/` 目录用途：**
- 如果是废弃的旧资源 → 移至 `assets/images/reference/` 或直接删除
- 如果是另一组序列帧 → 纳入 AssetConfig 的独立分组

**目标结构（仅搬迁运行时需要的文件）：**

```
assets/
  images/
    ui/              ← 图标、按钮、菜单元素（ST、IST、FST、BPK、WS、WSC、GEAR、GL、SST、BK、TKS、TOP、CS、SP、IFT、BOSS）
    battle/          ← 战斗背景（Fight_01_BG.jpg、Fight_02_BG.jpg）
    character/       ← 角色立绘（XXSZ_HF.png、XXZS_HF.png、XXZS.png）
    beauty/          ← 美颜帧（GC_0000 ~ GC_0015，已在子目录，不动）
    background/      ← 标题/大地图背景（background.png、title_bg.jpg）
```

**搬迁步骤：**
1. `ui/` 目录已存在（含设计参考图和 UI 说明，非游戏运行时图标），先将 `ui/` 内的现有内容移到 `reference/`；然后创建其余子目录 `battle/`、`character/`、`background/`、`worldmap/`、`reference/`
2. 将 `assets/images/` 根目录下的游戏运行时文件移动到对应子目录（如 `ST.png` → `ui/`、`Fight_01_BG.jpg` → `battle/` 等）
3. 更新 `AssetConfig.js` 里的路径
4. 将 `封面视觉用/`、`战斗画面背景/`、`地图资源/蜀汉国/地图资源（底图）/` 等纯参考素材移入 `reference/`
5. 确认 `emission/` 去向后处理

### 3.5 兼容当前同步启动流程的过渡方案

当前 `init()` 中图片加载是"设 src 后立即返回"模式，渲染循环会在图片未加载完时尝试绘制。新方案采用**渐进式迁移**：

**第一阶段（不改变加载行为）：**
- `AssetManager.init()` 只读取配置，不做加载
- `AssetManager.loadGroup('core')` 内部等价于当前的逐个 `$P.createImage()` + `.src = ...`，**不返回 Promise 阻塞**
- 资源仍通过 `onload`/`onerror` 异步就绪，渲染循环照常处理"图片未就绪"的状态
- 对外暴露 `get(id)` 替代直接访问 `Assets.xxx`

```js
// AssetManager.loadGroup 内部逻辑（第一阶段）
function loadGroup(groupId) {
    var items = config[groupId];
    for (var i = 0; i < items.length; i++) {
        var item = items[i];
        var img = createImage();
        img.src = item.src;
        img.onload = function() { /* 标记已就绪 */ };
        img.onerror = function() { /* 标记失败，get(id) 返回 null */ };
        cache[item.id] = img;
    }
}
```

**第二阶段（按需加载 + 卸载）：**
- 在第一阶段稳定后，增加 `unloadGroup` 和"二次加载"能力
- 美颜帧改为进入抽卡页面时才加载，退出时释放
- 战斗背景改为进入战斗时加载，退出时释放

### 3.6 null 安全渲染

所有通过 `assetManager.get(id)` 获取的图片，渲染时必须处理 null：

```js
// 渲染器中的标准写法
var img = assetManager.get('fightBgImage');
if (img) {
    ctx.drawImage(img, x, y, w, h);
} else {
    // fallback：使用纯色背景
    ctx.fillStyle = '#1a1a2e';
    ctx.fillRect(x, y, w, h);
}
```

新增 `getOrDefault` 辅助方法，封装常见 fallback 模式：

```js
function getOrDefault(id, fallback) {
    var asset = cache[id];
    return (asset && asset._loaded) ? asset : fallback;
}
```

### 4.2 迁移顺序（降低风险）

### 4.3 适配层设计（核心）

**目标：** 让 228 处现有 `Assets.xxx` 引用无需改动即可工作，同时让新代码通过 AssetManager 访问。

```js
Assets.settingsIcon       = assetManager.get('settingsIcon');
Assets.goldIcon           = assetManager.get('goldIcon');
Assets.starSourceIcon     = assetManager.get('starSourceIcon');
Assets.backIcon           = assetManager.get('backIcon');
```

## 五、三大方针校验

### 好维护
- 改图片/音频 = 只改 `AssetConfig.js` + 替换文件，不碰逻辑代码
- 出加载问题 = 只查 `AssetManager.js`
- 每个模块职责单一：Config 管数据，Manager 管加载，AudioSystem 管播放

### 好管理
- `AssetConfig.js` 是纯数据，策划可以直接编辑
- 文件目录分类清晰，新资源放入对应目录即可
- 遵循项目已有模式（config 放 `src/config/`，system 放 `src/systems/`）

### 好扩展
- 加新资源类型（视频、骨骼动画等）= Config 加一个分组 + Manager 加一种 loader
- 加 BGM = Config 加 `bgm` 分组，AudioSystem 扩展播放接口
- 加新世界地图图片 = Config 的 `worldmap` 分组加一条记录
- `get(id)` 接口不变，调用方无需改动
