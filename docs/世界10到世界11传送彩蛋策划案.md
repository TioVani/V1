# 世界10→世界11传送彩蛋「世界的边缘？」策划案

## 一、概述

玩家在 world_10（蜀汉·密道）通过传送到 world_11（蜀汉·暮色）的传送门 `portal_dusk` 时触发隐藏彩蛋。

- **第一次尝试**：蝉玉仙跳出，说"后面的内容以后再来探索吧~"并阻止传送。
- **第二次尝试**：直接放行，玩家进入 world_11，同时弹出提示"世界的边缘？"，达成成就「世界的边缘？」，发放 150 灵石。

---

## 二、设计原则：配置驱动，不加代码分支

对照猫灵对话系统的原则——**"加对话只加数据，加场景只加注册项，不加代码分支"**——本彩蛋遵循同样的统一入口思路：

| 统一入口 | 说明 |
|---------|------|
| **TeleportConfig.js** | 传送门实体配置，扩展 `easterEgg` 字段声明彩蛋行为，数据即文档 |
| **EasterEggConfig.js**（新建） | 彩蛋驱动器注册表：拦截脚本 + 奖励发放 + 存档状态，纯数据层，game.js 不写硬编码分支 |
| **TaskSystem.js** | 成就配置表，新增「世界的边缘？」成就条目（只加数据） |

**规则**：game.js 只做通用编排——检测 `easterEgg` 字段 → 委托 `EasterEggConfig` 执行——不为 `portal_dusk` 写一行硬编码判断。

---

## 三、触发条件与数据边界

| 条件 | 说明 |
|------|------|
| 触发传送门 | `portal_dusk`（world_10，`x=1338, y=384`，目标 world_11） |
| 前置条件 | 探索度达标（`requireExploration: 0.5`） |
| 存档字段 | `saveData.player.easterEggs.worldEdgeChecked`（Boolean） |

## 四、架构设计

### 4.1 新增/改动文件

| 文件 | 改动类型 | 职责 |
|------|---------|------|
| `V1/src/config/EasterEggConfig.js` | **新建** | 彩蛋驱动器注册表：拦截对话、奖励配置、状态初始化 |
| `V1/src/config/TeleportConfig.js` | 修改 | `portal_dusk` 条目新增 `easterEgg: 'worldEdge'` + `buildTransferDataForWorld()` 透传 |
| `V1/src/systems/worldmap/WorldMapEntity.js` | 修改 | `handlePortal()` 透传 `easterEgg` 到返回值和回调 |
| `V1/src/systems/GameDataStore.js` | 修改 | `defaultSaveData.player` 新增 `easterEggs` 字段 |
| `V1/src/systems/TaskSystem.js` | 修改 | 新增「世界的边缘？」成就定义（加数据） |
| `V1/game.js` | 修改 | portal 分支中增加通用彩蛋检测委托（不针对特定传送门），顶部 import EasterEggConfig |

### 4.2 数据流（配置驱动）

```
玩家点击 portal_dusk 传送门
  → WorldMapEntity.interact(entityId)
    → handlePortal(entity)   ← entity 包含 teleportConfig 传来的 easterEgg:'worldEdge'
      → 返回 { type:'portal', targetWorld:'world_11', easterEgg:'worldEdge' }
      → 回调 onInteractResult({ type:'portal', entity, targetWorld, easterEgg:'worldEdge' })
    → game.js 进入 if (result.type === 'portal') 分支
      → if (result.easterEgg) {
            → EasterEggConfig[result.easterEgg] 查找驱动器
            → 驱动器内部判定存档状态，返回 action
          }
```

**game.js 只做一件事**：检查 `result.easterEgg` 是否存在 → 存在就委托驱动器，不存在就走默认传送。

**关键数据通道**：`teleportConfig 数据行` → `buildTransferDataForWorld() 透传到 entity 对象` → `handlePortal() 透传到返回值 + 回调` → `game.js result.easterEgg`。这 3 处透传缺一不可。

### 4.3 EasterEggConfig 驱动器结构

```javascript
// 每个彩蛋是一个纯对象，自包含全部逻辑
export const EASTER_EGG_DRIVERS = {
    worldEdge: {
        // 状态 key：存档中 easterEggs 下的字段名
        stateKey: 'worldEdgeChecked',

        // 拦截阶段（第一次触发时）：返回 { type, dialogue? }
        onFirstTrigger: function (deps) {
            return {
                type: 'block',
                dialogue: [
                    { speaker: '蝉玉仙', text: '后面的内容以后再来探索吧～' }
                ]
            };
        },

        // 通过阶段（第二次触发时）：返回 { type, toast?, reward? }
        // toast 弹出提示，reward 包含成就 ID 和灵石数量，由 game.js 通用编排层统一处理
        onPass: function (deps) {
            return {
                type: 'pass',
                toast: { title: '世界的边缘？', icon: 'success', duration: 3000 },
                reward: {
                    achievementId: 'world_edge',
                    spiritStones: 150
                }
            };
        }
    }
};
```

### 4.6 game.js 通用编排逻辑

**插入位置**：`if (result.type === 'portal')` 分支最顶部，冷却判断之前。

**顶层需 import**：

```javascript
import { EASTER_EGG_DRIVERS } from './src/config/EasterEggConfig.js';
```

```javascript
if (result.type === 'portal') {
    // ── 通用彩蛋检测（不对任何特定传送门写硬编码）────────────
    if (result.easterEgg && EASTER_EGG_DRIVERS[result.easterEgg]) {
        var driver = EASTER_EGG_DRIVERS[result.easterEgg];
        var checked = pd.easterEggs && pd.easterEggs[driver.stateKey];

        // 冷却保护（拦截和通过都受冷却限制）
        var _now = Date.now();
        if (_now - _lastPortalTime < 2000) {
            $P.showToast({ title: '传送冷却中...', icon: 'none', duration: 1000 });
            return;
        }
        _lastPortalTime = _now;

        if (!checked) {
            // 第一次：拦截
            var action = driver.onFirstTrigger({ pd: pd, worldMapRenderer: worldMapRenderer });
            // 先存档标记（防止对话期间重复触发）
            if (!pd.easterEggs) pd.easterEggs = {};
            pd.easterEggs[driver.stateKey] = true;
            worldMapSystem.saveProgress();
            // 再播对话（showDialogue 非阻塞，对话关闭后无需额外操作，标记已持久化）
            if (action.dialogue && worldMapRenderer) {
                worldMapRenderer.showDialogue(action.dialogue);
            }
            return;
        }

        // 第二次：正常传送 + 附加逻辑
        if (audioSystem) audioSystem.playTeleport();
        var fromWorld = worldMapSystem.getWorldId();
        if (fromWorld === 'world_17' && result.targetWorld !== 'world_17') {
            if (audioSystem) { audioSystem.exitArdeacinerea(); audioSystem.playBgm('shuhanTheme', 0.32); }
        }
        worldMapSystem.loadWorld(result.targetWorld, fromWorld);
        _updateCatSpiritVisibility(result.targetWorld);
        worldMapSystem.saveProgress();
        if (result.targetWorld === 'world_17') {
            if (audioSystem) audioSystem.enterArdeacinerea();
        }

        // 驱动器定义的通过后行为（仅触发一次，成就完成则跳过）
        var passAction = driver.onPass({ pd: pd });
        if (passAction.toast) $P.showToast(passAction.toast);
        if (passAction.reward) {
            var achId = passAction.reward.achievementId;
            var cat = pd.taskProgress && pd.taskProgress.achievements;
            if (!cat) { if (!pd.taskProgress) pd.taskProgress = {}; pd.taskProgress.achievements = {}; cat = pd.taskProgress.achievements; }
            if (!cat[achId]) cat[achId] = { progress: 0, claimed: false };
            // 防重复：已完成的跳过
            if (!cat[achId].claimed) {
                cat[achId].progress = 1;
                cat[achId].claimed = true;
                if (passAction.reward.spiritStones) {
                    pd.starSource = (pd.starSource || 0) + passAction.reward.spiritStones;
                }
                worldMapSystem.saveProgress();
            }
        }
        return;
    }
    // ── 默认传送逻辑（非彩蛋传送门）────────────
    var _now = Date.now();
    // ... 原有冷却 + 传送代码 ...
```

**关键**：这段逻辑不出现 `portal_dusk`、`worldEdge`、`world_11` 等任何特化字符串。成就完成判断由 `pd.taskProgress.achievements[achId].claimed` 保证，已完成的跳过。

### 4.7 状态机

```
portal 传送（含 easterEgg 字段）:

  [第一次点击 - easterEgg 存档标记为 false]
    → EasterEggDriver.onFirstTrigger()
    → action.type === 'block'
    → 播对话 → 存档标记 → return
    → 状态: worldmap（停留当前世界）

  [第二次点击 - easterEgg 存档标记为 true]
    → 正常传送 (loadWorld)
    → EasterEggDriver.onPass()
    → toast + 成就 + 灵石
    → 状态: worldmap（载入目标世界）
```

不新增游戏状态，全部复用 `worldmap` 状态。

## 六、详细实现规格

### 6.1 EasterEggConfig.js 完整结构

```javascript
/**
 * EasterEggConfig — 传送门彩蛋驱动器注册表
 * 每个 driver 自包含：状态 key + 拦截行为 + 通过行为。
 * 新增传送彩蛋只需在此文件加一条注册项，并在 TeleportConfig 中关联 easterEgg 字段。
 * 不改 game.js。
 */

export const EASTER_EGG_DRIVERS = {
    // ── 世界的边缘？（world_10 portal_dusk → world_11）────────────
    worldEdge: {
        stateKey: 'worldEdgeChecked',

        // 第一次触发：返回拦截行为
        // deps 包含 { pd, worldMapRenderer }
        onFirstTrigger: function (deps) {
            return {
                type: 'block',
                dialogue: [
                    { speaker: '蝉玉仙', text: '后面的内容以后再来探索吧～' }
                ]
            };
        },

        // 第二次触发（通过时）：返回附加行为
        // deps 包含 { pd }
        // toast 弹出"世界的边缘？"，reward 由 game.js 通用编排层统一发放
        onPass: function (deps) {
            return {
                type: 'pass',
                toast: { title: '世界的边缘？', icon: 'success', duration: 3000 },
                reward: {
                    achievementId: 'world_edge',
                    spiritStones: 150
                }
            };
        }
    }
};
```

### 6.2 成就「世界的边缘？」

在 `TaskSystem.js` 的 `ACHIEVEMENT_TASKS` 数组中新增成就定义（供成就列表展示使用）：

```javascript
{
    id: 'world_edge',
    name: '世界的边缘？',
    description: '通往世界边缘的秘密',
    type: 'event_flag',
    target: 1,
    rewards: { starSource: 150 },
    hidden: true
}
```

**说明**：`ACHIEVEMENT_TASKS` 中的条目供成就列表渲染和 `claimTaskReward` 手动领奖使用。本彩蛋不走 `completeEventTask` 流程（避免自动追加 `" 完成！"` 后缀），而是由 game.js 通用编排层直接写入 `pd.taskProgress.achievements.world_edge` 并发放灵石。`rewards` 字段在此处仅作文档记录，实际发放由 `EasterEggConfig.onPass` 返回的 `reward.spiritStones` 驱动。

1. `portal_dusk` 条目新增 `easterEgg: 'worldEdge'`
2. `buildTransferDataForWorld()` 中 portal 实体构建处新增字段透传：

```javascript

```

### 6.4 WorldMapEntity.js 改动

`handlePortal()` 需要将 `entity.easterEgg` 透传到返回值和 `onInteractResult` 回调：

```javascript
function handlePortal(entity) {
    var exploration = getExplorationPercent ? getExplorationPercent() : 1;
    if (entity.requireExploration > 0 && exploration < entity.requireExploration) {
        if (onInteractResult) {
            onInteractResult({
                type: 'portal_locked', entity: entity,
                message: entity.lockedMessage, current: exploration,
                required: entity.requireExploration,
                easterEgg: entity.easterEgg       // ← 透传
            });
        }
        return { type: 'portal_locked', message: entity.lockedMessage || '条件未满足',
                 current: exploration, required: entity.requireExploration,
                 easterEgg: entity.easterEgg };    // ← 透传
    }
    if (onInteractResult) onInteractResult({
        type: 'portal', entity: entity,
        targetWorld: entity.targetWorld,
        easterEgg: entity.easterEgg                // ← 透传
    });
    return { type: 'portal', targetWorld: entity.targetWorld,
             easterEgg: entity.easterEgg };         // ← 透传
}
```

## 八、风险与边界

- **存档兼容性**：`easterEggs` 为新增字段，旧存档加载时通过 `_migrateIncomingSaveData` 自动补全为 `{ worldEdgeChecked: false }`。
- **扩展性**：未来新增其他传送门彩蛋（如"伪结局"、"隐藏关卡入口"），只需在 `EasterEggConfig.js` 加一个 driver，再在 `TeleportConfig.js` 对应 portal 加 `easterEgg` 字段即可。game.js 零改动。
- **探索度门槛**：portal_dusk 已有的 `exp: 0.5` 在 `WorldMapEntity` 层处理为 `portal_locked`，不进入 portal 分支，不会触发彩蛋逻辑。
- **对话时序保护**：`showDialogue` 为非阻塞方法，不会等待玩家关闭对话框。方案采用**先存档、后播对话**的顺序——存档标记在对话弹出前就已经持久化，即使玩家在对话期间关闭游戏或再次触发交互，`worldEdgeChecked` 也已经是 `true`，第二次进入走正常传送分支。
- **toast 提示**：第二次传送时弹出 `"世界的边缘？"`（由 `EasterEggConfig.onPass` 返回）。不放 `completeEventTask`，因此不会出现 `" 完成！"` 后缀。
- **重复发放保护**：game.js 通用编排层通过 `pd.taskProgress.achievements[achievementId].claimed` 判断，已完成的跳过。重启后 `claimed` 状态持久化，不丢失。
- **`hidden` 字段**：当前 `ACHIEVEMENT_TASKS` 数组中无 `hidden` 字段。如需达成前不显示此成就，需额外在成就列表渲染层做判断。`completeEventTask` 本身不依赖 `hidden` 字段。
- **`spiritStones` 字段**：`EasterEggConfig.onPass.reward.spiritStones` 是驱动器层面的字段名，实际写入存档的字段是 `pd.starSource`（game.js 通用编排层做映射）。`ACHIEVEMENT_TASKS` 中仍用 `rewards.starSource` 保持一致。
- **数据通道完整性**：`easterEgg` 字段需要经过 3 处透传——`TeleportConfig` 数据行 → `buildTransferDataForWorld()` entity 对象 → `handlePortal()` 返回值和回调。任一处遗漏都会导致 game.js 收不到 `result.easterEgg`。
