# 暂停后灵光残留与合成线穿透按钮问题修复方案

## 问题现象

1. **暂停后灵光继续生成并合成**：在任意战斗模式中按暂停键后，灵光仍在生成，合并大星星（mergeStars）仍在发生。
2. **合成线显示在暂停按钮上**：合成动画的金色连接线穿透暂停菜单半透明遮罩，直接出现在按钮区域上方。
3. **模式切换后遗留灵光**：在一个模式中暂停一段时间后画布积满灵光，返回菜单再进入其他模式时，上局遗留的灵光在新画布上短暂出现约一秒后被清理。

---

## 根因分析

三个问题共享同一个根因链条：**PauseCoordinator subscriber 覆盖不全 + 渲染和动画系统缺失暂停感知**。下面逐一剖析。

### 链路1：暂停后灵光继续生成

**涉及数据流**：

```
用户点击暂停按钮（game.js:4735）
  └─ PauseCoordinator.pause()
       ├─ ModeTimers.onPause → modeTimers.clearAll()
       │    └─ 清理通过 TimerManager.setInterval() 注册的定时器
       ├─ StarSystem.onPause → 空操作（当前是空函数体）
       │    ❌ 全局 moveInterval 未被清理
       └─ AnimationSystem.onPause → 冻结 getGameTime()（已有）

StarSystem.updateStarSpawnInterval()（StarSystem.js:688-693）:
  └─ setInterval(addNewStar, interval) → 存入全局 moveInterval（game.js:57）
       ❌ 这个 setInterval 不经过 TimerManager，ModeTimers 无法追踪
```

**根因**：`StarSystem` 的 subscriber `onPause` 是空函数（`StarSystem.js` 行 82）。灵光生成定时器 `moveInterval` 由 `StarSystem.updateStarSpawnInterval()` 直接用 `setInterval` 创建并存入全局变量，不在 `ModeTimers` 的 `TimerManager` 池中，所以 `ModeTimers.clearAll()` 清理不到它。

### 链路2：合成线显示在暂停按钮上

**涉及数据流**：

```
AnimationSystem 已注册 PauseCoordinator subscriber（AnimationSystem.js:48-51）:
  └─ onPause: 冻结 getGameTime()
  └─ onResume: 解冻 getGameTime() + 补偿 duration

updateMergeAnimations()（AnimationSystem.js:2049-2062）:
  └─ 用 getGameTime() 计算 elapsed
      └─ 暂停时 getGameTime() 返回冻结值 → elapsed 不变 → progress 不变
         → 动画不推进 ✓

drawMergeAnimations(scale)（AnimationSystem.js:2066-2111）:
  └─ 遍历 mergeAnimations[] → 读取 anim.progress → 绘制线条和虚影星
      ❌ 没有暂停感知，仍读取静止的 progress 绘制线条
```

**根因**：`getGameTime()` 冻结使动画不推进，但 `drawMergeAnimations` 没有任何暂停守卫，每帧仍然按 `anim.progress` 的静止值画出金色连接线。这些线条绘制在画布上，之后 `renderPausedMenu()` 叠加半透明遮罩，但由于合成线使用了 `globalAlpha`/`shadowBlur` 效果，仍然在遮罩上方视觉可见。

### 链路3：模式切换后遗留灵光

**涉及数据流**：

```
用户点击暂停→返回菜单（game.js:4919-4928）:
  └─ cleanupMode(exitMode)
       └─ handlers['season'].cleanup() → endSeasonGame()
            ├─ clearMoveInterval() ✓ 停止灵光生成
            ├─ clearTimerInterval() ✓
            ├─ setGameState(GAMEOVER) ✓
            ❌ 没有 stars = []
            ❌ 没有 clearAllAnimations()

用户点击新游戏 → startGame():
  └─ stars = []  ← 到这里才清空
  └─ clearAllAnimations()  ← 到这里才清 mergeAnimations
```

**根因**：`endSeasonGame()` 不做 `stars = []` 和 `clearAllAnimations()`。这意味着在 `cleanupMode` → 返回菜单 → 点击新游戏这整段空窗期内，全局 `stars` 数组和 `mergeAnimations` 数组仍然持有旧数据。`renderLoop` 根据新的 state 切换渲染分发函数，但在 `startGame()` 执行 `stars = []` 之前的渲染帧中，`renderGame()` 读取到旧 stars 数据并绘制到画布上，形成"遗留灵光闪现一秒后消失"的现象。

---

## 设计原则

以现有 `PauseCoordinator` 的 **subscriber 模式**为唯一扩展点。不改 `game.js`、不改 `PauseCoordinator.js`、不改 `ModeLifecycleManager.js`。所有修复收敛在两个子系统内部：

- **StarSystem**：补齐自己的 `onPause` 行为
- **AnimationSystem**：补齐 `drawMergeAnimations` 和 `drawStarBurstAnimations` 的暂停感知
- **GameLifecycleSystem**：在 `endSeasonGame`/`endGame` 中提供结算级清理入口

核心约束：
- PauseCoordinator 保持零 deps 单例不变
- game.js 的 `isCombat` 分支不做任何守卫修改
- 新增战斗模式时，只要其 handler 使用 StarSystem 和 AnimationSystem，暂停行为自动生效

## 修复方案

### 修改1：StarSystem.onPause 清理 moveInterval

**文件**：`V1/src/systems/StarSystem.js`，行 80-89

**当前代码**：

```javascript
PauseCoordinator.instance.subscribe(_owner, 'StarSystem', {
    onPause: function() {},
    onResume: function(duration) {
        var starsArr = getStars();
        for (var i = 0; i < starsArr.length; i++) {
            if (starsArr[i].disappearTime) starsArr[i].disappearTime += duration;
            if (starsArr[i].createTime) starsArr[i].createTime += duration;
        }
    }
});
```

**修改为**：

```javascript
PauseCoordinator.instance.subscribe(_owner, 'StarSystem', {
    onPause: function() {
        var mi = getMoveInterval();
        if (mi) {
            clearInterval(mi);
            setMoveInterval(null);
        }
    },
    onResume: function(duration) {
        var starsArr = getStars();
        for (var i = 0; i < starsArr.length; i++) {
            if (starsArr[i].disappearTime) starsArr[i].disappearTime += duration;
            if (starsArr[i].createTime) starsArr[i].createTime += duration;
        }
        // 注意：不在这里重建 moveInterval。
        // 恢复时 moveInterval 的重建由各模式的 resume handler 负责
        // （如 resumeNormalTimers、BossBattleAdapter.togglePause 等），
        // 因为不同模式需要不同的生成间隔参数。
    }
});
```

**说明**：
- `onPause` 中直接通过已有的 deps 注入 `getMoveInterval()` / `setMoveInterval()` 清理全局 `moveInterval`，不需要 PauseCoordinator 知道 moveInterval 的存在。
- `onResume` 中只做 `disappearTime`/`createTime` 的时间补偿，不重建 `moveInterval`。因为 `resume()` 执行时 gameState 还未从 PAUSED 恢复，`updateStarSpawnInterval()` 会被内部状态守卫拦截。定时器重建由各模式自己的 resume handler 负责，这是正确的职责分离——各模式知道自己的生成间隔参数。
- `getMoveInterval` / `setMoveInterval` 均在 `StarSystem` 的工厂函数闭包内可用（行 91-93 已有注入）。

### 修改2：AnimationSystem 中 drawMergeAnimations 和 drawStarBurstAnimations 增加暂停守卫

**文件**：`V1/src/systems/AnimationSystem.js`

**修改2a**：`drawMergeAnimations`（行 2066）开头加暂停守卫

**当前代码**：

```javascript
function drawMergeAnimations(scale) {
    var ctx = getCtx();
    for (var i = 0; i < mergeAnimations.length; i++) {
        // ...
    }
}
```

**修改为**：

```javascript
function drawMergeAnimations(scale) {
    if (PauseCoordinator.instance.isPaused) return;
    var ctx = getCtx();
    for (var i = 0; i < mergeAnimations.length; i++) {
        // ...
    }
}
```

**修改2b**：`drawStarBurstAnimations`（行 2018）开头加暂停守卫

**当前代码**：

```javascript
function drawStarBurstAnimations(scale) {
    var ctx = getCtx();
    for (var i = 0; i < starBurstAnimations.length; i++) {
        // ...
    }
}
```

**修改为**：

```javascript
function drawStarBurstAnimations(scale) {
    if (PauseCoordinator.instance.isPaused) return;
    var ctx = getCtx();
    for (var i = 0; i < starBurstAnimations.length; i++) {
        // ...
    }
}
```

**说明**：
- `PauseCoordinator` 已在 `AnimationSystem.js` 顶部可访问（行 48 已注册 subscriber），`PauseCoordinator.instance.isPaused` 可直接访问。
- 两个 `update` 函数（`updateMergeAnimations`、`updateStarBurstAnimations`）不需要守卫——它们都用 `getGameTime()` 计算时间，`getGameTime()` 在暂停时已冻结，`progress` 不推进。
- 两个 `draw` 函数每帧仍被 `isCombat` 分支调用，通过守卫跳过绘制，彻底消除合成线和粒子穿过暂停菜单的视觉问题。
- 与 `mergeAnimations` 同理，`starBurstAnimations` 在暂停时也在 `isCombat` 分支中被调用，画出静止的粒子残留。一并处理。

### 修改3：endSeasonGame / endGame 中清理全局渲染数据

**文件**：`V1/src/systems/GameLifecycleSystem.js`

**位置A**：`endSeasonGame()` 函数（行 407），在 `clearMoveInterval()` 之后追加

**当前代码（行 411-417）**：

```javascript
clearTimerInterval();
clearMoveInterval();
clearMonsterAttackInterval();
if (stopPetAttackTimer) stopPetAttackTimer();

if (getNormalBattleAdapter && getNormalBattleAdapter()) {
    getNormalBattleAdapter().destroy();
}
```

**修改为**：

```javascript
clearTimerInterval();
clearMoveInterval();
clearMonsterAttackInterval();
if (stopPetAttackTimer) stopPetAttackTimer();

// 清理战斗渲染数据（防止模式切换后残留渲染）
if (setStars) setStars([]);
if (clearAllAnimations) clearAllAnimations();

if (getNormalBattleAdapter && getNormalBattleAdapter()) {
    getNormalBattleAdapter().destroy();
}
```

**位置B**：同理，`endGame()` 函数（行 530-561），在 `clearMoveInterval()` 之后（行 553 附近）也需要追加相同两行。

**说明**：
- `setStars` 和 `clearAllAnimations` 需要通过 `GameLifecycleSystem` 的 deps 注入。检查 `GameLifecycleSystem.js` 的 deps 中是否已有这两个函数——如果有直接使用；如果没有则需要加到 deps 参数中。
- 这两行保证了"战斗结束 = 渲染数据立即清零"，不再依赖 `startGame()` 中的延迟清理。
- 不影响正常战斗流程（正常战斗中 `endSeasonGame` / `endGame` 只在结算时调用）。

## 架构评估

| 评估维度 | 评价 |
|---------|------|
| **统一** | 所有暂停行为通过 PauseCoordinator subscriber 统一驱动，无散落在渲染层的 if 守卫 |
| **好维护** | 修改集中在 2 个核心系统文件（StarSystem, AnimationSystem）加 1 处结算清理（GameLifecycleSystem），不碰渲染分发逻辑 |
| **好扩展** | 新增战斗模式只要使用 StarSystem 和 AnimationSystem，暂停时自动获得灵光生成停止 + 合成线隐藏 |
| **好管理** | 每个子系统自主管理自己的暂停行为（StarSystem 管自己的定时器，AnimationSystem 管自己的渲染），PauseCoordinator 只负责通知 |
